## Source-grounded modeling basis

The mission describes a hospital food-service system where robots deliver meals from the kitchen to inpatient rooms, support multiple delivery modes, cooperate with humans or other robots, track meal retrieval, alert on wrong-meal retrieval, and retrieve dirty dishes from rooms.

I model decompositions using the provided definitions: **AND** means all children are required, **OR** means one child is sufficient, and **FALLBACK** means an ordered alternative is tried only if the previous one fails. Tasks are modeled as concrete assignable robot operations with a mission-cited location and number of robots.

Important modeling choice: the source says dirty dishes “should be retrieved from the room,” but it does **not** specify the final drop-off destination, so the model stops at dish removal/tracking rather than inventing a disposal location.

## 4. Logical relationships with justifications

**G1 → G2, G17 [AND][parallel: `G2#G17`]**
Justification: The mission includes both food delivery and dirty-dish retrieval. They are both required capabilities, but they are not necessarily tied to the same moment, so parallel service execution is appropriate.

**G2 → G3, G4, G5, G6, G9, G16 [AND][sequential with parallel handoff tracking: `G3;G4;G5;G6;(G9#G16)`]**
Justification: Delivery must start from a kitchen request, gather information, assess uncertainty, transport meals, gain room access, then perform and track the handoff.

**G3 → AT1, AT2 [AND][sequential]**
Justification: The robot first receives the delivery request and then extracts operational details such as meal, inpatient, and room.

**G4 → AT3, AT4 [AND][parallel]**
Justification: Inpatient-record lookup and live availability checks both reduce uncertainty about who can retrieve food from the tray.

**G5 → AT5, AT6 [AND][sequential]**
Justification: Meals must be loaded at the kitchen before they can be carried to the inpatient room.

**G6 → G7, G8 [AND][`FALLBACK(G7,G8)`]**
Justification: Door opening can be supported by a human or another robot. A fallback structure handles the possibility that one cooperation mode is unavailable.

**G9 → G10, G11 [AND][`FALLBACK(G10,G11)`]**
Justification: Direct placement is modeled first because it avoids dependence on uncertain human availability; tray retrieval is the fallback when table placement is not possible.

**G11 → G12, G13, G14, G15 [AND][nested fallback]**
Justification: The possible tray-retrieval helpers are inpatient, companion, nurse, or another robot. The fallback order reflects escalating assistance when the previous actor is unable or unavailable.

**G16 → AT21, AT22 [AND][parallel]**
Justification: The system must track retrieval and alert if the wrong meal is retrieved; these monitoring functions can run together during handoff.

**G17 → G18, G19, G22, G26 [AND][sequential]**
Justification: Dish retrieval begins with a pickup request/assessment, then room access, dish collection, and completion recording.

**G19 → G20, G21 [AND][`FALLBACK(G20,G21)`]**
Justification: If the caller or human cannot open the door, robot-assisted opening remains available as an alternative.

**G22 → G23, G24, G25 [AND][nested fallback]**
Justification: Dish retrieval can occur unassisted, with two robots, or with robot-human cooperation, so these are modeled as ordered alternatives.

## 5. Main design rationale

The goal model separates **information goals** from **physical achievement goals** because the mission contains uncertainty about whether the inpatient, companion, or nurse can retrieve the meal. That uncertainty justifies explicit query goals before selecting a handoff strategy.

The model also separates **handoff execution** from **handoff monitoring** because the robot may carry multiple meals and must both indicate the correct meal and detect wrong retrieval. This makes correctness a first-class mission concern rather than a hidden detail.

For dish retrieval, the model avoids adding an unsupported final destination. The source only says dirty dishes must be retrieved from the room, so the final modeled state is that dishes are removed from the room and the pickup is recorded.
