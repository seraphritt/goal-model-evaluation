## Modeling rationale

The mission is naturally decomposed as: **understand the request → plan storage/order/robot assignment → execute collection → execute delivery → handle battery-triggered fallbacks**.

The most important modeling choices are:

1. **The root is an Achieve goal** because the mission is successful only when the required resources are delivered to the requesting agent at the specified location.
2. **Request interpretation and storage-order planning are Query goals** because they retrieve or compute information: required resources, storage places, waiting times, path estimates, and collection order.
3. **Collection must precede delivery** because the text says “Once retrieved, the delivery phase begins.”
4. **Parallelism appears at the collect-deliver assignment level** because the text says multiple robots can be assigned to parallel collect-deliver tasks when multiple items are required from different storages.
5. **Battery handling is modeled as FALLBACK**, not OR, because the low-battery behavior is not a free alternative; it is attempted only when the normal phase cannot continue safely.
