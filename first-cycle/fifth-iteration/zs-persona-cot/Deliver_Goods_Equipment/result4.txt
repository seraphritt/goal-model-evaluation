## Design interpretation

The mission is a **resource logistics mission** in a multi-robot system. The main objective is not only “move items,” but also to handle planning, storage selection, collection, delivery, battery-triggered handoff, checkpoint recovery, escalation, and possible parallelization.

Key modeling decisions:

1. **Planning comes before execution** because the robot must know the requested resources, requesting agent, specified destination, storage places, waiting-time estimates, and path estimates before acting.
2. **Collection precedes delivery** because the delivery phase begins only once resources are retrieved.
3. **Collection battery failure uses fallback** because the mission says that if battery reaches 10% during collection, the robot returns to recharge and transfers the mission.
4. **Delivery battery failure uses fallback** because the mission says that if battery reaches 30% during delivery, the robot must checkpoint the resource and transfer the remaining task.
5. **Checkpoint-return failure uses fallback escalation** because if the robot fails to return the resource to a checkpoint, an alert and report must be sent.
6. **Parallel execution is possible** when multiple items are required from different storages.

# Logical Relationships

* **G1 -> G2, G11, G32 [AND][sequential: `G2;G11;G32`]**
  **Justification:** The mission must be planned before action, executed through collection and delivery, and then considered complete only after delivery or escalation is verified.

* **G2 -> G3, G4, G5, G8 [AND][mixed: `(G3#G4);G5;G8`]**
  **Justification:** Request details and storage discovery are independent and can happen in parallel. Collection ordering and robot assignment require those results.

* **G5 -> G6, G7 [AND][sequential: `G6;G7`]**
  **Justification:** The robot must first estimate waiting time plus path cost, then use that estimate to define the storage order.

* **G8 -> G10, G9 [AND-fallback][`FALLBACK(G10,G9)`]**
  **Justification:** Parallel execution is preferred when multiple items from different storages exist and enough robots are available; otherwise the single-robot mode is valid.

* **G11 -> G21, G12 [AND-fallback][`FALLBACK(G21,G12)`]**
  **Justification:** Parallel execution can reduce time, but if it is not applicable or feasible, the mission can still be fulfilled by one assigned robot.

* **G12 -> G13, G16 [AND][sequential: `G13;G16`]**
  **Justification:** Delivery phase begins only after resources have been retrieved.

* **G13 -> G14, G15 [AND-fallback][`FALLBACK(G14,G15)`]**
  **Justification:** Normal collection is the intended path. If the assigned robot reaches 10% battery during collection, it must return to recharge and reassign the mission.

* **G14 -> AT1, AT2, AT3 [AND][sequential: `AT1;AT2;AT3`]**
  **Justification:** The robot must go to storage, send the request message, and wait for retrieval.

* **G15 -> AT4, AT5, AT6 [AND][sequential: `AT4;AT5;AT6`]**
  **Justification:** The low-battery collection protocol requires returning to recharge, assigning another robot, and continuing the mission.

* **G16 -> G17, G18 [AND-fallback][`FALLBACK(G17,G18)`]**
  **Justification:** Normal delivery is attempted first. If battery reaches 30%, checkpoint recovery is required.

* **G18 -> G19, G20 [AND-fallback][`FALLBACK(G19,G20)`]**
  **Justification:** Returning the resource to checkpoint is attempted first. If that fails, alert and report are mandatory.

* **G21 -> G22, G23 [AND][sequential with parallel execution inside: `G22;(G23#G23)`]**
  **Justification:** Parallel tasks must first be assigned, then multiple collect-deliver cycles can run concurrently.

* **G23 -> G24, G27 [AND][sequential: `G24;G27`]**
  **Justification:** Even in parallel execution, each robot must collect its assigned resources before delivering them.

* **G25 -> AT17, AT18, AT19 [AND][parallel: `AT17#AT18#AT19`]**
  **Justification:** Different robots can navigate to different storages, send requests, and wait for retrieval concurrently.

* **G28 -> AT23, AT24 [AND][parallel: `AT23#AT24`]**
  **Justification:** Multiple robots may perform delivery runs and handovers concurrently to reduce mission completion time.

* **G30 -> AT25, AT26, AT27, AT28 [AND][sequential: `AT25;AT26;AT27;AT28`]**
  **Justification:** The resource must be checkpointed, its position communicated, the remaining task reassigned, and delivery completed.

* **G32 -> G33, G34 [AND][sequential: `G33;G34`]**
  **Justification:** The system should verify that resources arrived and that no pending tasks remain after possible multiple runs or reassignment.
