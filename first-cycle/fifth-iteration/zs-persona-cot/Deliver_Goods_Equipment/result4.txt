## 1. Design Rationale

The mission is modeled as a **resource-delivery mission** whose main objective is to collect requested resources from storage and deliver them to the requesting agent at a specified location. This follows the mission statement that a robot must “collect the required resources in the storage and deliver them” to the requester. :chatgpt-content-reference{index="0"}

The model uses mostly **AND decomposition**, because the mission requires complementary steps: obtain the request, plan the collection, collect the resources, and deliver them. AND means all children are required for the parent goal to be fulfilled. :chatgpt-content-reference{index="1"}

The **collection phase precedes the delivery phase**, because the description explicitly says that once the resources are retrieved, the delivery phase begins. :chatgpt-content-reference{index="2"}

The battery-related behaviors are modeled with **FALLBACK**, because the description defines normal behavior and then alternative behavior triggered by battery thresholds or failure conditions. The source defines FALLBACK as the correct operator for condition, exception, failure, threshold, or interruption cases. :chatgpt-content-reference{index="3"}

Parallel execution is included at the execution level because the mission states that when multiple items are required from different storages, multiple robots can be assigned to parallel collect-deliver tasks. :chatgpt-content-reference{index="4"}

The source also warns that OR should not be used to represent execution alternatives such as parallel execution, single/multiple execution, or assignment. :chatgpt-content-reference{index="55"}
