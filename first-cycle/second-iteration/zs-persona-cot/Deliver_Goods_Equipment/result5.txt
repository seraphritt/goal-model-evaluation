## 5. Main modeling rationale

The strongest **parallel** relation is in the multi-storage case, where multiple robots can be assigned to parallel collect-deliver tasks. Parallel monitoring is also used for battery contingencies because collection and delivery low-battery rules are phase-dependent safeguards that can be checked during mission execution.

The clearest **FALLBACK** relation is the delivery low-battery failure case: the robot first attempts to return the resource to a checkpoint and transfer the remaining task; if returning the resource fails, the mission escalates by triggering an alert and sending a report to the sector manager.

No unsupported physical location was invented for the alert/report task. The mission states the report recipient, the sector manager, but does not define a physical place where that report action occurs.
