## 1. Source-derived modeling rationale

The mission describes a robot-based logistics process where required resources must be collected from storage and delivered to a requesting agent at a specified location. The collection phase requires going to storage places, ordering visits by estimated waiting time plus robot path, sending a precise request message, and waiting until the resource is retrieved. The delivery phase starts after retrieval and may require as many runs as necessary to deliver all resources. :chatgpt-content-reference{index="0"}

The mission also defines exception behavior. If battery drops to 10% during collection, the robot returns to the recharging station and assigns the mission to another robot. If battery drops to 30% during delivery, the robot returns the resource to a checkpoint and assigns the remaining task to another robot. If checkpoint return fails, an alert and report to the sector manager are required. :chatgpt-content-reference{index="1"}

Parallelism is explicitly supported when multiple items are required from different storages: multiple robots can be assigned to parallel collect-deliver tasks to reduce mission time. :chatgpt-content-reference{index="2"} Therefore, the model uses `#` for parallel execution, `;` for sequential execution, and `FALLBACK(...)` only for explicitly described failure or conditional recovery behavior, as required by the runtime annotation rules. :chatgpt-content-reference{index="3"}

**Modeling convention:**  
`G6[1]#...#G6[n]` means that the same collect-deliver task pattern can be instantiated in parallel for `n` resource/storage-specific assignments. `n` is derived from the number of required resource groups and storage places. `R` represents the available robot limit. The mission states that multiple robots can be used, but it does not provide an exact maximum fleet size. :chatgpt-content-reference{index="4"}

### G1 → G2, G5 [AND] [sequential: `G2;G5`]
**Justification:** The mission must first be prepared by identifying resources, storage places, ordering information, and robot assignment. Only after that can the collect-deliver task set be executed. The mission description requires both collection from storage and delivery to the requesting agent. :chatgpt-content-reference{index="31"}

### G2 → G3, G4, AT1 [AND] [sequential: `G3;G4;AT1`]
**Justification:** The system must know what is requested, where it should be delivered, where resources are stored, and how robots are assigned. These are complementary preparation steps, not alternatives.

### G5 → G6[1] ... G6[n] [AND] [parallel: `G6[1]#...#G6[n]`]
**Justification:** If multiple items are required from different storages, multiple robots can execute collect-deliver tasks in parallel to reduce mission time. All required task instances must be completed for the whole request to be handled. :chatgpt-content-reference{index="32"}

### G6 → G7, G10 [AND] [sequential: `G7;G10`]
**Justification:** For each collect-deliver task, collection must happen before delivery. The mission explicitly says that once resources are retrieved, the delivery phase begins. :chatgpt-content-reference{index="33"}

### G7 → G8, G9 [AND] [fallback: `FALLBACK(G8,G9)`]
**Justification:** Normal collection is attempted first. The low-battery collection recovery is performed only under the explicitly stated condition that the assigned robot reaches 10% battery during collection. :chatgpt-content-reference{index="34"}

### G8 → AT2, AT3, AT4 [AND] [sequential: `AT2;AT3;AT4`]
**Justification:** The robot must travel to storage, send a precise resource request message, and wait until retrieval. These tasks must occur in order. :chatgpt-content-reference{index="35"}

### G9 → AT5, AT6 [AND] [sequential: `AT5;AT6`]
**Justification:** When the collection battery threshold is reached, the robot returns to the recharging station and assigns the mission to another robot. Both actions are required. :chatgpt-content-reference{index="36"}

### G10 → G11, G12 [AND] [fallback: `FALLBACK(G11,G12)`]
**Justification:** Normal delivery is attempted first. Delivery low-battery recovery is only triggered if the robot reaches the 30% threshold during delivery. :chatgpt-content-reference{index="37"}

### G11 → AT7, AT8 [AND] [sequential: `AT7;AT8`]
**Justification:** Delivery may require multiple runs. Therefore, the robot performs a delivery run and repeats runs until all assigned resources are delivered. :chatgpt-content-reference{index="38"}

### G12 → G13, G14 [AND] [fallback: `FALLBACK(G13,G14)`]
**Justification:** The first recovery action is to return the resource to a checkpoint and reassign the remaining delivery. The alert/report branch is attempted only if checkpoint return fails, matching the fallback definition. :chatgpt-content-reference{index="39"}

### G13 → AT9, AT10 [AND] [sequential: `AT9;AT10`]
**Justification:** The robot must first return the resource to a checkpoint. Then the remaining task can be assigned to another robot that knows where the resource is positioned. :chatgpt-content-reference{index="40"}
