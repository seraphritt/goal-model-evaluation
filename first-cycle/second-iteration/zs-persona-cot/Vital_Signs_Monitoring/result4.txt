## Mission Design Rationale (summary)

The mission is decomposed around the main objective: **perform periodic vital-sign monitoring of all patients using available robots while satisfying timing, safety, identification, and contingency constraints**.

Main modeling decisions:

* **AND decompositions** are used when all activities are mandatory for mission completion (e.g., a patient must be identified, checked, and marked as completed).
* **OR decompositions** are used when alternative strategies can achieve the same objective (e.g., identifying a patient by asking or scanning a barcode).
* **Sequential runtime (`;`)** is used when order matters (e.g., enter room → identify patient → collect vital signs).
* **Parallel runtime (`#`)** is used when activities can happen simultaneously (e.g., preparing assignments while monitoring robot status).
* **Fallback runtime** is used when the description explicitly requires an alternative after failure (e.g., patient unavailable → return after 5 minutes; insufficient battery → recharge and reassign).
