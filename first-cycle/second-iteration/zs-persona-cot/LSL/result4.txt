## 1. Scope and modeling rationale

### Included robot-performed mission elements
The goal model includes only mission elements that can be performed by robots:

- Transporting samples from **patient floors** to the **laboratory**.
- Carrying samples in **secure locked drawers**.
- Robotically checking whether a robot is authorized to open a drawer.
- Robotically opening locked drawers only in permitted locations.
- Robotic arm picking samples in the laboratory.
- Barcode scanning, sorting, and loading samples into the **entry-module of the analysis machines**.
- Securely logging where and when a sample was picked.
- Tracking collection-to-delivery time against laboratory protocols.

### Excluded human-only mission elements
The following are treated as external triggers/preconditions and are **not included as tasks**, because the prompt states that goals/tasks with zero robots must not be in the model:

| Mission element | Reason for exclusion |
|---|---|
| Nurse collects the sample | Human-only action. |
| Nurse requests delivery | Human-only trigger; represented indirectly by robot querying the delivery request. |
| Nurse inserts sample data in the track system | Human-only/system action; represented indirectly by robot querying the track data. |
| Laboratory personnel pick up sample | Human-only alternative; excluded by zero-robot rule. |
| Barcode identification before collection | Precondition/data source; robot scanning in the lab is included. |

### No FALLBACK relation used
No FALLBACK is modeled because the description does not specify a failure-triggered ordered alternative. The statement that a sample can be picked by a robotic arm or laboratory personnel is an alternative, but laboratory personnel are excluded because they are not robots, and no failure/order condition is specified.

# 5. Logical relationships

## Top-level mission

- **G1 -> G2, G6, G13 [AND][(G2;G6)#G13]**
  - **Justification:** The complete mission requires secure transport, robotic laboratory intake, and traceability/timing assurance. Transport must precede lab intake. Traceability/timing can occur in parallel with transport/intake because tracking and logging are monitoring activities linked to events during the mission.

---

## Secure transport branch

- **G2 -> G3, G4, G5 [AND][G3;G4;G5]**
  - **Justification:** The robot must first obtain delivery/sample information, then ensure the samples are secured in locked drawers, and finally deliver the drawer to the laboratory.

- **G3 -> AT1, AT2 [AND][AT1#AT2]**
  - **Justification:** The delivery request and sample tracking/barcode information are both required. They are independent data queries and may be performed in parallel.

- **G4 -> AT3, AT4 [AND][AT3;AT4]**
  - **Justification:** The drawer must be locked/verified before it can be monitored as locked during transport.

- **G5 -> AT5, AT6 [AND][AT5;AT6]**
  - **Justification:** The robot must physically transport the drawer to the laboratory and then confirm delivery.

---

## Laboratory intake branch

- **G6 -> G7, G11, G12 [AND][G7;G11;G12]**
  - **Justification:** Laboratory processing requires authorized drawer opening first, then robotic pickup/barcode scanning, then sorting/loading into analysis machines.

- **G7 -> G8, G9, G10 [AND][(G8#G9);G10]**
  - **Justification:** Drawer opening requires both robot authorization and location permission. These two checks can be performed in parallel, but drawer opening must occur only after both are satisfied.

- **G8 -> AT7, AT8 [AND][AT7;AT8]**
  - **Justification:** The robot must identify itself before its authorization can be checked.

- **G9 -> AT9, AT10 [AND][AT9;AT10]**
  - **Justification:** The robot must determine its current location before validating whether opening is allowed there.

- **G10 -> AT11, AT12 [AND][AT11;AT12]**
  - **Justification:** The drawer must be unlocked before it can be physically opened.

- **G11 -> AT13, AT14 [AND][AT13;AT14]**
  - **Justification:** The robotic arm picks each sample and then scans its barcode. The barcode scan depends on having access to the picked sample.

- **G12 -> AT15, AT16 [AND][AT15;AT16]**
  - **Justification:** Samples must be sorted before they are loaded into the corresponding entry-module of the analysis machines.

---

## Traceability and timing branch

- **G13 -> G14, G15 [AND][G14#G15]**
  - **Justification:** Secure pickup logging and timing-compliance checking are both required. They concern different monitored properties and can be performed independently.

- **G14 -> AT17, AT18 [AND][AT17;AT18]**
  - **Justification:** The robot must first capture the pickup location/time and then securely write the log entry.

- **G15 -> AT19, AT20 [AND][AT19;AT20]**
  - **Justification:** The robot must retrieve collection/delivery timestamps before calculating elapsed time and comparing it with laboratory protocols.
