## 1. Modeling scope and rationale

This goal model includes **only intentions and actions that can be performed by robots or robot-controlled subsystems**.

Excluded from the goal model because they are **not robot-performed** in the description:

- Nurse collecting the sample.
- Nurse requesting the delivery.
- Nurse inserting sample data into the track system.
- Human laboratory personnel picking samples.
- Human authorized personnel opening drawers.

These are treated as **external triggers, preconditions, or non-robot alternatives**, not as goal-model nodes.

The mission is modeled as one requested delivery/batch. For multiple simultaneous deliveries, the same goal model can be instantiated multiple times.

No FALLBACK relation is used because the description does not specify a failure-triggered ordered recovery behavior.  
No OR decomposition is used because the explicit alternatives involving humans are excluded by the “robot-only” constraint.

## 5. Logical relationships

### Root mission decomposition

- **G1 -> G2, G3, G4, G5, G6 [AND][sequential: `G2;G3;G4;G5;G6`]**
  - **Justification:** All major mission intentions are required. The robot first needs delivery/sample information, then the sample must be secured in a locked drawer, transported to the laboratory with timing evidence, accessed only under authorization, and finally processed by the robotic arm. The order follows the mission flow from request to lab processing.

---

### Delivery-data acquisition

- **G2 -> AT1, AT2 [AND][sequential: `AT1;AT2`]**
  - **Justification:** The robot must first obtain the delivery request, then obtain or verify the sample barcode/track-system data associated with that request. Both are necessary for safe and traceable transport, so the relation is AND.

---

### Secure drawer preparation at patient floor

- **G3 -> AT3, AT4 [AND][sequential: `AT3;AT4`]**
  - **Justification:** The locked drawer must be accessed/presented only through an authorized robot at the patient floor, and then it must be locked before transport. The drawer cannot be locked for transport before the handoff step is complete, so the order is sequential.

---

### Transport and protocol timing

- **G4 -> AT5, AT6, AT7 [AND][sequential: `AT5;AT6;AT7`]**
  - **Justification:** The sample must be transported from patient floors to the laboratory. Once it arrives, the robot records the laboratory delivery time. Only after delivery time is known can the robot check the collection-to-delivery duration against protocols. All three are necessary, so this is an AND decomposition.

---

### Authorized laboratory drawer access

- **G5 -> AT8, AT9 [AND][sequential: `AT8;AT9`]**
  - **Justification:** The drawer must not be opened until robot identity and location authorization succeed. Therefore, authorization verification must occur before drawer opening. Both tasks are required to satisfy the security constraint.

---

### Robotic sample processing and traceability

- **G6 -> AT10, AT11, AT12, AT13, AT14 [AND][sequential/parallel: `AT10;(AT11#AT12);AT13;AT14`]**
  - **Justification:** The robotic arm must first pick the sample. After pickup, two required actions can potentially occur in parallel: secure pickup logging and barcode scanning. The description requires both but does not impose an order between them. Sorting depends on identification, so it follows scanning. Loading into the analysis-machine entry module is the final step after sorting.

## 6. Notes on OR and FALLBACK absence

| Relation type | Used? | Reason |
|---|---:|---|
| OR decomposition | No | The description contains alternatives involving humans, such as “robotic arm or laboratory personnel” and “authorized personnel or specific robots.” However, non-robot actions must not be included in the goal model. No explicit alternative between two robot-performed options is specified. |
| FALLBACK | No | The description does not define a failure condition such as “if the robotic arm fails, then laboratory personnel pick the sample.” It only states possible actors, not an ordered failure-recovery behavior. Therefore, FALLBACK is not justified. |
