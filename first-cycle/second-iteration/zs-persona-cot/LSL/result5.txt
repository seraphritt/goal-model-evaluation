## Modeling scope and assumptions

- The model includes **only robot-performed goals/tasks**. Human-only activities are excluded from the goal model, including: nurse collecting the sample, nurse inserting data, and laboratory personnel picking up samples.
- The nurse request and track-system data are treated as **external triggers/data sources** that robots query and use.
- The laboratory personnel alternative is **not modeled as an OR branch** because it is not performed by a robot.
- No FALLBACK relation is used because the mission description does not define an explicit “try X, if X fails then Y” behavior.
- The model is written for one delivery request/sample or sample batch; it can be repeated for multiple requests.

# 4. Logical Relationships and Justifications

- **G1 → G2, G3, G6, G8, G11 [AND][sequential: `G2;G3;G6;G8;G11`]**  
  - **Justification:** The whole robotic mission requires delivery data, secure drawer preparation, physical transport, authorized lab access, and robotic lab intake. These are all mandatory and naturally ordered.

- **G2 → AT1, AT2 [AND][sequential: `AT1;AT2`]**  
  - **Justification:** The robot must first detect/retrieve the delivery request and then obtain the corresponding sample/barcode information.

- **G3 → G4, G5 [AND][sequential: `G4;G5`]**  
  - **Justification:** The drawer should only be operated after authorization is confirmed. Both authorization and secure locking are required.

- **G4 → AT3, AT4 [AND][parallel: `AT3#AT4`]**  
  - **Justification:** Authorization depends on both robot identity and location. These checks are independent and can be performed in parallel.

- **G5 → AT5, AT6, AT7 [AND][sequential: `AT5;AT6;AT7`]**  
  - **Justification:** The drawer must be unlocked, then locked after loading, then verified as locked before transport. The order is necessary for secure transport.

- **G6 → AT8, G7 [AND][parallel: `AT8#G7`]**  
  - **Justification:** Physical delivery and timing supervision are both required. Timing can be tracked while the robot is transporting the drawer.

- **G7 → AT9, AT10, AT11 [AND][sequential: `AT9;AT10;AT11`]**  
  - **Justification:** To evaluate the collection-to-delivery interval, the robot needs the collection timestamp, then the delivery timestamp, then the elapsed-time compliance result.

- **G8 → G9, G10 [AND][sequential: `G9;G10`]**  
  - **Justification:** The laboratory drawer should be opened only after the robot and location are authorized.

- **G9 → AT12, AT13 [AND][parallel: `AT12#AT13`]**  
  - **Justification:** The access rule includes both robot identity and location; these checks can be executed in parallel.

- **G10 → AT14, AT15 [AND][sequential: `AT14;AT15`]**  
  - **Justification:** The robot must unlock the drawer to allow pickup and then re-secure it to preserve the secure-drawer requirement.

- **G11 → AT16, AT17, AT18, AT19, AT20 [AND][mixed: `AT16;((AT17;AT18;AT19)#AT20)`]**  
  - **Justification:** The sample must first be picked. After pickup, barcode scanning, sorting, and loading must occur in sequence. Secure logging of pickup time/location can occur in parallel with those later processing steps because the pickup event has already occurred.
