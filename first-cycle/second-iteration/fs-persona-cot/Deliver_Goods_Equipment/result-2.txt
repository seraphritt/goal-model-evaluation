## Source-Grounded Interpretation

The mission’s main objective is that a robot collects required resources from storage and delivers them to a requesting agent at a specified location. The collection phase requires visiting storage places, ordering visits by estimated waiting time plus robot path, sending a precise resource request, and waiting until the resources are retrieved. :chatgpt-content-reference{index="0"}

The delivery phase starts after retrieval and may require as many runs as necessary to move all resources to the specified location. Battery contingencies are explicitly different for collection and delivery: 10% battery during collection causes return to the recharging station and reassignment; 30% battery during delivery causes checkpoint return and reassignment, with alert/reporting if checkpoint return fails. :chatgpt-content-reference{index="1"}

When multiple items are required from different storages, multiple robots may be assigned to parallel collect-deliver tasks to reduce mission time. :chatgpt-content-reference{index="2"}

**Notation note:** `n` means the number of robots available and useful for the required items/storages. Task locations use only mission-stated locations: `storage places`, `storage`, `specified location`, `recharging station`, `checkpoint`, and `sector manager`.

- **G2 -> G3, G4 [AND][sequential: `G3;G4`]**  
  **Justification:** The system needs both ordering information and robot assignment before execution. Storage ordering is based on waiting time plus path, and robot assignment may involve multiple robots. :chatgpt-content-reference{index="36"} :chatgpt-content-reference{index="37"}

- **G3 -> AT1, AT2 [AND][sequential: `AT1;AT2`]**  
  **Justification:** Both waiting time and robot path are required because the order is defined by their sum. :chatgpt-content-reference{index="38"}
