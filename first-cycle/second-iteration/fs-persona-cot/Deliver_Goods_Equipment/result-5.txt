## Logical Relationships

**G1 -> G2, G5 [AND][sequential: `G2;G5`]**  
Justification: the mission must first be prepared by identifying resources, storage places, ordering, and assignment; only then can collection and delivery be executed.

**G2 -> G3, G4 [AND][sequential: `G3;G4`]**  
Justification: the robot must know the request details before determining storage ordering and robot assignment.

**G4 -> G4.1, G4.2 [AND][sequential: `G4.1;G4.2`]**  
Justification: the system must estimate waiting time and path before deciding the collection order and whether multiple robots should be assigned.

**G5 -> G6 instances [AND][parallel: `G6#G6`]**  
Justification: when multiple items are required from different storages, multiple robots can execute collect-deliver tasks in parallel to reduce total mission time.

**G6 -> G7, G10 [AND][sequential: `G7;G10`]**  
Justification: the mission explicitly says delivery begins once the resources have been retrieved.

**G7 -> G8, G9 [AND][fallback: `FALLBACK(G8,G9)`]**  
Justification: normal collection is attempted first. If battery reaches 10% in the collection phase, the robot goes to the recharging station and assigns the mission to another robot.

**G8 -> G8.1, G8.2, G8.3 [AND][sequential: `G8.1;G8.2;G8.3`]**  
Justification: the collection phase is ordered: go to storage, send the request message, then wait until resources are retrieved.

**G9 -> G9.1, G9.2 [AND][sequential: `G9.1;G9.2`]**  
Justification: after the collection battery condition occurs, the robot must return to the recharging station and assign the mission to another robot.

**G10 -> G11, G12 [AND][fallback: `FALLBACK(G11,G12)`]**  
Justification: normal delivery is pursued first. If battery reaches 30% in the delivery phase, the checkpoint handoff behavior is required.

**G11 -> G11.1, G11.2 [AND][sequential: `G11.1;G11.2`]**  
Justification: the robot must perform delivery runs and confirm that all resources have been transported.

**G12 -> G13, G14 [AND][fallback: `FALLBACK(G13,G14)`]**  
Justification: the robot first attempts to return the resource to a checkpoint. If that fails, an alert and report must be produced.

**G13 -> G13.1, G13.2, G13.3 [AND][sequential: `G13.1;G13.2;G13.3`]**  
Justification: checkpoint handoff requires the resource to be positioned, the replacement robot to know its position, and the remaining task to be assigned.

**G14 -> G14.1, G14.2 [AND][sequential: `G14.1;G14.2`]**  
Justification: failure to return to checkpoint requires both alert triggering and sending a report to the sector manager.
