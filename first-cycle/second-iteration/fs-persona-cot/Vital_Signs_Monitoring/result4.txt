## Mission Analysis Rationale (brief)

The mission is decomposed around the main intentional objective: **perform periodic vital-sign monitoring of all patients using available robots while respecting safety constraints**.

Main decomposition decisions:

* The mission requires several conditions to be simultaneously satisfied (patient identification, availability verification, battery management, vital-sign collection, safety procedures, and timing constraints). Therefore, most high-level goals use **AND decomposition**.
* Some activities have alternatives:

  * Patient identification can happen through asking the patient **OR** scanning a barcode.
  * Failed vital-sign collection can be handled through fallback questioning and then escalation.
  * Patient availability can result in either checking now or scheduling a retry.
* Runtime annotations represent operational ordering:

  * Robot must verify availability and battery **before entering the room** → sequential.
  * Robot can perform independent checks/actions simultaneously when the mission allows it → parallel.
  * Recovery actions after failure are represented using FALLBACK.
