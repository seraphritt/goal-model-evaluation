## Design rationale (brief)

The mission is modeled as an **Achieve-oriented mission** because the system must reach explicit world states (e.g., “all occupied rooms checked”, “high-risk patients checked within 15 minutes”, “failed measurements handled”). Query goals are used when the robot only needs to obtain information (e.g., room occupancy, patient identity, battery level). Perform goals are used for concrete actions that must be executed (e.g., entering rooms, announcing procedures, sterilization).

The root goal is decomposed with **AND** because all mission obligations must be satisfied. Parallel execution is used where independent activities can occur simultaneously (e.g., checking different rooms with multiple robots). Sequential execution is used where the mission description imposes an order (e.g., identify patient → enter room → collect vital signs → mark done). Fallback is used where an alternative action is explicitly required after failure (e.g., failed vital sign collection → ask status questions → alert medical staff if no response).

# Logical Relationships

### G1 -> G2, G7, G12, G13 [AND][Parallel]

* **Justification:** The mission cannot succeed unless preparation, patient monitoring, failure management, and safety procedures are all completed. These activities can overlap when multiple robots exist.

### G2 -> G3, G4 [AND][Sequential]

* **Justification:** The system must first obtain room information before assigning robots.

### G4 -> G5, G6 [AND][Parallel]

* **Justification:** Battery evaluation and reassignment management are independent resource activities.

### G7 -> G8, G9, G10, G11 [AND][Sequential]

* **Justification:** The robot must identify the patient, interact, measure vital signs, and only then mark the room completed.

### G8 -> G14, G15 [AND][Parallel]

* **Justification:** Availability and identity are both required before entering the room.

### G15 -> AT7, AT6 [AND][FALLBACK(AT7,AT6)]

* **Justification:** Patient identification can be performed by asking or by scanning the barcode when the first method is insufficient.

### G9 -> AT9, AT10, AT11 [AND][Sequential]

* **Justification:** The robot approaches, explains, and instructs before measurement.

### G12 -> G18, G19 [AND][FALLBACK(G18,G19)]

* **Justification:** The mission specifies attempting patient status questions first and alerting staff if the patient does not respond.

### G13 -> G20, G21 [AND][Parallel]

* **Justification:** Sterilization after infectious rooms and actuator disinfection after contact are separate safety requirements.

### G4 -> AT2, AT3, AT4 [AND]

* **Justification:** Battery checking, charging, and reassignment are all required when resources are insufficient.

### G7 -> AT12, AT15 [AND]

* **Justification:** Vital sign collection and completion marking are necessary operational steps.

### G13 -> AT16, AT17 [AND]

* **Justification:** Both infection-control actions are required depending on the situation.

### G1 -> AT18, AT19 [AND]

* **Justification:** Additional robots should be requested when needed, and the manager must be informed if the mission remains impossible.
