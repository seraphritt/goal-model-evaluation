## Mission Analysis Rationale (Concise)

The mission describes a periodic hospital monitoring mission where robots must autonomously inspect patients, collect vital signs, handle failures, maintain safety constraints (battery, sterilization, patient identification), and escalate when the mission cannot be completed.

Main modeling decisions:

* **High-level mission objective is modeled as an Achieve Goal** because the desired final state is that all required patients have been checked within the required constraints.
* **Patient information acquisition goals are Query Goals** because the robot retrieves world information (room occupation, patient identity, availability, risk condition).
* **Robot actions such as navigation, measuring signs, sterilization, recharging, and alerting are Perform Goals** because they represent required robot behaviors.
* **AND decompositions** are used when all activities are mandatory for mission completion.
* **OR decompositions** are used when alternatives can independently satisfy a requirement (e.g., identifying a patient by asking or scanning).
* **Sequential runtime constraints** are used where the description imposes an order (e.g., identify patient before entering procedure).
* **Fallback runtime constraints** are used where the mission explicitly defines recovery behavior (e.g., failed measurement → questions → alert).
