## 1. Modeling scope and key interpretation

This goal model includes only mission elements that can be performed by robots. Therefore:

- Included:
  - A delivery robot transporting samples from **patient floors** to the **laboratory**.
  - A robotic arm opening/accessing the locked drawer when authorized.
  - A robotic arm picking, scanning, sorting, and loading samples into the **entry-module of the analysis machines**.
  - Robot-side secure logging and protocol-time tracking.

- Excluded from the goal model because they are not robot-performed:
  - Nurse collecting the sample.
  - Nurse inserting data into the tracking system.
  - Laboratory personnel picking samples.
  - Human authorization actions.

The human alternatives mentioned in the description are acknowledged, but not modeled as goal/task nodes because the instruction says that goals/tasks performed by zero robots must not be in the goal model.

No FALLBACK relation is used because the mission description does not define an explicit failure-triggered alternative order. The sentence “robotic arm or laboratory personnel” is an alternative, but the human branch is excluded and there is no stated fallback order.

## 5. Logical Relationships

- **G1 -> G2, G3, G6, G9 [AND][G2;((G3;G6)#G9)]**
  - **Justification:** The whole mission requires request/data acquisition, secure transport, robotic laboratory processing, and traceability/protocol tracking. G2 must happen first because the robot needs the delivery request and barcode/sample data. G3 must precede G6 because samples must arrive at the laboratory before robotic arm processing. G9 can operate in parallel with G3 and G6 because timing and logging are monitoring activities tied to events during transport and pickup.

- **G2 -> AT1, AT2 [AND][AT1;AT2]**
  - **Justification:** The robot must receive the delivery request and retrieve barcode-linked sample data. The request identifies the mission, and the metadata identifies the samples.

- **G3 -> G4, G5 [AND][G4;G5]**
  - **Justification:** Secure sample transport requires both preserving drawer security and physically delivering the drawer to the laboratory. Security must be established before/during transport.

- **G4 -> AT3, AT4 [AND][AT3;AT4]**
  - **Justification:** The drawer must be locked before departure and remain secure during movement. Both are required by the “secure locked drawers” constraint.

- **G5 -> AT5, AT6 [AND][AT5;AT6]**
  - **Justification:** The robot must first move from patient floors to the laboratory and then position the drawer for laboratory robotic access.

- **G6 -> G7, G8 [AND][G7;G8]**
  - **Justification:** Laboratory robotic processing requires authorized drawer opening before samples can be picked, scanned, sorted, and loaded.

- **G7 -> AT7, AT8 [AND][AT7;AT8]**
  - **Justification:** Since only authorized personnel or specific robots in specific locations may open locked drawers, robot and location authorization must occur before the drawer is opened.

- **G8 -> AT9, AT10, AT11, AT12 [AND][AT9;AT10;AT11;AT12]**
  - **Justification:** The mission explicitly states the robotic arm sequence: pick up samples, scan barcode, sort, and load into the entry-module of the analysis machines.

- **G9 -> G10, G11 [AND][G10#G11]**
  - **Justification:** The system must both securely log pickup information and track collection-to-delivery time. These are complementary monitoring goals and can run in parallel because one is tied to pickup events and the other to delivery-time compliance.

- **G10 -> AT13, AT14 [AND][AT13;AT14]**
  - **Justification:** Secure pickup logging requires first capturing the pickup information and then storing it securely.

- **G11 -> AT15, AT16 [AND][AT15;AT16]**
  - **Justification:** Protocol timing verification requires recording the laboratory delivery time and comparing the elapsed collection-to-delivery interval against laboratory protocols.
