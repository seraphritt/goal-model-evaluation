## Mission Analysis Rationale (brief)

The mission objective is interpreted as **periodically monitoring all patients' vital signs using one or more robots**. The main decomposition follows these principles:

* The mission requires several complementary activities (visiting rooms, validating patient identity, checking patient availability, checking battery, collecting measurements, handling failures, sterilization, and escalation), therefore most decompositions are **AND**.
* Some steps represent alternatives explicitly stated in the mission:

  * Patient identification can be performed by asking the patient **or** scanning the barcode → OR.
  * Additional robots can be assigned when the current allocation is insufficient → fallback behavior.
* Runtime annotations represent temporal constraints:

  * Visiting rooms, checking patients, and completing measurements happen sequentially.
  * Some independent preparation/monitoring activities can occur in parallel.
* Goals are classified as:

  * **Achieve** when the objective is reaching a world state (e.g., "all patients checked").
  * **Perform** when the objective is executing an action (e.g., sterilizing a robot).
  * **Query** when information must be obtained (e.g., identifying a patient).
