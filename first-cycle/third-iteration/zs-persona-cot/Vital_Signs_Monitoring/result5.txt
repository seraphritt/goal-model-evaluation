# 5. Logical relationships

## Mission-level relationships

**G1 -> G2, G7, G37 [AND] [`G2;FALLBACK(G7,G37)`]**  
- **Justification:** The mission must first be prepared, then attempted using the assigned allocation. If it cannot be performed in the required time, the model falls back to infeasibility handling.

**G2 -> G3, G4, G5, G6 [AND] [`(G3#G4);(G5;G6)`]**  
- **Justification:** Room occupancy and patient profiles are both required and can be retrieved independently. Robot assignment and high-risk scheduling follow after the mission scope is known.

**G7 -> G8, G9 [AND] [`G8;G9`]**  
- **Justification:** High-risk patients must be checked in the first 15 minutes, so this must be enforced before the general occupied-room workflow proceeds.

**G37 -> G38, G39 [AND] [`FALLBACK(G38,G39)`]**  
- **Justification:** The mission first tries to recover by assigning additional robots. If no robot combination can complete the mission, the manager is alerted.

## Preparation relationships

- **Justification:** Identifying occupied rooms operationalizes the need to visit every occupied room.

**G4 -> AT2 [AND]**  
- **Justification:** Retrieving patient condition data operationalizes the condition-specific vital-sign requirements.

**G5 -> AT3, AT4 [AND]**  
- **Justification:** The mission requires both assigning a robot and allocating the rooms/tasks to that robot.

**G6 -> AT5 [AND]**

## Room-workflow relationships

**G9 -> G10, G17, G20, G32 [AND] [`G10;G17;G20;G32`]**  
- **Justification:** A valid room visit requires readiness checking, patient identification, bedside procedure execution, and post-check closure/hygiene.

**G10 -> G11, G14 [AND] [`G11#G14`]**

**G11 -> G12, G13 [AND] [`FALLBACK(G12,G13)`]**

**G12 -> AT8 [AND]**

**G13 -> AT9 [AND]**  
- **Justification:** Returning after 5 minutes is the specified action after patient unavailability.

**G14 -> G15, G16 [AND] [`FALLBACK(G15,G16)`]**  
- **Justification:** The robot first checks battery sufficiency. If insufficient, it recharges and triggers task reassignment.

**G15 -> AT10 [AND]**  
- **Justification:** Checking battery level operationalizes the battery-readiness query.

**G16 -> AT11, AT12 [AND]**  
- **Justification:** The mission requires both recharge and task reassignment when battery is insufficient.

## Bedside-procedure relationships

**G20 -> G21, G22, G23 [AND] [`G21;G22;G23`]**  
- **Justification:** The robot must approach the patient, announce/provide instructions, and then perform vital-sign checking.

**G21 -> AT15 [AND]**

**G22 -> AT16, AT17 [AND]**

**G23 -> G24, G28, G30, G31 [AND] [`G24;FALLBACK(G28,FALLBACK(G30,G31))`]**  
- **Justification:** The robot must determine required measurements, try to collect them, ask questions if collection fails, and alert the responsible nurse/doctor if there is non-response.

**G24 -> G25, G26, G27 [AND] [`G25#G26#G27`]**  
- **Justification:** The patient may have infectious disease, post-surgical condition, diabetes history, or combinations of these; therefore all applicable condition checks must be considered.

- **Justification:** Infectious-disease requirements must be checked to determine the need for heart rate, blood pressure, temperature, and oxygenation measurements.

**G26 -> AT19 [AND]**  
- **Justification:** Post-surgical requirements must be checked to determine the need for heart rate and oxygenation measurements.

**G27 -> AT20 [AND]**  
- **Justification:** Diabetes history must be checked to determine the need for glucose measurement.

**G28 -> G29 [AND]**  
- **Justification:** Vital-sign collection is performed through the condition-specific measurement tasks.

**G29 -> AT21, AT22, AT23, AT24, AT25 [AND]**  
- **Justification:** These tasks represent the full set of possible required measurements. In execution, the applicable subset is selected from the patient’s condition profile.

**G30 -> AT26 [AND]**  
- **Justification:** Asking assessment questions operationalizes the required response to failed vital-sign collection.

**G31 -> AT27 [AND]**
