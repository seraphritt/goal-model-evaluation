## Mission Design Rationale (concise)

The mission is decomposed around the main intentional objective: **perform periodic patient vital-sign monitoring using a multi-robot team**.

Main modeling decisions:

* The overall mission is an **Achieve Goal** because the system must reach a desired world state: all required patients have been checked according to their medical conditions.
* Patient checking is decomposed into preparation, patient identification, measurement execution, exception handling, hygiene, and mission feasibility because these are complementary requirements.
* Sequential runtime annotations are used when the description explicitly imposes an order (e.g., identify patient → enter room → perform measurements).
* Parallel runtime annotations are used where activities can happen independently (e.g., checking battery while allocating robots, hygiene procedures while other robots continue).
* Fallback is used where the mission explicitly requires an alternative action after failure (e.g., if vital signs cannot be collected, ask questions; if the patient does not respond, alert medical staff).

# Logical Relationships

### G1 -> G2, G3, G6, G9, G12, G15 [AND][(G2#G12#G15);G3;G6;G9]

* **Justification:** The mission requires all these capabilities. Resource preparation, hygiene, feasibility monitoring, patient visiting, measurement, and exception handling are complementary. Some preparation activities can occur in parallel before execution.

---

### G2 -> AT1, AT2 [AND][parallel]

* **Justification:** Battery verification and robot allocation are both necessary preparation activities and can occur independently.

---

### G3 -> G4, G5 [AND][sequential]

* **Justification:** The robot must reach the room before identifying the patient inside it.

---

### G5 -> AT4, AT5 [OR]

* **Justification:** Patient identification can be achieved either by asking the patient or scanning the barcode.

---

### G6 -> G7, G8 [AND][sequential]

* **Justification:** The robot must know which measurements are required before collecting them.

---

### G9 -> G10, G11 [AND][parallel]

* **Justification:** Patient unavailability and measurement failure are independent exception cases that must be handled.

---

### G11 -> AT9, AT10 [AND][FALLBACK(AT9,AT10)]

* **Justification:** Questions are attempted first after failed measurements. If the patient does not respond, an alert is sent.

---

### G12 -> AT11, AT12 [AND][parallel]

* **Justification:** Sterilization after infectious rooms and actuator disinfection after contact are separate hygiene obligations.

---

### G15 -> AT13, AT14 [AND][FALLBACK(AT13,AT14)]

* **Justification:** Additional robots are the first recovery strategy. If no robot combination can complete the mission, the manager must be alerted.
