## Mission-design rationale (summary)

The mission is modeled as a hierarchical multi-robot objective where the main objective is to perform periodic patient vital-sign monitoring. The decomposition follows these principles:

* **AND relations** are used when several activities are mandatory together (e.g., checking patients requires visiting rooms, identifying patients, collecting signs, and handling failures).
* **OR relations** are used when alternatives exist (e.g., patient identification by asking or barcode scanning).
* **Sequential runtime (`;`)** is used when the mission description imposes an order (e.g., enter room → approach patient → collect measurements).
* **Parallel runtime (`#`)** is used when activities can occur simultaneously (e.g., multiple robots checking different rooms).
* **Fallback runtime** is used where the mission explicitly defines recovery behavior (e.g., insufficient battery → recharge → reassign tasks).
