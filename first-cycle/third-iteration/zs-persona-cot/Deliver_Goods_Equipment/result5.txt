## Modeling assumptions

1. **Main mission objective:** a robot collects required resources from storage and delivers them to the requesting agent at the specified location. Texto colado  
2. **Collection precedes delivery:** the description explicitly defines a collection phase and says that, once resources are retrieved, the delivery phase begins. Texto colado  
3. **Battery exceptions are fallback behavior:** 10% battery in collection causes return to recharging station and reassignment; 30% battery in delivery causes checkpoint handoff. Texto colado  
4. **Parallelism is allowed when multiple items come from different storages:** multiple robots may perform parallel collect-deliver tasks to reduce total mission time. Texto colado

- **G1 → G2, G3, G7 [AND][sequential: `G2;G3;G7`]**  
  - **Justification:** The mission first requires assignment of a robot or robots, then collection, then delivery. Collection must precede delivery because the delivery phase begins once resources are retrieved. Texto colado

- **G2 → AT1, AT2 [OR][fallback strategy: `FALLBACK(AT2, AT1)`]**  
  - **Justification:** A single robot is the default formulation, but multiple robots can be assigned when multiple items from different storages justify parallel collect-deliver tasks. Texto colado Texto colado

- **G3 → G4, G5, G6 [AND][sequential + fallback: `G4;FALLBACK(G5, G6)`]**  
  - **Justification:** The collection phase needs an ordered storage plan, then normal retrieval. If collection cannot continue because battery reaches 10%, the mission switches to the recharging-and-reassignment behavior. Texto colado

- **G4 → AT3, AT4 [AND][parallel: `AT3#AT4`]**  
  - **Justification:** Waiting time and path are both required to define the order. They are modeled as parallel information-gathering tasks because both are estimates needed before ordering. Texto colado

- **G5 → AT5, AT6, AT7 [AND][sequential: `AT5;AT6;AT7`]**  
  - **Justification:** The robot must first go to storage, then send the precise request message, then wait until retrieval is complete. Texto colado

- **G6 → AT8, AT9 [AND][sequential: `AT8;AT9`]**  
  - **Justification:** When battery reaches 10% during collection, the robot returns to the recharging station and assigns the mission to another robot. Texto colado

- **G7 → G8, G9 [AND][fallback: `FALLBACK(G8, G9)`]**  
  - **Justification:** Normal delivery is attempted by making the required runs. If delivery is interrupted by the 30% battery threshold, the checkpoint handoff behavior is used. Texto colado

- **G8 → AT10, AT11 [AND][sequential: `AT10;AT11`]**  
  - **Justification:** The robot must perform as many runs as necessary, so the run requirement is determined and then executed. Texto colado
