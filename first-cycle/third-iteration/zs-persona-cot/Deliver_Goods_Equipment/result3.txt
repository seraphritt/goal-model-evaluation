## 1. Design Rationale

The mission’s top-level objective is to ensure that required resources are collected from storage and delivered to the requesting agent at the specified location. The mission explicitly separates the work into a **collection phase** and a **delivery phase**, so the core execution is modeled sequentially: collect first, deliver afterward. The description states that the robot must go to storage places, request resources, wait for retrieval, and then begin delivery, including as many delivery runs as necessary. :chatgpt-content-reference{index="0"}

Battery-related behavior is modeled as **FALLBACK** because the description defines exception-triggered behavior: low battery at 10% during collection causes return to recharge and reassignment, while low battery at 30% during delivery causes checkpoint return and reassignment. If checkpoint return fails, alerting and reporting are triggered. :chatgpt-content-reference{index="1"} This matches the provided fallback definition, which applies to normal behavior followed by an alternative behavior triggered by a condition, exception, failure, threshold, or interruption. :chatgpt-content-reference{index="2"}

No OR decomposition is used because the mission does not describe true alternatives where only one child is sufficient. Instead, the mission describes required complementary subgoals, so decompositions are AND-based. OR would be used only for alternatives, while AND is used when all children must be fulfilled. :chatgpt-content-reference{index="3"}

The mission also states that when multiple items are required from different storages, multiple robots can be assigned to parallel collect-deliver tasks. Therefore, the collect-deliver subtree is modeled as a repeatable task instance `G11[i]`, with parallel execution across instances. :chatgpt-content-reference{index="4"}

## 5. Logical Relationships

**G1 -> G2, G6, G10 [AND][sequential: `G2;G6;G10`]**  
- **Justification**: The mission must first identify what is required, then plan storage order and robot assignment, and finally execute collection and delivery.

**G2 -> G3, G4, G5 [AND][parallel: `G3#G4#G5`]**  
- **Justification**: Required resources, requesting agent/location, and storage places are all necessary mission context items. They are independent query results, so they can be obtained without a strict sequence.

**G6 -> G7, G8, G9 [AND][parallel then sequential: `(G7#G8);G9`]**  
- **Justification**: Waiting time and path estimates are both required before defining the storage order and robot assignment.

**G9 -> AT1, AT2 [AND][sequential: `AT1;AT2`]**  
- **Justification**: The system first defines the storage order, then assigns robot(s) to execute the collect-deliver tasks.

**G10 -> G11[1], ..., G11[n] [AND][parallel: `G11[1]#...#G11[n]`]**  
- **Justification**: All assigned collect-deliver task instances must finish. When multiple items are located in different storages, multiple robots can work in parallel.

**G11 -> G12, G15 [AND][sequential: `G12;G15`]**  
- **Justification**: A collect-deliver task must collect resources first and deliver them afterward.

**G12 -> G13, G14 [AND][fallback: `FALLBACK(G13,G14)`]**  
- **Justification**: Normal collection is attempted first. If collection is interrupted by the 10% battery condition, the low-battery handover behavior is executed.

**G13 -> AT3, AT4, AT5, AT6 [AND][sequential: `AT3;AT4;AT5;AT6`]**  
- **Justification**: The robot must go to storage, request the resource, wait for retrieval, and confirm retrieval before delivery can begin.

**G14 -> AT7, AT8 [AND][sequential: `AT7;AT8`]**  
- **Justification**: During collection low battery, the robot returns to the recharging station and the mission is assigned to another robot.

**G15 -> G16, G17 [AND][fallback: `FALLBACK(G16,G17)`]**  
- **Justification**: Normal delivery is attempted first. If delivery is interrupted by the 30% battery condition, delivery low-battery behavior is executed.

**G16 -> AT9, AT10 [AND][sequential: `AT9;AT10`]**  
- **Justification**: Delivery requires making the necessary runs and bringing the resources to the requesting agent at the specified location.

**G17 -> G18, G19 [AND][fallback: `FALLBACK(G18,G19)`]**  
- **Justification**: The robot first attempts checkpoint handover. If returning the resource to a checkpoint fails, alerting and reporting are triggered.

**G18 -> AT11, AT12, AT13 [AND][sequential: `AT11;AT12;AT13`]**  
- **Justification**: The resource must be returned to a checkpoint, the remaining task must be assigned to another robot, and the replacement robot must know where the resource is positioned.

**G19 -> AT14, AT15 [AND][sequential: `AT14;AT15`]**  
- **Justification**: When checkpoint return fails, the system must trigger an alert and send a report to the sector manager.
