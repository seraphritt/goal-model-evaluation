## Modeling assumptions and traceability

This model decomposes the mission in which robots collect required resources from storage places and deliver them to a requesting agent at a specified location. The collection phase includes going to storage places, ordering visits by estimated waiting time plus path, requesting precisely specified resources, and waiting until resources are retrieved. :chatgpt-content-reference{index="0"} The model also includes the stated battery exceptions: 10% battery during collection causes return to the recharging station and reassignment, while 30% battery during delivery causes checkpoint return and reassignment, with alert/report escalation if checkpoint return fails. :chatgpt-content-reference{index="1"} Parallel collect-deliver tasks are modeled because the description explicitly allows multiple robots for items required from different storages. :chatgpt-content-reference{index="2"}

Leaf goals use `-` as runtime annotation, following the provided rule for leaf goal nodes. :chatgpt-content-reference{index="3"} Goal types follow the supplied definitions of Perform, Query, and Achieve goals. :chatgpt-content-reference{index="4"} Tasks are modeled as concrete operational steps with location and number of robots, as required. :chatgpt-content-reference{index="5"}
