# 5. Key Modeling Decisions

| Decision | Explanation |
|---|---|
| High-risk patients are modeled before remaining rooms | The mission imposes a strict first-15-minutes requirement, so this becomes an ordering constraint. |
| Patient identification is OR-decomposed | Asking the patient and scanning the barcode are alternatives; either is sufficient. |
| Availability retry is modeled as FALLBACK | The robot first checks availability, and only if unavailable does it return after 5 minutes. |
| Battery recovery is modeled as FALLBACK | The robot first checks battery; if insufficient, it recharges and tasks are reassigned. |
| Vital-sign failure handling is modeled as nested FALLBACK | The robot first tries to collect signs, then asks questions if collection fails, then alerts staff if there is no response. |
| Condition-specific checks are AND-decomposed | A patient may belong to multiple condition groups, and the mission requires all applicable checks. |
| Additional robots are fallback support | Extra robots are not the default; they are introduced only when the required time cannot be met. |
| Site-manager alert is final fallback | The manager is alerted only if no combination of robots can complete the mission. |

I kept the structure faithful to the source and used “fallback” only where the mission explicitly gives a first action and a recovery action.
