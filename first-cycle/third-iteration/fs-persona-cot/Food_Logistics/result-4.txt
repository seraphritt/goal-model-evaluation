# 5. Logical Relationships

**G1 → G2, G11 [AND] [sequential: `G2;G11`]**
**Justification:** In a complete meal-service cycle, the food first has to be delivered and dirty dishes are retrieved afterward. Both are mission obligations, so AND is appropriate.

**G2 → G3, G4 [AND] [sequential: `G3;G4`]**
**Justification:** The meal must first reach the inpatient room before it can be handed over.

**G3 → AT1, AT2 [AND] [sequential: `AT1;AT2`]**
**Justification:** The robot first takes the meal at the kitchen and then transports it to the inpatient room.

**G4 → G5, G6 [AND] [`FALLBACK(G5,G6)`]**
**Justification:** Direct placement on the room table is attempted when the required manipulation capability is available; tray cooperation provides the fallback delivery mechanism. The source establishes both mechanisms but not their priority. The priority therefore represents a design choice. Because FALLBACK is used, the supplied modeling rules require AND decomposition.

**G5 → AT3, AT4 [AND] [sequential: `AT3;AT4`]**
**Justification:** The robot has to position itself for table manipulation before actually placing the meal on the room table.

**G6 → G7, G8, G10 [AND] [sequential: `G7;G8;G10`]**
**Justification:** Tray delivery requires first determining possible support, then conducting the retrieval, and finally ensuring that the retrieval has been validated and traced.

**G8 → AT5, G9 [AND] [sequential: `AT5;G9`]**
**Justification:** Where the collaborator is a person, the correct meal must be identified before it is removed from a tray potentially containing several meals.

**G9 → AT6, AT7, AT8, AT9 [AND] [`FALLBACK(FALLBACK(FALLBACK(AT6,AT7),AT8),AT9)`]**
**Justification:** The description explicitly provides four possible collaborators. The fallback ordering prefers the inpatient, then an available companion, then a nurse, and finally another robot. This ordering is a resource-allocation design assumption rather than an ordering stated by the source.

**G10 → AT10, AT11, AT12 [AND] [`AT10;(AT11#AT12)`]**
**Justification:** The meal is first checked so a wrong retrieval can be detected and alerted. Recording the retrieval time and retrieval location are independent bookkeeping actions and can therefore be executed in parallel.

**G11 → G12, G13, G14 [AND] [sequential: `G12;G13;G14`]**
**Justification:** Information about potential door help can guide the access strategy; access must then be obtained before dishes can be retrieved.

**G13 → AT13, AT14 [AND] [`FALLBACK(AT13,AT14)`]**
**Justification:** A person may indicate that they can open the door. If human assistance is not possible, another robot can be used. Both possibilities are explicitly stated in the mission.

**G14 → AT15, AT16, AT17 [AND] [`FALLBACK(FALLBACK(AT15,AT16),AT17)`]**
**Justification:** Dirty-dish retrieval may be unassisted, robot-human cooperative, or two-robot cooperative. The chosen order first attempts the solution requiring the fewest additional resources.

## 6. Important modeling observation

There is **no unconditional OR branch** in this version because the alternatives for which execution order matters were represented with `FALLBACK`, and your specification explicitly says that fallback-related children are connected through **AND**, not OR. 

An alternative valid model could represent **table delivery vs. tray retrieval** and the different human/robot collaborators as pure **OR decompositions** if the intended semantics are “select exactly one feasible alternative without giving any alternative priority.” The source itself establishes those alternatives but does not prescribe the priority used above. 

The numbering above follows a depth-first traversal for both goals (`G1…G14`) and tasks (`AT1…AT17`), as required by the supplied goal/task definitions.
