## 1. Modeling rationale

The mission has a clear **normal sequence**: a robot receives a resource request, collects the required resources from storage, and then delivers them to the requesting agent at the specified location. The collection phase requires the robot to visit storage places, request the resource with precise specifications, and wait until the resource is retrieved before delivery begins. :chatgpt-content-reference{index="0"}

The battery-related behaviors are modeled as **fallbacks**, because the description explicitly defines normal behavior and then defines alternative behavior triggered by low-battery thresholds or failure conditions. In collection, low battery at 10% causes the robot to go to the recharging station and assign the mission to another robot. In delivery, low battery at 30% causes the robot to return the resource to a checkpoint and assign the remaining task to another robot. If checkpoint return fails, an alert and report are required. :chatgpt-content-reference{index="1"} This follows the provided definition that fallback is used for alternative behavior triggered by a condition, exception, failure, threshold, or interruption. :chatgpt-content-reference{index="2"}

Parallelism is modeled for multiple items from different storages, because the mission explicitly states that multiple robots can be assigned to parallel collect-deliver tasks to reduce completion time. :chatgpt-content-reference{index="3"}

Locations are restricted to terms that appear in the mission description: `storage_places`, `storage`, `specified_location`, `recharging_station`, and `checkpoint`. This follows the task-location instruction that locations should not be invented. :chatgpt-content-reference{index="4"}

## 5. Logical relationships

**G1 -> G2, G5 [AND][sequential: `G2;G5`]**  
- **Justification**: The mission must first be prepared, then executed. The robot needs the required resources, storage plan, and destination before collection and delivery can be performed. :chatgpt-content-reference{index="38"}

**G2 -> G3, G4 [AND][sequential: `G3;G4`]**  
- **Justification**: Request parameters must be known before the storage visit order and robot allocation can be planned.

**G3 -> AT1, AT2 [AND][sequential: `AT1;AT2`]**  
- **Justification**: Both required resources and delivery destination are necessary to define the mission.

**G4 -> AT3, AT4 [AND][sequential: `AT3;AT4`]**  
- **Justification**: The storage visit order is needed before assigning robots to the resulting collect-deliver work packages.

- **Justification**: Collection precedes delivery for each package, but multiple packages can be assigned to multiple robots in parallel when resources are required from different storages. :chatgpt-content-reference{index="39"}

**G6 -> G7, G8 [AND][fallback: `FALLBACK(G7,G8)`]**  
- **Justification**: Normal collection is pursued first. If the assigned robot reaches 10% battery during collection, collection is interrupted and reassigned. :chatgpt-content-reference{index="40"}

**G7 -> AT5, AT6, AT7, AT8 [AND][sequential: `AT5;AT6;AT7;AT8`]**

**G8 -> AT9, AT10 [AND][sequential: `AT9;AT10`]**  
- **Justification**: The robot first goes to the recharging station, then assigns the mission to another robot. :chatgpt-content-reference{index="42"}

**G9 -> G10, G11 [AND][fallback: `FALLBACK(G10,G11)`]**  
- **Justification**: Normal delivery is attempted first. If the delivery-phase battery threshold is reached, checkpoint handoff is required. :chatgpt-content-reference{index="43"}

**G10 -> AT11, AT12 [AND][sequential: `AT11;AT12`]**  
- **Justification**: Resources must be transported to the specified location and delivered to the requesting agent. :chatgpt-content-reference{index="44"}

**G11 -> G12, G13 [AND][fallback: `FALLBACK(G12,G13)`]**  
- **Justification**: Checkpoint handoff is the first recovery behavior. Alert/report is only triggered if returning the resource to a checkpoint fails. :chatgpt-content-reference{index="45"}

**G12 -> AT13, AT14, AT15 [AND][sequential: `AT13;AT14;AT15`]**
