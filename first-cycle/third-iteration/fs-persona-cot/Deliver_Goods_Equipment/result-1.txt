# 4. Logical Relationships

* **G1 -> G2, G7, G15 [AND][sequential: `G2;G7;G15`]**

  * **Justification:** The mission cannot be completed unless the request is prepared, the resources are collected, and the resources are delivered. The phases are sequential because delivery begins only once resources are retrieved.

* **G2 -> G3, G4 [AND][sequential: `G3;G4`]**

  * **Justification:** The system must first know what resources, specifications, agent, and location are involved before deciding how many robots to assign.

* **G3 -> AT1 [AND]**

  * **Justification:** Acquiring request data is operationalized by reading or receiving the request information.

* **G4 -> G5, G6 [OR][fallback: `FALLBACK(G5,G6)`]**

  * **Justification:** One robot is sufficient for the basic mission, but if multiple items from different storages are required, multiple robots can be assigned to reduce total mission time.

* **G5 -> AT2 [AND]**

  * **Justification:** Assigning one robot directly satisfies the single-robot strategy.

* **G6 -> AT3 [AND][parallel: `#`]**

  * **Justification:** Multiple robots can execute collect-deliver subtasks in parallel when different storages are involved.

* **G7 -> G8, G9, G12 [AND][sequential/fallback: `G8;FALLBACK(G9,G12)`]**

  * **Justification:** Storage prioritization must occur before retrieval. Normal retrieval is attempted first, but low battery during collection activates recovery.

* **G8 -> AT4, AT5 [AND][sequential: `AT4;AT5`]**

  * **Justification:** Waiting times and paths must be estimated before the storage order can be computed.

* **G9 -> G10, G11 [AND][sequential: `G10;G11`]**

  * **Justification:** The robot must first reach storage before sending the resource request and waiting for retrieval.

* **G10 -> AT6 [AND]**

  * **Justification:** Navigating to storage operationalizes the goal of reaching the storage places.

* **G11 -> AT7, AT8 [AND][sequential: `AT7;AT8`]**

  * **Justification:** The robot sends the resource request message first, then waits for storage to retrieve the resources.

* **G12 -> G13, G14 [AND][sequential: `G13;G14`]**

  * **Justification:** During collection, when battery reaches 10%, the robot returns to the recharging station and the mission is assigned to another robot.

* **G13 -> AT9 [AND]**

  * **Justification:** Returning to the recharging station operationalizes the recharge recovery goal.

* **G14 -> AT10 [AND]**

  * **Justification:** Transferring the collection mission operationalizes reassignment to another robot.

* **G15 -> G16, G20 [AND][fallback: `FALLBACK(G16,G20)`]**

  * **Justification:** Normal delivery is attempted first. If battery becomes low during delivery, checkpoint handover and reassignment are required.

* **G16 -> G17, G18 [AND][sequential: `G17;G18`]**

  * **Justification:** The robot transports resources to the destination and repeats runs until all resources are delivered.

* **G17 -> AT11 [AND]**

  * **Justification:** Carrying resources to the specified location directly operationalizes transport.

* **G18 -> AT12 [AND]**

  * **Justification:** Additional runs are necessary when one run is insufficient to deliver all resources.

* **G20 -> G21, G22, G23 [AND][fallback: `FALLBACK(G21;G22,G23)`]**

  * **Justification:** The robot first attempts to return the resource to a checkpoint and reassign the remaining task. If checkpoint return fails, alert and reporting actions are triggered.

* **G21 -> AT13 [AND]**

  * **Justification:** Placing the resource at the checkpoint satisfies the checkpoint-return requirement.

* **G22 -> AT14, AT15 [AND][sequential: `AT14;AT15`]**

  * **Justification:** The replacement robot must know where the resource is positioned before taking over the remaining delivery task.

* **G23 -> AT16, AT17 [AND][sequential: `AT16;AT17`]**

  * **Justification:** Failure to return the resource to the checkpoint requires both an alert and a report to the sector manager.
