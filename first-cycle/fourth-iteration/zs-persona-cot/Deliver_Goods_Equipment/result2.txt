# 6. Logical relationships

**G1 -> G2, G6 [AND][sequential: `G2;G6`]**
**Justification:** The mission must first identify what must be collected and where it must be delivered, then execute the collect-deliver strategy.

**G2 -> G3, G4, G5 [AND][sequential: `G3;G4;G5`]**
**Justification:** The robot must know the requested resources and destination, then the storage sources, then the order based on waiting time plus path.

**G3 -> AT1 [AND]**
**Justification:** Identifying request details is operationalized by reading the request information.

**G4 -> AT2 [AND]**
**Justification:** Identifying storage sources requires querying or determining the storage places where resources can be found.

**G5 -> AT3 [AND]**
**Justification:** The storage order must be computed using the mission’s rule: waiting time estimate plus path cost.

**G6 -> G20, G7 [AND][fallback: `FALLBACK(G20,G7)`]**
**Justification:** When multiple items from different storages exist and multiple robots are available, the parallel strategy is preferable to reduce time. If that strategy is not applicable, the single-robot strategy still fulfills the mission.

**G7 -> G8, G13 [AND][sequential: `G8;G13`]**
**Justification:** Collection must happen before delivery because the delivery phase begins once resources are retrieved.

**G8 -> G9, G12 [AND][fallback: `FALLBACK(G9,G12)`]**
**Justification:** Normal collection is attempted first. If battery reaches 10% during collection, the robot must return to recharge and reassign the mission.

**G9 -> G10, G11 [AND][sequential: `G10;G11`]**
**Justification:** The robot must first reach the storage, then request and wait for the resources.

**G10 -> AT4 [AND]**
**Justification:** Reaching storage is performed by navigation to storage places.

**G11 -> AT5, AT6 [AND][sequential: `AT5;AT6`]**
**Justification:** The robot sends the precise request message and then waits until retrieval is complete.

**G12 -> AT7, AT8 [AND][sequential: `AT7;AT8`]**
**Justification:** The robot first returns to the recharging station, then assigns the mission to another robot.

**G13 -> G14, G15 [AND][fallback: `FALLBACK(G14,G15)`]**
**Justification:** Normal delivery is attempted first. If the battery reaches 30%, the delivery low-battery procedure must be executed.

**G14 -> AT9 [AND]**
**Justification:** Normal delivery is operationalized by making as many runs as necessary to deliver all resources.

**G15 -> G16, G19 [AND][fallback: `FALLBACK(G16,G19)`]**
**Justification:** The robot first attempts checkpoint handoff. If returning the resource to checkpoint fails, alert and reporting actions are required.

**G16 -> AT10, AT11 [AND][sequential: `AT10;AT11`]**
**Justification:** The resource must first be returned to a checkpoint, then the remaining task must be assigned to another robot with resource-position knowledge.

**G19 -> AT12, AT13 [AND][sequential: `AT12;AT13`]**
**Justification:** In checkpoint-return failure, both an alert and a sector-manager report are required.

**G20 -> G21, G25 [AND][parallel: `G21#G25`]**
**Justification:** Multiple robots can execute collect-deliver tasks in parallel when multiple items are required from different storages.

**G21 -> G22, G23 [AND][sequential: `G22;G23`]**
**Justification:** Each parallel branch remains a collect-deliver task: collect first, deliver second.

**G22 -> AT14, AT15 [AND][sequential: `AT14;AT15`]**
**Justification:** Branch A must navigate to storage, request the resources, and wait for retrieval.

**G23 -> AT16 [AND]**
**Justification:** Branch A is complete only when its resources are delivered to the specified location.

**G25 -> G26, G27 [AND][sequential: `G26;G27`]**
**Justification:** Branch B follows the same collect-then-deliver structure for another storage/resource subset.

**G26 -> AT17, AT18 [AND][sequential: `AT17;AT18`]**
**Justification:** Branch B must navigate to its storage, request resources, and wait for retrieval.

**G27 -> AT19 [AND]**
**Justification:** Branch B is complete only when its assigned resources are delivered.
