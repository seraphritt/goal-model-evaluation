## 1. Modeling rationale

The mission’s top-level intention is: **every two hours, all occupied patient rooms must be visited and the required vital signs must be checked**. The description adds constraints about availability, battery, patient identification, condition-specific vital signs, failure handling, sterilization, actuator disinfection, high-risk priority, adding robots, and alerting the site manager if no robot combination can finish the mission. Texto colado

Key modeling choices:

| Mission statement | Modeling decision |
|---|---|
| “Every two hours, all patient's vital signs should be checked.” | Root goal is an **Achieve Goal**, because the system must reach the state where all required checks are completed within the periodic mission. |
| “The assigned robot should visit every occupied room.” | Visiting occupied rooms is modeled as an **AND** requirement under mission execution. |
| “Before entering the room, the robot must check if the patient is available... and if there is enough battery...” | Availability and battery readiness are both required, so they are modeled as **AND**. |
| “If the patient is not available, the robot should come back in 5 minutes.” | This is modeled with **FALLBACK**, because the mission explicitly defines what happens if the first attempt fails. |
| “If there is not enough battery, the robot should recharge and the tasks need to be reassigned.” | This is modeled with **FALLBACK** from battery sufficiency to recharge/reassignment. |
| “Identify the correct patient either by asking or by scanning the patients barcode.” | This is modeled as **OR**, because either identification method is sufficient and no priority order is given. |
| “Failure of collecting any necessary vital signs should trigger a set of questions...” | Collection failure triggers a fallback to assessment questions. |
| “In case of non-response, an alert should be sent...” | Non-response triggers fallback to alerting the nurse/doctor. |
| “Additional robots can be assigned... The responsible manager... must be alerted if no combination of robots can complete the mission.” | Mission completion uses nested **FALLBACK**: assigned robots first, additional robots second, manager alert last. |

# 5. Logical relationships and justifications

- **G1 -> G2, G25, G26 [AND][FALLBACK(FALLBACK(G2,G25),G26)]**  
  **Justification:** The mission is first attempted with the assigned robot set. If that cannot satisfy the required time, additional robots can be assigned. If no combination of robots can complete the mission, the manager must be alerted.

- **G2 -> G3, G6, G10 [AND][sequential]**  
  **Justification:** The robot must first know which rooms and patients are involved, then prioritize high-risk patients, then complete the remaining occupied-room checks.

- **G3 -> AT1, AT2 [AND][parallel]**  
  **Justification:** Occupied rooms and patient categories are both required mission inputs and can be obtained independently.

- **G6 -> AT3, G7 [AND][sequential]**  
  **Justification:** The mission route must first prioritize high-risk patients, then execute checks for those patients within the first 15 minutes.

- **G8 -> G8.1, G8.2, G8.3 [AND][availability and battery in parallel, identification after readiness]**  
  **Justification:** Availability and battery are both pre-entry checks. Patient identity must also be confirmed before performing procedures.

- **G8.1 -> AT4, AT5 [AND][FALLBACK(AT4,AT5)]**  
  **Justification:** The patient is checked for availability first. If unavailable, the robot returns in 5 minutes.

- **G8.2 -> AT6, AT7, AT8 [AND][FALLBACK(AT6,(AT7;AT8))]**  
  **Justification:** Battery sufficiency is attempted first. If the robot does not have enough battery, it recharges and the tasks are reassigned.

- **G8.3 -> AT9, AT10 [OR][parallel/no priority]**  
  **Justification:** Asking the patient and scanning the barcode are alternatives. Either one is sufficient, and no required order is stated.

- **G9.2 -> AT16, G9.3 [AND][FALLBACK(AT16,G9.3)]**  
  **Justification:** The robot first attempts to collect required vital signs. If collection fails, it must perform failure handling.

- **G9.3 -> AT17, AT18 [AND][FALLBACK(AT17,AT18)]**  
  **Justification:** The robot first asks assessment questions. If the patient does not respond, it alerts the responsible nurse or doctor.

- **G10 -> G11, G15, G22 [AND][sequential]**  
  **Justification:** For every occupied room, the robot must prepare entry, interact with the patient, and close the visit safely before proceeding.

- **G11 -> G12, G13, G14 [AND][availability and battery in parallel, identification after readiness]**  
  **Justification:** The robot must check both patient availability and battery before entering, then identify the correct patient.

- **G12 -> AT19, AT20 [AND][FALLBACK(AT19,AT20)]**  
  **Justification:** If the patient is not available, the robot comes back after 5 minutes.

- **G13 -> AT21, AT22, AT23 [AND][FALLBACK(AT21,(AT22;AT23))]**  
  **Justification:** If battery is insufficient, the robot recharges and tasks are reassigned.

- **G14 -> AT24, AT25 [OR][parallel/no priority]**  
  **Justification:** The correct patient may be identified either by asking or by scanning the barcode.

- **G15 -> AT26, AT27, AT28 [AND][sequential]**  
  **Justification:** The robot must approach the patient, announce the procedure, and provide instructions in that order.

- **G16 -> G17, G18, G19 [AND][parallel]**  
  **Justification:** The robot must determine all applicable vital-sign requirements because a patient may satisfy more than one medical category.

- **G20 -> AT32, G21 [AND][FALLBACK(AT32,G21)]**  
  **Justification:** Vital-sign collection is attempted first. If any necessary sign cannot be collected, the robot must assess the patient through questions.

- **G21 -> AT33, AT34 [AND][FALLBACK(AT33,AT34)]**  
  **Justification:** If the patient does not respond to assessment questions, the robot must alert the responsible nurse or doctor.

- **G22 -> AT35, G23, G24, AT40 [AND][sequential with conditional hygiene in parallel]**  
  **Justification:** After checking the patient, the robot marks the patient as done, performs any required hygiene actions, and proceeds to the next room.

- **G23 -> AT36, AT37 [AND][sequential]**  
  **Justification:** The robot must detect that it exited an infectious-disease room and then sterilize itself.

- **G24 -> AT38, AT39 [AND][sequential]**  
  **Justification:** The robot must determine whether patient contact occurred and then disinfect its actuators if contact duties were performed.

- **G25 -> AT41, G2 [AND][sequential]**  
  **Justification:** Additional robots are assigned first, and then the mission execution is retried with the expanded robot set.

- **G26 -> AT42 [AND][single task]**  
  **Justification:** If no combination of robots can complete the mission, the required operational response is to alert the responsible site manager.
