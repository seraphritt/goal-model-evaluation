## 1. Main modeling rationale

The mission’s top-level objective is an **Achieve Goal** because the system must reach a final state: all required vital signs for all relevant patients are checked within the required periodic mission window. The phrase “Every two hours, all patient's vital signs should be checked” indicates a target state, not merely an action attempt. Texto colado

The model uses:

**AND decompositions** when all child elements are required, such as checking availability, checking battery, identifying the patient, collecting required signs, and finalizing the patient check.

**OR decompositions** when the mission gives alternatives, especially patient identification “either by asking or by scanning the patients barcode.” Texto colado

**FALLBACK runtime annotations** only where the description explicitly gives a primary attempt and a secondary action after failure, such as battery insufficiency leading to recharge and reassignment, non-response leading to an alert, and robot-team infeasibility leading to additional robots or manager alert. The provided instructions state that fallback should be used only when the order is explicitly defined. Texto colado

# 5. Logical relationships and justifications

- **G1 -> G2, G3, G7 [AND][sequential: `G2;G3;G7`]**  
  **Justification:** The mission must first know what rooms and patient categories exist, then ensure that the robot team can perform the mission, and finally execute the room checks.

- **G2 -> AT1, AT2, AT3, AT4 [AND]**  
  **Justification:** The robot must visit every occupied room, prioritize high-risk patients, and know condition-specific vital-sign requirements.

- **G3 -> G4, G5, G6 [AND][fallback: `FALLBACK(FALLBACK(G4,G5),G6)`]**  
  **Justification:** The primary assumption is the assigned robot. If the mission cannot be performed in time, additional robots may be assigned. If no robot combination works, the manager must be alerted.

- **G7 -> G8, G9 [AND][sequential: `G8;G9`]**  
  **Justification:** High-risk patients must be checked in the first 15 minutes, so priority enforcement precedes completion of the general occupied-room monitoring cycle.

- **G9 -> G10, G20, G29 [AND][sequential: `G10;G20;G29`]**  
  **Justification:** For each room, the robot must first satisfy entry readiness, then perform the in-room procedure, and only afterward mark completion and perform hygiene.

- **G10 -> G11, G14, G17 [AND][mixed: `(G11#G14);G17`]**  
  **Justification:** Availability and battery checks are both required before entering the room and may be checked independently; patient identification is then required because rooms may have multiple beds.

- **G11 -> G12, G13 [AND][fallback: `FALLBACK(G12,G13)`]**  
  **Justification:** The robot first checks availability. If the patient is unavailable, the described recovery action is to come back in 5 minutes.

- **G14 -> G15, G16 [AND][fallback: `FALLBACK(G15,G16)`]**  
  **Justification:** The robot first checks battery sufficiency. If battery is insufficient, it must recharge and the tasks must be reassigned.

- **G17 -> G18, G19 [OR][unordered alternatives: `G18#G19`]**  
  **Justification:** The mission says the robot identifies the correct patient either by asking or by scanning the patient barcode. One successful identification method is sufficient.

- **G20 -> G21, G22, G26 [AND][sequential: `G21;G22;G26`]**  
  **Justification:** The robot should approach, announce, and instruct before collection. Failure handling only becomes relevant after a collection attempt.

- **G22 -> G23, G24, G25 [AND][parallel/condition-based: `G23#G24#G25`]**  
  **Justification:** These are condition-specific requirements. If a patient belongs to more than one category, all applicable checks are required. No sequence among these categories is specified.

- **G23 -> AT20, AT21, AT22, AT23 [AND]**  
  **Justification:** Infectious-disease patients must be checked for heart rate, blood pressure, body temperature, and blood oxygenation.

- **G24 -> AT24, AT25 [AND]**  
  **Justification:** Post-surgical patients must be checked for heart rate and blood oxygenation.

- **G25 -> AT26 [AND]**  
  **Justification:** Diabetes-history patients must be checked for blood glucose.

- **G26 -> G27, G28 [AND][fallback: `FALLBACK(G27,G28)`]**  
  **Justification:** The robot first asks questions to assess status when vital-sign collection fails. If there is non-response, it alerts the responsible nurse or doctor.

- **G29 -> G30, G31, G32 [AND][sequential/parallel: `G30;(G31#G32)`]**  
  **Justification:** The patient is first marked done and the robot proceeds. Sterilization and actuator disinfection are then applied when their triggering conditions hold.

- **G30 -> AT29, AT30 [AND]**  
  **Justification:** The patient must be marked as done and the robot must proceed to the next room.

- **G31 -> AT31 [AND, conditional]**  
  **Justification:** Sterilization is required after exiting a room treating an infectious-disease patient.

- **G32 -> AT32 [AND, conditional]**  
  **Justification:** Actuator disinfection is required after duties involving patient contact.
