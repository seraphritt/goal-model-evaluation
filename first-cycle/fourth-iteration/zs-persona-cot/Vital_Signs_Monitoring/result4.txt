## Modeling notes

I interpret the root mission as an **Achieve Goal**, because the robot team must reach a target state: all relevant patients in occupied rooms have been checked within the two-hour cycle, high-risk patients have been checked in the first 15 minutes, and required alerts/safety actions have been handled. The mission explicitly says that vital signs must be checked every two hours, every occupied room must be visited, high-risk patients must be checked first, extra robots may be assigned if needed, and the site manager must be alerted if no robot combination can complete the mission. Texto colado

I use **FALLBACK** only where the description gives an explicit “try this, otherwise do that” structure: patient unavailable → come back in 5 minutes; insufficient battery → recharge and reassign; vital-sign collection failure → ask questions; non-response → alert nurse/doctor; infeasible assigned robot → add robots; no feasible robot combination → alert manager. Texto colado

`n` means the maximum number of robots available to the mission. `[1,n]` is used only where the description supports possible multi-robot execution through additional robot assignment. Texto colado

# 4. Logical relationships and justifications

- **G1 → G2, G6 [AND][sequential `G2;G6`]**  
  **Justification:** The mission must first be feasible in terms of robot assignment before the actual patient-checking workflow can be executed.

- **G2 → G3, G4, G5 [AND][`FALLBACK(G3,FALLBACK(G4,G5))`]**  
  **Justification:** The assigned robot is the initial performer. If the mission cannot be completed in time, additional robots can be assigned. If no robot combination works, the manager must be alerted. Texto colado

- **G3 → AT1, AT2 [AND][sequential `AT1;AT2`]**  
  **Justification:** The system must estimate whether the assigned robot can complete the mission before confirming its plan.

- **G4 → AT3, AT4 [AND][sequential `AT3;AT4`]**  
  **Justification:** Extra robots must first be selected before rooms and tasks can be distributed among them.

- **G5 → AT5, AT6 [AND][sequential `AT5;AT6`]**  
  **Justification:** The manager alert is justified only after determining that no robot combination can complete the mission.

- **G6 → G7, G8 [AND][sequential `G7;G8`]**  
  **Justification:** The high-risk timing constraint must influence the execution order of the room-checking workflow.

- **G7 → AT7, AT8 [AND][sequential `AT7;AT8`]**  
  **Justification:** High-risk patients must be identified before they can be placed at the beginning of the mission plan.

- **G8 → G9, G10, G15, G16, G17, G18, G22, G25 [AND][sequential]**  
  **Justification:** For each occupied room, the robot must visit the room, check pre-entry conditions, identify the patient, prepare the procedure, determine required measurements, collect them, perform safety actions, mark done, and proceed.

- **G10 → G11, G12, G13, G14 [AND][`FALLBACK(G11,G12)#FALLBACK(G13,G14)`]**  
  **Justification:** Patient availability and battery sufficiency are both required before entry. If the patient is unavailable, the robot returns in 5 minutes. If battery is insufficient, the robot recharges and tasks are reassigned. Texto colado

- **G15 → AT19, AT20 [OR][parallel/alternative `AT19#AT20`]**  
  **Justification:** The description explicitly gives two alternative identification methods: asking the patient or scanning the barcode. One is sufficient. Texto colado

- **G16 → AT21, AT22, AT23, AT24 [AND][sequential]**  
  **Justification:** Once inside the room, the robot must approach the patient, announce the procedure, and provide instructions.

- **G17 → AT25, AT26, AT27 [AND][parallel `AT25#AT26#AT27`]**  
  **Justification:** These condition checks determine which vital signs are required. A patient may match multiple categories, so the model should not treat them as mutually exclusive.

- **G18 → G19, G20, G21 [AND][parallel/conditional `G19#G20#G21`]**  
  **Justification:** Infectious-disease, post-surgical, and diabetes-related checks are condition-dependent. If several conditions apply, all applicable checks must be completed.

- **G19 → AT28, AT29, AT30, AT31, AT32, AT33 [AND][`FALLBACK((AT28#AT29#AT30#AT31),FALLBACK(AT32,AT33))`]**  
  **Justification:** Infectious-disease patients require heart rate, blood pressure, body temperature, and blood oxygenation. Failed collection triggers assessment questions; non-response triggers nurse/doctor alert.

- **G20 → AT34, AT35, AT36, AT37 [AND][`FALLBACK((AT34#AT35),FALLBACK(AT36,AT37))`]**  
  **Justification:** Post-surgical patients require heart rate and blood oxygenation, with the same failure-response rule.

- **G21 → AT38, AT39, AT40 [AND][`FALLBACK(AT38,FALLBACK(AT39,AT40))`]**  
  **Justification:** Diabetes history requires blood glucose checking. If glucose collection fails, the robot asks questions; if there is no response, it alerts the nurse/doctor.

- **G22 → G23, G24 [AND][parallel/conditional `G23#G24`]**  
  **Justification:** After the room procedure, infectious-room sterilization and patient-contact actuator disinfection are both mandatory when their conditions apply.

- **G23 → AT41, AT42 [AND][sequential `AT41;AT42`]**  
  **Justification:** The robot must first come out of the infectious-disease room and then be sterilized.

- **G24 → AT43, AT44 [AND][sequential `AT43;AT44`]**  
  **Justification:** The system must know that patient contact occurred before disinfecting the actuators.

- **G25 → AT45, AT46 [AND][sequential `AT45;AT46`]**  
  **Justification:** Once the patient is checked, the robot marks the patient as done and proceeds to the next room, exactly as stated in the mission description. Texto colado
