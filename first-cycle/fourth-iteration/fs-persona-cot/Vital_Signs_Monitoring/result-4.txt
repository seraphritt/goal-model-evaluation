## Design rationale

The root objective is modeled as an **Achieve Goal** because the mission has a desired final state: all required patient checks are completed within the periodic mission constraints. Query goals are used only where the robot/system must obtain information, such as occupied rooms, patient condition, availability, battery, or patient identity. Perform goals/tasks are used for concrete actions such as visiting rooms, announcing procedures, collecting measurements, disinfecting actuators, sterilizing the robot, and sending alerts.

Fallback is used only where the mission explicitly defines a failure-contingency sequence: if the patient is unavailable, return in five minutes; if battery is insufficient, recharge and reassign; if collection fails, ask questions; if there is non-response, alert the nurse/doctor; if the mission cannot be completed in time, use additional robots, and if no combination works, alert the site manager.
