# Multi-Robot Goal Model: Hospital Vital-Signs Checking Mission

## 1. Modeling Basis and Design Rationale

The mission is modeled as a periodic hospital mission in which vital signs must be checked every two hours. The assigned robot must visit every occupied room, verify patient availability and battery before entering, identify the correct patient, perform the required vital-sign procedure, handle failures, apply hygiene rules, and proceed to the next room. The description also introduces timing constraints for high-risk patients, condition-specific vital signs, additional robot assignment, and escalation if no robot combination can complete the mission. :chatgpt-content-reference{index="2"}

The model follows the provided definitions: a goal model is a hierarchical tree of goals, sub-goals, and tasks using AND/OR decompositions; goals may be Perform, Query, or Achieve goals; and tasks must include operational information such as location and number of robots. :chatgpt-content-reference{index="3"} :chatgpt-content-reference{index="4"} :chatgpt-content-reference{index="5"}

### Main modeling decisions

1. **Root mission goal as Achieve Goal**  
   The root goal is an Achieve goal because the mission has a target state: all required vital signs of all occupied-room patients are checked within the periodic mission cycle.

2. **Mission scope as Query Goals**  
   Occupied rooms, patient risk level, patient condition, availability, battery sufficiency, and identity are modeled as Query goals because they retrieve information needed to decide what the robot should do.

3. **Robot allocation as fallback**  
   The mission first tries the assigned robot. If that is impossible, additional robots and reassignment are used. If no combination of robots can complete the mission, the responsible manager is alerted. This is modeled with nested `FALLBACK(...)` because the mission explicitly defines the order of recovery actions.

4. **Patient identification as OR decomposition**  
   The patient can be identified either by asking or by scanning the barcode. Since the mission does not specify that one must be attempted before the other, this is an OR decomposition, not a fallback.

5. **Failed vital-sign collection as fallback**  
   The robot first attempts to collect the required vital sign. If collection fails, it asks assessment questions. If the patient does not respond, it alerts the responsible nurse or doctor. This is modeled as fallback because the mission explicitly defines the recovery order.

6. **Hygiene actions as conditional AND goals**  
   Sterilization and actuator disinfection are modeled as required post-room goals when their conditions hold: infectious-disease room exit and patient contact, respectively.
