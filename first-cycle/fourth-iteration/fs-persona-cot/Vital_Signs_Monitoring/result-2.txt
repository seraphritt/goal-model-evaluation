Below is a goal-model decomposition grounded in the supplied mission description and definitions. I use AND when all children are jointly required, OR when the mission gives alternatives such as “asking or scanning,” and FALLBACK only where the description gives an explicit contingency, such as retrying after patient unavailability, recharging/reassignment after low battery, alerting after non-response, or alerting the manager when no robot combination can complete the mission. The source defines a goal model as a hierarchical decomposition of goals into sub-goals/tasks using AND/OR relations, with runtime annotations for sequential, parallel, and fallback execution. ## 1. Main modeling assumptions

| Assumption | Modeling decision |
|---|---|
| “Every two hours” | Modeled as the temporal target of the root mission goal: all required patient checks must be completed in each two-hour cycle. |
| “Assigned robot” | Default number of robots is 1 for patient-room tasks. |
| “Additional robots can be assigned” | Modeled as a fallback from the assigned-robot allocation to an expanded robot team. |
| “If no combination of robots can complete the mission” | Modeled as the final fallback: alert the responsible site manager. |
| Clinical categories | Infectious disease, post-surgical, and diabetes are modeled as conditions that determine which vital signs must be collected. |
| High-risk patients | Modeled as a priority goal that must be achieved in the first 15 minutes before the remaining room sequence proceeds. |

The mission states that robots must visit occupied rooms, check patient availability and battery before entry, identify the correct patient by asking or barcode scanning, perform condition-specific vital-sign checks, handle failures and non-response, decontaminate when required, and escalate infeasible missions. # 5. Logical relationships and justifications

**G1 -> G2, G27 [AND][FALLBACK(G2,G27)]**  
**Justification:** The mission should first be completed. If no robot combination can complete it, the responsible site manager must be alerted. This is a fallback, not an OR, because alerting the manager is only triggered by mission infeasibility.

**G2 -> G3, G6, G9 [AND][sequential]**  
**Justification:** A feasible robot allocation must exist before the mission scope is executed. Scope and priority information must be known before checking patients.

**G3 -> G4, G5 [AND][FALLBACK(G4,G5)]**  
**Justification:** The assigned robot is the initial plan. Additional robots are assigned only when the mission cannot be performed in the required time.

**G4 -> AT1 [AND]**  
**Justification:** Confirming assigned-robot feasibility is operationalized by evaluating whether the assigned robot can complete the mission.

**G5 -> AT2, AT3 [AND][sequential]**  
**Justification:** Additional robots must be assigned, and then tasks must be reassigned among them.

**G6 -> G7, G8 [AND][parallel]**  
**Justification:** The occupied-room list and patient classifications are both required mission data. They can be obtained independently as information-gathering goals.

**G7 -> AT4 [AND]**  
**Justification:** The only concrete operation needed for this query goal is retrieving occupied rooms.

**G8 -> AT5, AT6 [AND][parallel]**  
**Justification:** High-risk status and clinical condition are both needed because they affect timing and required vital signs.

**G9 -> G10, G11 [AND][sequential]**  
**Justification:** High-risk patients must be checked first, and then the full room-check workflow is applied to occupied rooms.

**G10 -> AT7, AT8 [AND][sequential]**  
**Justification:** The robot first prioritizes high-risk patients, then visits them first.

**G11 -> G12, G15, G16, G17, G20, G23 [AND][sequential]**  
**Justification:** The room workflow follows the mission order: pre-entry checks, identification, patient preparation, vital-sign collection, failure handling if needed, and closeout.

**G12 -> G13, G14 [AND][sequential]**  
**Justification:** Before entering, the robot must check both patient availability and battery sufficiency.

**G13 -> AT9, AT10 [AND][FALLBACK(AT9,AT10)]**  
**Justification:** The robot checks availability first. If the patient is not available, it returns in 5 minutes.

**G14 -> AT11, AT12, AT13 [AND][FALLBACK(AT11,(AT12#AT13))]**  
**Justification:** The robot checks battery first. If there is not enough battery, it recharges and tasks are reassigned.

**G15 -> AT14, AT15 [OR][alternative]**  
**Justification:** The description explicitly says the robot can identify the correct patient either by asking or by scanning the patient barcode. One successful identification method is sufficient.

**G16 -> AT16, AT17, AT18 [AND][sequential]**  
**Justification:** Once inside the room, the robot approaches the patient, announces the procedure, and provides instructions.

**G17 -> G18, G19 [AND][sequential]**  
**Justification:** The robot must determine which signs are required before measuring them.

**G18 -> AT19 [AND]**  
**Justification:** The concrete task is mapping the patient’s condition to required vital signs.

**G19 -> AT20, AT21, AT22, AT23, AT24 [AND][parallel where applicable]**  
**Justification:** Required vital signs are complementary. The applicable subset depends on the patient’s condition: infectious disease requires heart rate, blood pressure, temperature, and blood oxygenation; post-surgical requires heart rate and blood oxygenation; diabetes history requires blood glucose.

**G20 -> G21, G22 [AND][FALLBACK(G21,G22)]**  
**Justification:** If collection fails, the robot asks assessment questions first. If there is non-response, it alerts the nurse/doctor.

**G21 -> AT25 [AND]**  
**Justification:** Asking assessment questions is the concrete operation for failed vital-sign collection.

**G22 -> AT26 [AND]**  
**Justification:** Sending the nurse/doctor alert is the concrete operation for non-response.

**G23 -> G24, G25, G26 [AND][sequential]**  
**Justification:** The patient is marked done, required decontamination is performed, and the robot proceeds to the next room.

**G24 -> AT27 [AND]**  
**Justification:** Marking the patient as done is explicitly required after the patient is checked.

**G25 -> AT28, AT29 [AND][parallel where applicable]**  
**Justification:** Sterilization is required after leaving infectious-disease rooms, and actuator disinfection is required after patient-contact duties. These are distinct hygiene requirements and both apply when their conditions hold.

**G26 -> AT30 [AND]**  
**Justification:** Proceeding to the next room is the operational action after completing the current room.

**G27 -> AT31 [AND]**  
**Justification:** Alerting the site manager is the required action when no combination of robots can complete the mission.
