## Design rationale summary

The root mission is to **complete periodic vital-sign checking for all occupied rooms every two hours**, while respecting patient availability, battery constraints, patient identification, special medical-condition requirements, hygiene requirements, high-risk priority, and infeasibility escalation. The main mission behavior comes from the statement that the robot must visit every occupied room, check availability and battery before entering, identify the correct patient, collect condition-dependent vital signs, handle failures through questions and alerts, mark patients as done, sterilize/disinfect when required, and escalate if no robot combination can finish on time. - **G7 -> G8, G9, G10 [AND][FALLBACK(G8,FALLBACK(G9,G10))]**  
  **Justification:** The primary plan is to use the assigned robot. If that cannot meet time requirements, additional robots are assigned. If no robot combination works, the manager is alerted.

- **G8 -> AT8 [AND]**  
  **Justification:** Assigning the initial robot operationalizes the mission’s “assigned robot” requirement.

- **G9 -> AT9, AT10 [AND][sequential]**  
  **Justification:** Helper robots must first be assigned, then tasks redistributed among them.

- **G10 -> AT11 [AND]**  
  **Justification:** Alerting the responsible manager is the required action when no robot combination can complete the mission.

- **G3 -> G11, G12 [AND][sequential]**  
  **Justification:** High-risk patients must be checked in the first 15 minutes, so prioritization precedes general room processing.

- **G11 -> AT12 [AND]**  
  **Justification:** Scheduling high-risk patients first is the operational way to satisfy the first-15-minutes constraint.

- **G12 -> G13, G20, G23, G48, G49 [AND][sequential]**  
  **Justification:** For each room, the robot checks preconditions, identifies the patient, conducts the procedure, completes the record, and performs required hygiene.

- **G13 -> G14, G17 [AND][parallel]**  
  **Justification:** Patient availability and battery sufficiency are both pre-entry requirements, and no order is specified.

- **G14 -> G15, G16 [AND][FALLBACK(G15,G16)]**  
  **Justification:** The robot first checks availability. If the patient is unavailable, it comes back in five minutes.

- **G15 -> AT13 [AND]**  
  **Justification:** Availability checking is a query task before entering the room.

- **G16 -> AT14, AT15 [AND][sequential]**  
  **Justification:** The robot must wait five minutes and then return.

- **G17 -> G18, G19 [AND][FALLBACK(G18,G19)]**  
  **Justification:** The robot first checks battery sufficiency. If battery is insufficient, it recharges and tasks are reassigned.

- **G18 -> AT16 [AND]**  
  **Justification:** Battery sufficiency is queried before entering the room.

- **G19 -> AT17, AT18 [AND][sequential]**  
  **Justification:** The robot must recharge, and then affected tasks must be reassigned.

- **G20 -> G21, G22 [OR][parallel/unordered alternatives]**  
  **Justification:** The correct patient can be identified either by asking or by scanning the patient barcode. Since no priority order is given, this is OR, not fallback.

- **G21 -> AT19 [OR]**  
  **Justification:** Asking is one valid identification method.

- **G22 -> AT20 [OR]**  
  **Justification:** Barcode scanning is another valid identification method.

- **G23 -> G24, G25 [AND][sequential]**  
  **Justification:** The robot must prepare the patient before or during the procedure and then perform the required checks.

- **G24 -> AT21, AT22, AT23 [AND][sequential]**  
  **Justification:** The mission lists approaching, announcing, and instructing as required patient-interaction actions.

- **G25 -> G26, G27 [AND][sequential]**  
  **Justification:** The robot must determine which signs are required before collecting them.

- **G26 -> AT24 [AND]**

- **G27 -> G28, G32, G36, G40, G44 [AND][parallel]**  
  **Justification:** All applicable vital signs must be handled. They are modeled as parallel-capable because signs are independent requirements, although a single robot may execute them one by one in implementation.

- **G28 -> G29, G30, G31 [AND][FALLBACK(G29,FALLBACK(G30,G31))]**

- **G44 -> G45, G46, G47 [AND][FALLBACK(G45,FALLBACK(G46,G47))]**

- **G48 -> AT40, AT41 [AND][sequential]**

- **G49 -> G50, G51 [AND][parallel]**

- **G51 -> AT43 [AND]**

- **G52 -> G9, G10 [AND][sequential]**
