# Goal Model: Periodic Vital-Signs Round in a Hospital

**Conventions**
- Goals are numbered G1, G2, ... and tasks AT1, AT2, ..., both in depth-first order.
- For goals, **Relation** is the AND/OR decomposition over the goal's children. For tasks, it is the relation to the parent goal's decomposition.
- A goal whose only child is a task gets runtime "-", since there is nothing to order.
- Some tasks have a trigger condition (for example, disinfect only if there was patient contact). They are still part of the AND/OR structure and are simply skipped when the trigger is false.

## Goals

| Name | Text | Runtime | Goal Type | Relation | Justification |
|---|---|---|---|---|---|
| **G1: Vital signs round** | Check the vital signs of all patients in occupied rooms every 2 hours, or alert the site manager if this is impossible. | FALLBACK(G2, AT27) | **Achieve.** Target: ∀ patient ∈ occupied_rooms: checked(patient, current_cycle) | OR | The mission wants a future world state, with every occupied-room patient checked in each 2-hour cycle. |
| **G2: Round with sufficient robots** | Execute the round with a robot set able to finish on time. | ; | **Achieve.** Target: robots_allocated ∧ all patients in occupied_rooms checked | AND | Allocation must precede execution. Both must hold for the round to count as done. |
| **G3: Allocate robots** | Assign the default robot, or add robots when the deadlines (2 h total, 15 min for high-risk) cannot be met. | FALLBACK(AT1, AT2) | **Achieve.** Target: estimated_completion(R) ≤ 2 h ∧ high_risk_completion(R) ≤ 15 min | OR | The description says extra robots are assigned only if the default one cannot meet the time, which is a target state. |
| **G4: Check all patients** | Determine the visit order, then check every patient room by room. | ; | **Achieve.** Target: ∀ p ∈ occupied_rooms: status(p) = done | AND | The order must be known before the visits, and the end state is every patient marked done. |
| **G5: Determine visit order** | Retrieve occupied rooms and patient risk profiles, with high-risk patients first. | - | **Query.** Enquired information: occupied_rooms ordered by risk, with each patient's risk level, conditions (infectious, post-surgical, diabetes) and bed | AND | It only retrieves information and involves no physical action. |
| **G6: Check patient in room** | Complete the whole visit for one room, from arrival to decontamination. Instantiated per room in the ordered collection. High-risk rooms must finish within 15 min of mission start. | ; | **Achieve.** Target: patient_checked(p) ∧ robot_clean | AND | The end state is a checked patient and a clean robot ready for the next room. |
| **G7: Pre-entry conditions verified** | Before entering, confirm the patient is available and the battery is sufficient. | # | **Achieve.** Target: patient_available ∧ battery_sufficient | AND | The two checks are independent, so they run in parallel, and both must hold. |
| **G8: Patient availability ensured** | Check availability, otherwise come back in 5 minutes. | FALLBACK(AT5, AT6) | **Achieve.** Target: patient_available = true | OR | It describes a condition to be brought about. Rescheduling is the alternative way to get there. |
| **G9: Battery sufficiency ensured** | Verify the battery covers all tasks in the room, otherwise recharge and reassign. | FALLBACK(AT7, G10) | **Achieve.** Target: battery ≥ energy_required(room) ∨ tasks reassigned | OR | The description defines an explicit state ("enough battery") with a recovery alternative. |
| **G10: Recharge and reassign** | Recharge the robot and reassign its pending room tasks. | # | **Achieve.** Target: battery_full ∧ tasks reassigned | AND | Reassigning lets another robot proceed while this one charges, so both run in parallel. |
| **G11: Patient identified** | Identify the correct patient in a multi-bed room by barcode or by asking. | FALLBACK(AT11, AT12) | **Achieve.** Target: identified_patient = expected_patient | OR | Either method is enough. Barcode comes first because it is more reliable and works if the patient is drowsy. |
| **G12: Patient informed** | Approach the patient, announce the procedure and give instructions. | ; | **Perform** | AND | Success depends only on the activities being carried out, not on a measurable world state. |
| **G13: Required vital signs collected** | Determine the required signs, measure them, and handle any that failed. | ; | **Achieve.** Target: ∀ s ∈ required_signs: measured(s) ∨ assessed(s) ∨ alert_sent | AND | Every required sign must end up measured, assessed by questions, or escalated. |
| **G14: Required signs determined** | Retrieve the patient's conditions and derive the signs to collect. Infectious: HR, BP, temperature, SpO₂. Post-surgical: HR, SpO₂. Diabetes: glucose. The union applies. | - | **Query.** Enquired information: required_signs(patient) | AND | It only retrieves information from the patient record. |
| **G15: Signs measured** | Attempt each required measurement. | # | **Perform** | AND | Perform is chosen so that failed readings do not abort the visit. The failures are handled by G16. Independent sensors allow parallel measurement. |
| **G16: Failed signs handled** | For signs not collected, ask assessment questions, and alert the nurse/doctor if there is no response. Triggered only if some sign failed. | FALLBACK(AT22, AT23) | **Achieve.** Target: ∀ failed s: assessed(s) ∨ alert_sent | OR | It brings about a state, with an alert as the fallback. |
| **G17: Patient marked as checked** | Record the patient as done. | - | **Achieve.** Target: status(patient) = done | AND | The end state is a record change. |
| **G18: Robot decontaminated** | Disinfect actuators after patient contact, and sterilize the robot after leaving an infectious patient's room. | ; | **Achieve.** Target: (contact → actuators_disinfected) ∧ (infectious → robot_sterilized) | AND | The hygiene requirements are explicit end states. Disinfection comes before sterilization. |

## Tasks

| Name | Text | Relation | Location | Number of Robots |
|---|---|---|---|---|
| **AT1: Assign default robot** | Assign the designated robot to the round if feasible within the deadlines. | OR | hospital | 1 |
| **AT2: Assign additional robots** | Add helper robots and redistribute rooms when the default robot cannot finish on time. | OR | hospital | [1, N_available] |
| **AT3: Retrieve rooms and risk profiles** | Query the hospital system for occupied rooms and risk levels, and sort them high-risk first. | AND | hospital | 1 |
| **AT4: Navigate to room entrance** | Move to the entrance of the next room in the ordered list. | AND | current_room (from occupied_rooms) | 1 |
| **AT5: Check patient availability** | Verify (for example by asking or sensing) that the patient can be checked now. | OR | room_entrance | 1 |
| **AT6: Reschedule in 5 minutes** | If unavailable, postpone the visit, wait 5 minutes and recheck. | OR | room_entrance | 1 |
| **AT7: Verify battery sufficiency** | Compare the battery level with the estimated energy for all tasks in the room. | OR | room_entrance | 1 |
| **AT8: Recharge battery** | Go to the charging station and recharge. | AND | charging_station | 1 |
| **AT9: Reassign pending tasks** | Hand the room's tasks over to another available robot. | AND | hospital | 1 |
| **AT10: Enter room** | Enter the patient room. | AND | current_room | 1 |
| **AT11: Scan patient barcode** | Scan the wristband barcode to identify the patient at the bed. | OR | patient_bed | 1 |
| **AT12: Ask patient identity** | Ask the patient to state name or ID if scanning fails or is impossible. | OR | patient_bed | 1 |
| **AT13: Approach patient** | Move next to the identified patient. | AND | patient_bed | 1 |
| **AT14: Announce procedure** | Tell the patient which procedure will be performed. | AND | patient_bed | 1 |
| **AT15: Instruct patient** | Give the patient instructions for the measurements. | AND | patient_bed | 1 |
| **AT16: Retrieve patient conditions** | Read the patient record and compute the required signs. | AND | hospital (patient record) | 1 |
| **AT17: Measure heart rate** | Measure heart rate, if required. | AND | patient_bed | 1 |
| **AT18: Measure blood pressure** | Measure blood pressure, if required (contact). | AND | patient_bed | 1 |
| **AT19: Measure body temperature** | Measure body temperature, if required. | AND | patient_bed | 1 |
| **AT20: Measure blood oxygenation** | Measure SpO₂, if required. | AND | patient_bed | 1 |
| **AT21: Measure blood glucose** | Measure blood glucose, if required (contact). | AND | patient_bed | 1 |
| **AT22: Ask assessment questions** | Ask a set of questions to assess status for each sign that could not be measured. | OR | patient_bed | 1 |
| **AT23: Alert nurse/doctor** | Send an alert to the responsible nurse/doctor if the patient does not respond. | OR | hospital | 1 |
| **AT24: Mark patient as done** | Record the patient as checked in the system. | AND | hospital | 1 |
| **AT25: Disinfect actuators** | Disinfect actuators after any patient contact. Skipped if there was no contact. | AND | current_room | 1 |
| **AT26: Sterilize robot** | Sterilize the robot after leaving the room of a patient with an infectious disease. Skipped otherwise. | AND | sterilization_station | 1 |
| **AT27: Alert site manager** | Alert the responsible manager that no combination of robots can complete the mission. | OR | hospital | 1 |

## Design notes

- **High-risk deadline:** G5 orders rooms high-risk first, and G3 only accepts a robot set that meets the 15-minute constraint. If the default robot cannot, AT2 adds robots. If neither works, G2 fails and G1 falls back to alerting the manager (AT27).
- **5-minute revisit (AT6):** the postponed room is re-queued in G4's ordered collection, so the robot can move on to other rooms in the meantime.
- **G15 as Perform:** measurement failures are expected and handled by G16, so a failed reading should not abort the visit.
