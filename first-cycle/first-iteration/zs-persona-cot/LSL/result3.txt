## Modeling rationale and assumptions

1. **Mission phases identified from the description**:  
   The mission naturally decomposes into: sample identification/registration, secure drawer-based transport, controlled drawer opening, laboratory pickup/processing, and secure traceability.

2. **Multi-robot interpretation**:  
   The description mentions “specific robots,” a “robotic arm,” and secure drawers. I model the transport as being carried by a mobile delivery robot with a locked drawer, and the laboratory manipulation by a robotic arm.

3. **Human actions are preserved where explicitly stated**:  
   The nurse and laboratory personnel are explicitly part of the mission. For their purely human actions, the task uses **Number of Robots = 0**. This means the task is monitored or coordinated by the multi-robot/track system but does not require a robot to execute it physically.

4. **No FALLBACK relation is used**:  
   The description says samples can be picked by a robotic arm **or** laboratory personnel, but it does not state that one is tried first and the other only if the first fails. Therefore, this is modeled as an **OR decomposition**, not as `FALLBACK(...)`.

5. **Monitored variables relevant to the model**:  
   `sampleID`, `barcodeID`, `drawerID`, `collectionTime`, `deliveryTime`, `elapsedTime`, `protocolComplianceStatus`, `openerID`, `openerType`, `openerLocation`, `authorizationStatus`, `pickupLocation`, `pickupTimestamp`, `secureLogStatus`.

# Logical Relationships

- **G1 -> G2, G3, G7, G10 [AND][sequential: `G2;G3;G7;G10`]**  
  - **Justification**: The whole mission requires registration/request, secure transport, authorized drawer opening, and lab processing. These are all mandatory and naturally ordered from patient floor to laboratory processing.

- **G2 -> AT1, AT2, AT3, AT4 [AND][sequential: `AT1;AT2;AT3;AT4`]**  
  - **Justification**: The sample must be barcoded before collection, then collected, entered into the track system, and delivery requested. All steps are necessary for a valid transport mission.

- **G3 -> G4, G5, G6 [AND][mixed: `G4;(G5#G6)`]**  
  - **Justification**: The sample must first be secured in the locked drawer. After that, physical transport and time monitoring can occur in parallel because timing is tracked during the delivery process.

- **G4 -> AT5, AT6 [AND][sequential: `AT5;AT6`]**  
  - **Justification**: The sample must be received into the secure drawer before the drawer can be locked and associated with the sample record.

- **G5 -> AT7, AT8 [AND][sequential: `AT7;AT8`]**  
  - **Justification**: The delivery robot must take custody of the locked drawer before transporting it from patient floors to the laboratory.

- **G6 -> AT9, AT10, AT11 [AND][sequential: `AT9;AT10;AT11`]**  
  - **Justification**: To check protocol compliance, the system needs collection time, delivery time, and then elapsed-time verification.

- **G7 -> G8, G9 [OR][parallel/alternative: `G8#G9`]**  
  - **Justification**: The description allows either authorized personnel or specific robots in specific locations to open locked drawers. Either one is sufficient. This is not fallback because no failure-triggered ordering is specified.

- **G8 -> AT12, AT13 [AND][sequential: `AT12;AT13`]**  
  - **Justification**: A robot must be verified as authorized and correctly located before it opens the locked drawer.

- **G9 -> AT14, AT15 [AND][sequential: `AT14;AT15`]**  
  - **Justification**: Laboratory personnel must be verified as authorized before opening the drawer.

- **G10 -> G11, AT18, G12, AT22, AT23 [AND][mixed: `G11;(AT18#G12);AT22;AT23`]**  
  - **Justification**: The sample must first be picked. After pickup, barcode scanning and secure pickup logging can occur in parallel. Sorting depends on identification/scanning, and loading into the entry-module follows sorting.

- **G11 -> AT16, AT17 [OR][parallel/alternative: `AT16#AT17`]**  
  - **Justification**: The sample can be picked by either the robotic arm or laboratory personnel. One alternative is sufficient. Again, this is not fallback because the description does not say one is attempted only if the other fails.

- **G12 -> AT19, AT20, AT21 [AND][mixed: `(AT19#AT20);AT21`]**  
  - **Justification**: The secure log requires both pickup location and pickup timestamp. These two data items can be captured in parallel, but the secure log can only be written after both are available.
