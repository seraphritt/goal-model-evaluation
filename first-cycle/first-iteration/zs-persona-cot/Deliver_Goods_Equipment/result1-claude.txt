# Goal model: resource collection and delivery mission

**Modeling assumptions**
- IDs follow the definition (`G<n>`, `AT<n>`, depth-first) rather than the `G4.1` style in the example.
- A goal whose only child is one task uses `-` as runtime, since there is nothing to orchestrate.
- "Battery ≤10% in collection" and "battery ≤30% in delivery" make G8 and G11 fail, which triggers their FALLBACK branches (G9 and G12).
- G6 is instantiated once per storage group, and the instances run in parallel (`#` at G5). The robot count for each instance is 1.
- A handoff (G9, G13) ends the original robot's participation. The replacement robot starts a new instance of G6 and skips the parts already completed.

## 1. Goals

| Name | Text | Runtime | Goal Type | Relation |
|---|---|---|---|---|
| **G1: Deliver requested resources** | When required, collect the requested resources from storage and deliver them to the requesting agent at the specified location. | `G2 ; G5` | **Achieve.** Target condition: all requested resources are at `DeliveryLocation` with the requesting agent. It describes a world state to be brought about. | AND |
| **G2: Plan mission** | Decide where and in which order to collect, and who does what. | `G3 ; G4` | **Perform.** Its outcome depends only on the planning activities being carried out. | AND |
| **G3: Determine storage order** | Rank the storages holding the requested resources. | `-` | **Query.** Enquired information: the ordered list of storages, ranked by estimated waiting time plus path length. The mission text defines the order as "waiting time summed up with the path", so this is a request for information. | AND |
| **G4: Allocate robots** | Split the storages into groups and assign robots to them, using more than one robot when items come from different storages. | `-` | **Perform.** The goal is the allocation activity itself. | AND |
| **G5: Execute collect-deliver missions** | Run the collect-deliver cycles for all storage groups to reduce total mission time. | `#` (one G6 instance per group) | **Achieve.** Target condition: every storage group's resources have been delivered. | AND |
| **G6: Collect and deliver for one group** | For one robot and its storage group, first collect and then deliver. | `G7 ; G10` | **Achieve.** Target condition: the group's resources are at `DeliveryLocation`. | AND |
| **G7: Collect resources** | Collect the required resources, or hand the mission over if the battery is low. | `FALLBACK(G8, G9)` | **Achieve.** Target condition: the requested resources are loaded on the robot, or the mission is handed over. | OR |
| **G8: Collect from storage** | Go to the storage, send the precise request, wait for retrieval, and load. Fails if battery ≤10%. | `;` | **Perform.** The description lists activities to carry out, and success is measured by their execution. | AND |
| **G9: Handle low battery (collection)** | At battery ≤10%, go to the recharging station and reassign the mission to another robot. | `#` | **Achieve.** Target condition: the robot is at `RechargingStation` and the mission is assigned to another robot. Both actions are independent, so they run in parallel. | AND |
| **G10: Deliver resources** | Deliver all resources, or hand the remaining delivery over safely. | `FALLBACK(G11, G12)` | **Achieve.** Target condition: all collected resources are at `DeliveryLocation`. | OR |
| **G11: Deliver in runs** | Make as many runs as necessary to bring all resources. Fails if battery ≤30%. | `;` (repeated until all resources are delivered) | **Perform.** The mission specifies the activity ("as many runs as necessary"), not a fixed end state. | AND |
| **G12: Handle low battery (delivery)** | At battery ≤30%, secure the resource and reassign the task. If that is not possible, escalate. | `FALLBACK(G13, G14)` | **Achieve.** Target condition: the resource is at `Checkpoint` and the task is reassigned, or the alert and report have been issued. | OR |
| **G13: Transfer delivery** | Return the resource to a checkpoint and assign the remaining task to another robot, which will know the resource position. | `;` | **Achieve.** Target condition: the resource is at `Checkpoint` and the remaining task is assigned. | AND |
| **G14: Report failure** | If the resource could not be returned to the checkpoint, trigger an alert and report to the sector manager. | `#` | **Perform.** These are independent notification activities. | AND |

## 2. Tasks

| Name | Text | Relation | Location | Number of Robots |
|---|---|---|---|---|
| **AT1: Compute storage order** | Query storages for estimated waiting time, compute path lengths, and rank the storages. | AND | `StorageList` | 1 |
| **AT2: Assign robots to groups** | Negotiate and assign robots to storage groups. | AND | `RobotLocation` (message-based) | [1,3] |
| **AT3: Go to storage** | Navigate to the next storage in the assigned order. | AND | `AssignedStorage` | 1 |
| **AT4: Send request** | Send the storage a message with the precise specification of the requested resources. | AND | `AssignedStorage` | 1 |
| **AT5: Wait for retrieval** | Wait until the storage confirms the resources were retrieved. | AND | `AssignedStorage` | 1 |
| **AT6: Load resources** | Receive and load the retrieved resources. | AND | `AssignedStorage` | 1 |
| **AT7: Return to recharging** | Go to the recharging station. | AND | `RechargingStation` | 1 |
| **AT8: Reassign mission** | Hand the mission to another available robot. | AND | `RobotLocation` (message-based) | 2 |
| **AT9: Carry load** | Transport the current load to the delivery location. | AND | `DeliveryLocation` | 1 |
| **AT10: Unload** | Hand over the resources to the requesting agent. | AND | `DeliveryLocation` | 1 |
| **AT11: Return for next run** | Go back to the remaining resources for the next run. | AND | `CollectionPoint` | 1 |
| **AT12: Return to checkpoint** | Place the carried resource at a checkpoint. | AND | `Checkpoint` | 1 |
| **AT13: Assign remaining task** | Assign the remaining delivery to another robot, sharing the resource position. | AND | `RobotLocation` (message-based) | 2 |
| **AT14: Trigger alert** | Raise an alert about the failed return. | AND | `RobotLocation` | 1 |
| **AT15: Report to manager** | Send the report to the sector manager. | AND | `RobotLocation` (message-based) | 1 |

**Variable monitoring.** The parent goal monitors each variable used by its tasks:

| Variable | Monitored by |
|---|---|
| `StorageList` | G3 |
| `RobotLocation` | G4, G9, G13, G14 |
| `AssignedStorage` | G8 |
| `RechargingStation` | G9 |
| `DeliveryLocation`, `CollectionPoint` | G11 |
| `Checkpoint` | G13 |

## 4. Logical relationships

- **G1 → G2, G5 [AND][(sequential)]**
- **G2 → G3, G4 [AND][(sequential)]**
- **G3 → AT1 [AND]**
- **G4 → AT2 [AND]**
- **G5 → G6 [AND][(parallel)]**, with one G6 instance per storage group
- **G6 → G7, G10 [AND][(sequential)]**
- **G7 → G8, G9 [OR][FALLBACK(G8, G9)]**
- **G8 → AT3, AT4, AT5, AT6 [AND][(sequential)]**
- **G9 → AT7, AT8 [AND][(parallel)]**
- **G10 → G11, G12 [OR][FALLBACK(G11, G12)]**
- **G11 → AT9, AT10, AT11 [AND][(sequential)]**
- **G12 → G13, G14 [OR][FALLBACK(G13, G14)]**
- **G13 → AT12, AT13 [AND][(sequential)]**
- **G14 → AT14, AT15 [AND][(parallel)]**

The mission text gives no fleet size or number of storages. The robot count in AT2 ([1,3]) and the choice of location variables are my assumptions and should be adjusted to the real deployment.
