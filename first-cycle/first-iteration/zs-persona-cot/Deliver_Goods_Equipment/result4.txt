### Task Model

| Name | Text | Relation | Location | Number of Robots |
|------|------|----------|----------|------------------|
| **AT1 – Move to Storage** | Robot moves from its current position to the storage where the required item is located. | **AND** | *Storage X* | 1 |
| **AT2 – Send Request Message** | Robot transmits a request containing the exact specification of the needed resource to the storage. | **AND** | *Storage X* | 1 |
| **AT3 – Await Retrieval** | Robot waits until the storage confirms that the item(s) have been removed and are in the robot’s possession. | **AND** | *Storage X* | 1 |
| **AT4 – Transport Resource to Delivery Point** | Robot carries the item(s) to the designated delivery location. | **AND** | *Delivery Point* | 1 |
| **AT5 – Return to Recharge Station** | Robot navigates back to the recharging station because its battery is below the collection threshold. | **AND** | *Recharge Station* | 1 |
| **AT6 – Assign Mission to New Robot** | Robot informs the control centre to re‑assign the pending collection/delivery task to another robot. | **AND** | *Control Centre* | 1 |
| **AT7 – Return Resource to Checkpoint** | Robot returns the item(s) to the nearest checkpoint when battery falls below the delivery threshold. | **AND** | *Checkpoint* | 1 |
| **AT8 – Trigger Alert and Report** | Robot generates an alert and sends a report to the sector manager about the failed checkpoint return. | **AND** | *Sector Manager* | 1 |
| **AT9 – Monitor Battery Level** | Robot continuously monitors its battery level during both collection and delivery phases. | **AND** | *Robot* | 1 |

### Justifications for Goal Types

| Goal | Chosen Type | Rationale |
|------|-------------|-----------|
| G1 | **Achieve** | The mission’s ultimate objective is to change the world state so that the requested resources are physically present at the destination and confirmed by the requester. This requires a state change that is externally verifiable. |
| G2, G3, G2.1‑G2.4, G3.1‑G3.4 | **Perform** | Each of these goals specifies a set of concrete actions (navigating, messaging, waiting, re‑assigning, etc.) that need to be executed. The success of each goal depends solely on whether the associated activities are performed; there is no need for a specific state query or target beyond completion of the activities. |
