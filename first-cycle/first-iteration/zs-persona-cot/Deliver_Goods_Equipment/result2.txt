## Modeling basis

The mission is modeled as a hierarchical goal tree: goals represent intentional objectives, while tasks are concrete operational steps assigned to robots. The model uses AND decompositions when children are jointly required and uses the fallback operator only where the mission explicitly says what happens after a failure. This follows the provided definitions of goal models, AND/OR decomposition, runtime annotations, goal types, and task attributes. :chatgpt-content-reference{index="0"} :chatgpt-content-reference{index="1"} :chatgpt-content-reference{index="2"} :chatgpt-content-reference{index="3"}

**Variable used:** `n` = maximum number of robots available or assigned for parallel collect-deliver tasks. The exact number is not stated, but the mission says multiple robots can be assigned when multiple items are required from different storages. :chatgpt-content-reference{index="4"}

## 4. Logical relationships and justifications

**G1 → G2, G5 [AND][sequential: `G2;G5`]**  
The mission must first be prepared by identifying resources, storage places, ordering criteria, and robot assignment. Only then can the robot or robots execute collection and delivery. This is an AND decomposition because both preparation and execution are required to fulfill the request. :chatgpt-content-reference{index="40"}

**G2 → G3, G4 [AND][sequential: `G3;G4`]**  
The storage/order information must be available before meaningful robot assignment can be completed. This is AND because knowing where to collect and assigning robots are complementary requirements. :chatgpt-content-reference{index="41"} :chatgpt-content-reference{index="42"}

**G3 → AT1, AT2 [AND][sequential: `AT1;AT2`]**  
The robot must first identify storage places for the resources, then estimate waiting time plus path to define the order. This is AND because both pieces are required to establish the collection sequence. :chatgpt-content-reference{index="43"}

**G4 → AT3, AT4 [AND][sequential: `AT3;AT4`]**  
A robot or robot team must be assigned, and when multiple storages/items exist, work can be distributed as parallel collect-deliver tasks. This is AND because assignment and dispatching together define the execution allocation. :chatgpt-content-reference{index="44"}

**G5 → G6, G10 [AND][sequential: `G6;G10`]**  
Collection precedes delivery because the delivery phase begins once resources have been retrieved. This is a clear sequential AND relation. :chatgpt-content-reference{index="45"}

**G6 → G7, G8, G9 [AND][mixed: `(G7;G8)#G9`]**  
The robot must reach the storage and then obtain the resource. The collection low-battery handler is modeled in parallel because it is a condition that can occur during the collection phase. :chatgpt-content-reference{index="46"}

**G7 → AT5, AT6 [AND][sequential: `AT5;AT6`]**  
The robot navigates to the storage and then confirms it has reached the correct point/time for requesting resources. Both are necessary before the request can be sent. :chatgpt-content-reference{index="47"}

**G8 → AT7, AT8 [AND][sequential: `AT7;AT8`]**  
The robot first sends the precise resource request and then waits until retrieval is completed. These actions are explicitly sequential. :chatgpt-content-reference{index="48"}

**G9 → AT9, AT10 [AND][sequential: `AT9;AT10`]**  
When the collection battery threshold is reached, the robot goes to the recharging station and assigns the mission to another robot. Both are required for continuity. :chatgpt-content-reference{index="49"}

**G10 → G11, G12 [AND][parallel: `G11#G12`]**  
Delivery is the main activity, while battery handling is an event-driven safety behavior that can occur during delivery. The 30% condition must therefore be monitored alongside delivery execution. :chatgpt-content-reference{index="50"}

**G11 → AT11, AT12 [AND][sequential: `AT11;AT12`]**  
The robot makes the necessary runs and completes the delivery to the requesting agent at the specified location. This is AND because transport and final handoff are jointly required. :chatgpt-content-reference{index="51"}

**G12 → G13, G14 [AND][fallback: `FALLBACK(G13,G14)`]**  
The first intended response is checkpoint handoff. Only if returning the resource to the checkpoint fails does the system trigger an alert and send a report. This exactly matches the fallback definition because the second goal is attempted only if the first fails. :chatgpt-content-reference{index="52"} :chatgpt-content-reference{index="53"}

**G13 → AT13, AT14 [AND][sequential: `AT13;AT14`]**  
The robot must return the resource to a checkpoint and then assign the remaining task to another robot that knows the resource position. Both are necessary for successful handoff. :chatgpt-content-reference{index="54"}

**G14 → AT15, AT16 [AND][sequential: `AT15;AT16`]**  
If checkpoint return fails, the mission requires both an alert and a report to the sector manager. This is AND because the description requires both actions. :chatgpt-content-reference{index="55"}
