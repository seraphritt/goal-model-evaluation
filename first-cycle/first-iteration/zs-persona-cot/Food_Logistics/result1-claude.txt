# Goal Model: Hospital Meal Delivery and Dish Retrieval (Multi-Robot)

**Modeling conventions**
- Goal IDs (G) and task IDs (AT) are numbered depth-first.
- A *leaf goal* has no sub-goals and is realized by one task, or by alternative tasks in an OR relation. Its runtime is "-".
- The *Relation* column gives the decomposition type of the node's own children.
- Uncertainty about who can retrieve the meal is handled by FALLBACK operators. The uncertain information is enquired in a Query goal (G12, G22).

---

## 1. Goals

### Root and delivery branch

| Name | Text | Runtime | Goal Type | Relation |
|---|---|---|---|---|
| **G1: Serve meals** | Deliver ordered meals to inpatient rooms and retrieve dirty dishes | G2 # G21 | **Achieve.** Target: all requested meals are handed over and all dirty dishes are back in the kitchen | AND |
| **G2: Deliver ordered meals** | Deliver the meals of a kitchen request to the right inpatient room | G3 ; G6 ; (G9 # G18) | **Achieve.** Target: every meal in the request is available to its inpatient | AND |
| **G3: Prepare order** | Know the delivery request and have the meals on the robot | G4 ; G5 | **Achieve.** Target: request known and meals loaded on the tray | AND |
| **G4: Know request** | Obtain the kitchen delivery request | - | **Query.** Enquired information: order id, meals, inpatient, target room | AND |
| **G5: Load meals** | Load one or several meals onto the robot tray, each in an identified slot | - | **Achieve.** Target: all meals of the request are on the tray with slot–meal mapping | AND |
| **G6: Reach room** | Get the robot inside the inpatient room | G7 ; G8 | **Achieve.** Target: robot is inside the room | AND |
| **G7: Reach door** | Navigate to the room door | - | **Achieve.** Target: robot at `room_door` | AND |
| **G8: Open door** | Get the room door opened with help | - | **Achieve.** Target: door open | OR |
| **G9: Hand over meal** | Make the meal available to the inpatient, preferably unassisted | FALLBACK(G10, G11) | **Achieve.** Target: meal on the table or retrieved from the tray | OR |
| **G10: Meal on table** | Robot with manipulation skill places the meal on the room table | - | **Achieve.** Target: meal on `room_table` | AND |
| **G11: Tray retrieval** | Deliver the meal via tray retrieval | G12 ; G13 | **Achieve.** Target: meal removed from the tray by an authorized retriever | AND |
| **G12: Find retriever** | Determine who can retrieve the meal from the tray | - | **Query.** Enquired information: inpatient's ability to fetch (from record), companion presence, nurse availability, each with confidence level | AND |
| **G13: Complete retrieval** | Get the meal retrieved by a human or, failing that, by another robot | FALLBACK(G14, G17) | **Achieve.** Target: meal off the tray and handed over | OR |
| **G14: Human retrieval** | Meal is retrieved by inpatient, companion or nurse | G15 ; G16 | **Achieve.** Target: meal retrieved by a human | AND |
| **G15: Indicate meal** | Indicate which meal the person must take | - | **Perform** | AND |
| **G16: Human takes meal** | Present the tray and wait for the person to take the meal | - | **Achieve.** Target: meal removed from tray by a human | AND |
| **G17: Robot retrieval** | Another robot takes the meal from the tray | - | **Achieve.** Target: meal removed from tray by a cooperating robot | AND |
| **G18: Track and alert** | Track retrievals and alert on wrong retrieval | G19 # G20 | **Perform.** | AND |
| **G19: Log retrieval** | Record when and where each meal was retrieved | - | **Achieve.** Target: every retrieved meal has a record (meal id, time, place) | AND |
| **G20: Alert wrong meal** | Alert if the retrieved meal is not the one assigned | - | **Perform** | AND |

**Justifications (goal types)**
- **G1, G2, G3, G6–G11, G13, G14, G16, G17, G19:** they describe world states the system wants to reach, and each has a checkable target condition, so they are Achieve goals.
- **G4:** the description says delivery happens "in response to kitchen delivery requests"; the goal only retrieves information, so it is a Query.
- **G5:** success depends on a verifiable state (meals loaded in identified slots), not just on having tried, so it is Achieve.
- **G12:** the description says the ability to retrieve is obtained "based on the inpatient record" and is "subject to uncertainty"; the goal only enquires this information, so it is a Query.
- **G15:** success depends only on having performed the indication (screen, voice, light). Whether the person complies is handled by G16, so it is Perform.
- **G18, G20:** they are continuous or conditional monitoring activities. G20 does nothing when the right meal is taken, and its outcome depends only on performing the alert action, so both are Perform.

### Dish retrieval branch

| Name | Text | Runtime | Goal Type | Relation |
|---|---|---|---|---|
| **G21: Retrieve dishes** | Collect dirty dishes from a room and take them to the kitchen | G22 ; G23 ; G28 ; G32 | **Achieve.** Target: dishes of the room are in the kitchen | AND |
| **G22: Know pickup need** | Know which room needs pickup and whether the caller can open the door | - | **Query.** Enquired information: room id, request origin (call from the room or post-meal), and whether the caller signaled they can open the door | OR |
| **G23: Reach room (dishes)** | Get the robot inside the room | G24 ; G25 | **Achieve.** Target: robot inside the room | AND |
| **G24: Reach door (dishes)** | Navigate to the room door | - | **Achieve.** Target: robot at `room_door` | AND |
| **G25: Open door (dishes)** | Open the door, preferring the caller if they signaled they can | FALLBACK(G26, G27) | **Achieve.** Target: door open | OR |
| **G26: Caller opens door** | Person in the room opens the door | - | **Achieve.** Target: door opened by the caller | AND |
| **G27: Other agent opens door** | Another robot or a human opens the door | - | **Achieve.** Target: door opened by a robot or human | OR |
| **G28: Collect dishes** | Get the dishes onto the robot: unassisted, then with two robots, then with robot and human | FALLBACK(G29, FALLBACK(G30, G31)) | **Achieve.** Target: dishes on the robot tray | OR |
| **G29: Unassisted collection** | One robot with manipulation skill picks up the dishes | - | **Achieve.** Target: dishes on tray, no help used | AND |
| **G30: Two-robot collection** | Two robots cooperate to collect the dishes | - | **Achieve.** Target: dishes on tray via robot cooperation | AND |
| **G31: Robot–human collection** | Robot(s) and a human cooperate to load the dishes | - | **Achieve.** Target: dishes on tray via human help | AND |
| **G32: Return dishes** | Take the dishes to the kitchen and unload them | - | **Achieve.** Target: dishes unloaded at `kitchen_return` | AND |

**Justifications (goal types)**
- **G22:** it only retrieves information (who called, from where, and whether they can open the door), so it is a Query.
- **All others:** each has a concrete state that can be checked (robot at the door, door open, dishes on the tray, dishes in the kitchen), so they are Achieve goals.

## 4. Logical Relationships

**Goal–goal relations**
- **G1 -> G2, G21 [AND][(parallel)]**
- **G2 -> G3, G6, G9, G18 [AND][(sequential) G3 ; G6 ; (G9 # G18)]**
- **G3 -> G4, G5 [AND][(sequential)]**
- **G6 -> G7, G8 [AND][(sequential)]**
- **G9 -> G10, G11 [OR][FALLBACK(G10, G11)]**
- **G11 -> G12, G13 [AND][(sequential)]**
- **G13 -> G14, G17 [OR][FALLBACK(G14, G17)]**
- **G14 -> G15, G16 [AND][(sequential)]**
- **G18 -> G19, G20 [AND][(parallel)]**
- **G21 -> G22, G23, G28, G32 [AND][(sequential)]**
- **G23 -> G24, G25 [AND][(sequential)]**
- **G25 -> G26, G27 [OR][FALLBACK(G26, G27)]**
- **G28 -> G29, G30, G31 [OR][FALLBACK(G29, FALLBACK(G30, G31))]**

**Goal–task relations**
- **G4 -> AT1 [AND]**
- **G5 -> AT2 [AND]**
- **G7 -> AT3 [AND]**
- **G8 -> AT4, AT5 [OR]**
- **G10 -> AT6 [AND]**
- **G12 -> AT7 [AND]**
- **G15 -> AT8 [AND]**
- **G16 -> AT9 [AND]**
- **G17 -> AT10 [AND]**
- **G19 -> AT11 [AND]**
- **G20 -> AT12 [AND]**
- **G22 -> AT13, AT14 [OR]**
- **G24 -> AT15 [AND]**
- **G26 -> AT16 [AND]**

- **G29 -> AT19 [AND]**
- **G30 -> AT20 [AND]**
- **G31 -> AT21 [AND]**
- **G32 -> AT22 [AND]**

**Design notes on the runtime choices**
- **G9 FALLBACK(G10, G11):** table placement is unassisted and needs no cooperation, so it is tried first. Tray retrieval is the fallback when the robot lacks the manipulation skill or the table is unavailable.
- **G13 FALLBACK(G14, G17):** human retrieval is tried first, based on G12's uncertain estimate. If nobody can retrieve the meal, another robot does.
- **G28 FALLBACK:** the order goes from least to most cooperation (unassisted, two robots, robot plus human).
- **G25 FALLBACK:** the caller who signaled they can open the door is used first. Otherwise another robot or a human helps.
