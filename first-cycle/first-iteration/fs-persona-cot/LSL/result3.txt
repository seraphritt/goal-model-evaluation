## 1. Modeling rationale, mission interpretation, and assumptions

I model the mission as a **secure and traceable hospital sample-delivery workflow** involving at least: 
1. a mobile delivery robot or robotic drawer carrier, 
2. a laboratory robotic arm, 
3. the track/logging system, and 
4. authorized human laboratory personnel as an explicitly permitted non-robot alternative.

Key modeling decisions:

- **No FALLBACK relation is used.** The description gives alternatives, e.g., “robotic arm or laboratory personnel,” but it does not say that one must be attempted first and the second only if the first fails. Therefore, these are modeled as **OR alternatives**, not fallback.
- **The nurse’s actions are external triggers/preconditions** for the robot mission: the nurse requests delivery, the sample has a barcode, and sample data is inserted into the track system. The robot/system must acquire or verify this information before transport.
- **Authorization is mandatory before drawer opening.** The description explicitly states that only authorized personnel or specific robots in specific locations may open locked drawers.
- **Time tracking is concurrent with transportation.** The sample is physically transported while the elapsed time from collection to delivery is monitored.
- **Laboratory pickup has two alternatives:** robotic arm pickup/intake or laboratory personnel pickup.
- **Human-only tasks use Number of Robots = 0**, because the description explicitly allows laboratory personnel to perform pickup/opening.

Monitored variables include: `sample_id`, `barcode_id`, `request_id`, `track_record`, `drawer_state`, `actor_id`, `robot_id`, `current_location`, `collection_time`, `delivery_time`, `elapsed_time`, `pickup_time`, `pickup_location`, and `secure_log_status`.

# 5. Logical relationships

## Top-level mission

- **G1 -> G2, G3, G4, G5 [AND][sequential: `G2;G3;G4;G5`]**
  - **Justification:** The sample-delivery mission requires all major concerns: request/sample-data acquisition, secure containment, transport with timing, and laboratory receiving. These are not alternatives; all must be achieved. The sequence follows the mission workflow: the system first knows what to transport, then secures it, transports it, and finally performs laboratory receiving.

---

## Request and sample-data acquisition

- **G2 -> AT1, AT2, AT3 [AND][sequential/parallel: `AT1;(AT2#AT3)`]**
  - **Justification:** The nurse request initiates delivery. After the request is received, barcode verification and track-system record retrieval are both required but can happen in parallel because they are independent checks. This comes directly from the statements that the nurse requests delivery, the sample has a barcode, and data exists in the track system.

---

## Secure containment before transport

- **G3 -> AT4, AT5 [AND][sequential: `AT4;AT5`]**
  - **Justification:** The sample must be transported in a secure locked drawer. The robot must first load or receive the sample into the drawer, then lock it. Both are required, so this is AND.

---

## Transport and time protocol tracking

- **G4 -> AT6, AT7, AT8, AT9 [AND][sequential/parallel: `AT6;(AT7#AT8);AT9`]**
  - **Justification:** The timer must start at collection/acceptance, then the robot physically transports the sample while monitoring elapsed time. Transport and monitoring can occur in parallel. At laboratory delivery, the timer stops and the elapsed time is checked against protocols. This directly models the requirement that collection-to-delivery time be tracked according to laboratory protocols.

---

## Laboratory receiving

- **G5 -> G6, G7, G10 [AND][sequential: `G6;G7;G10`]**
  - **Justification:** Before the drawer is opened, authorization constraints must be enforced. Then a permitted pickup mode is used. Finally, the where/when pickup information is logged securely. All three are required by the description.

---

## Drawer-opening authorization

- **G6 -> AT10, AT11 [AND][parallel: `AT10#AT11`]**
  - **Justification:** The mission requires that only authorized personnel or specific robots in specific locations open the drawers. Therefore, both actor authorization and location authorization are mandatory. They can be checked in parallel because checking identity/role and checking location do not depend on one another.

  - **Justification:** The description states that in the laboratory the sample can be picked by a robotic arm **or** laboratory personnel. Therefore, either branch is sufficient to satisfy the pickup-mode goal. This is OR, not FALLBACK, because the description does not state that one option is tried first and the other only if it fails.

## Robotic-arm intake branch

- **G8 -> AT12, AT13, AT14, AT15, AT16 [AND][sequential: `AT12;AT13;AT14;AT15;AT16`]**
  - **Justification:** The robotic-arm branch follows the described operational order: open/unlock the drawer, pick up the sample, scan the barcode, sort the sample, and load it into the analysis-machine entry-module. Each action contributes to the full robotic intake process, so the decomposition is AND.

## Laboratory-personnel pickup branch

- **G9 -> AT17, AT18 [AND][sequential: `AT17;AT18`]**
  - **Justification:** The human branch requires authorized personnel to open the drawer before picking the sample. The description explicitly allows laboratory personnel to pick samples, so this is modeled as an alternative to robotic-arm intake.

## Secure pickup logging

- **G10 -> AT19, AT20 [AND][sequential: `AT19;AT20`]**
  - **Justification:** The system must log where and when a given sample was picked. The pickup event data must first be captured, then securely written to the logging/track system. Both are required, so the relation is AND.

# 6. Fallback analysis

No `FALLBACK(...)` relation is used in this model.

Reason: the description contains alternatives, but it does **not** define an explicit priority, exception, failure condition, or retry order. For example:

- “The sample can be picked by a robotic arm or laboratory personnel” means either is acceptable.
- It does not say: “try robotic arm first; if unavailable, use laboratory personnel.”

Therefore, this is modeled as:

- **OR decomposition:** `G7 -> G8, G9`
- **Runtime availability:** `G8#G9`
- **Not fallback.**
