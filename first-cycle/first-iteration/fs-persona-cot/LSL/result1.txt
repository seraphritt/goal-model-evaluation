## 1. Mission interpretation and modeling rationale

The mission can be decomposed into the following main concerns:

1. **Request and identification**: a nurse requests transport, the sample has a barcode, and sample data is entered in the tracking system.
2. **Secure containment**: the sample must travel in a secure locked drawer.
3. **Transport**: the sample moves from **patient floors** to the **laboratory**.
4. **Laboratory retrieval**: once in the laboratory, the sample can be picked either by a **robotic arm** or by **laboratory personnel**. This is modeled as an **OR decomposition**, not a fallback, because the description does not state that one is tried only after the other fails.
5. **Laboratory robotic processing**: if the robotic arm is used, it picks, scans barcode, sorts, and loads samples into the **entry-module of the analysis machines**.
6. **Security and traceability**: drawer opening must be restricted to authorized personnel or specific robots in specific locations; pickup location/time must be securely logged.
7. **Protocol timing**: time from collection to laboratory delivery must be tracked and checked against laboratory protocols.

No **FALLBACK** relation is used because the description provides alternatives but does not explicitly define a failure-triggered order such as “try robotic arm first, and if it fails use personnel.”

## 5. Logical relationships and justifications

- **G1 -> G2, G9 [AND][parallel: `G2#G9`]**
  - **Justification**: The mission is not only about moving samples; it also requires traceability, access control, and timing compliance. The operational workflow and compliance monitoring can run concurrently.

- **G2 -> G3, G4, G5, G6 [AND][sequential: `G3;G4;G5;G6`]**
  - **Justification**: A request and sample identity must be established before drawer loading. The sample must be secured before transport. Laboratory retrieval occurs after delivery.

- **G3 -> AT1, AT2, AT3 [AND][sequential: `AT1;AT2;AT3`]**
  - **Justification**: The nurse request, barcode verification, and tracking-system confirmation are all required for a traceable delivery.

- **G4 -> AT4, AT5, AT6 [AND][sequential: `AT4;AT5;AT6`]**
  - **Justification**: The drawer must be presented/opened, the sample inserted, and the drawer closed and locked before transport.

- **G5 -> AT7, AT8 [AND][sequential: `AT7;AT8`]**
  - **Justification**: Physical movement to the laboratory must occur before delivery confirmation.

- **G6 -> G7, G8 [OR][parallel/no-order availability: `G7#G8`]**
  - **Justification**: The sample can be picked by a robotic arm or by laboratory personnel. Either child satisfies the laboratory retrieval goal. This is not fallback because the description does not say one is attempted only after the other fails.

- **G7 -> AT9, AT10, AT11, AT12, AT13 [AND][sequential: `AT9;AT10;AT11;AT12;AT13`]**
  - **Justification**: The robotic-arm path requires opening the drawer, picking samples, scanning barcodes, sorting, and loading into the analysis-machine entry-module. The description lists these actions in an operational order.

- **G8 -> AT14, AT15, AT16 [AND][sequential: `AT14;AT15;AT16`]**
  - **Justification**: Personnel pickup requires credential validation, drawer opening, and monitored pickup.

- **G9 -> G10, G11, G12, G13 [AND][combined: `((G10;G11)#G13)#G12`]**
  - **Justification**: The mission requires all three compliance dimensions: authorization/access control, secure pickup logging, and delivery-time tracking. Authorization verification must occur before enforcement. Timing and logging are event-driven and can run alongside the main workflow.

- **G10 -> AT17, AT18, AT19 [AND][combined: `(AT17#AT18);AT19`]**
  - **Justification**: The opener identity and drawer location are both needed to determine authorization. They can be sensed in parallel, then queried together against the access policy.

- **G11 -> AT20, AT21 [AND][sequential: `AT20;AT21`]**
  - **Justification**: The drawer must remain locked by default and only release after authorization succeeds.

- **G12 -> AT22, AT23 [AND][sequential: `AT22;AT23`]**
  - **Justification**: The pickup event must first be captured, then securely stored.

- **G13 -> AT24, AT25, AT26 [AND][sequential: `AT24;AT25;AT26`]**
  - **Justification**: The delivery-time interval must start at collection/request, stop at laboratory delivery, and then be compared against protocol limits.

## 6. Fallback analysis

No fallback relation is modeled.

- The description says: “In the laboratory, the sample can be picked by a robotic arm or laboratory personnel.”
- This indicates an **OR alternative**.
- It does **not** state: “try the robotic arm first, and if it fails, use personnel.”
- Therefore, modeling this as `FALLBACK(G7, G8)` would add an execution order and failure condition not present in the mission description.
