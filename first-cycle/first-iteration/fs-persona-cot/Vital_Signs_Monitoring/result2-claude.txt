# Goal Model: Hospital Vital-Signs Round (Multi-Robot System)

## 1. Step-by-step reasoning

**Step 1: Extract the mission structure.** The mission is a periodic (every 2 h) round over *occupied* rooms. The main phases are: know what to check → plan → for each room: enter → identify patient → prepare patient → measure → handle failures → hygiene → next room. Around this sits a time-feasibility layer (extra robots, then manager alert).

**Step 2: Separate goals from tasks.** Goals hold intentions ("ensure the patient is available"). Tasks are concrete robot actions with a place and a robot count ("scan barcode at the bed").

**Step 3: Identify the operators the text implies.**
- *Sequential (;)*: "before entering", "once inside", "once checked … proceed".
- *Fallback*: "if not available, come back in 5 min", "asking **or** scanning", "in case of non-response, alert", "additional robots … manager alerted if no combination works".
- *Parallel (#)*: independent checks or measurements with no stated order (availability ∥ battery; sensors).

**Step 4: Handle the conditional requirements.**
- Infectious: HR, BP, temperature, SpO₂.
- Post-surgical: HR, SpO₂.
- Diabetes: glucose.

HR and SpO₂ appear in two conditions, so I grouped signs to avoid measuring twice: (HR, SpO₂) for infectious or post-surgical patients; (BP, temperature) for infectious patients only; (glucose) for diabetic patients. A patient may have several conditions, so the required set is the union.

**Step 5: Place the hygiene rules.**
- Actuator disinfection follows patient contact, so it sits *per patient*. This matters in multi-bed rooms to avoid cross-contamination.
- Robot sterilization applies when leaving an infectious room, so it sits *per room*.

**Step 6: Place the timing rules.**
- The high-risk 15-minute rule becomes a prioritization task (AT3) plus a feasibility estimate (AT4).
- The 2-hour deadline becomes the fallback chain in G3.

**Modeling conventions and assumptions**
- IDs follow depth-first order (G1, G2… / AT1, AT2…).
- A goal with a single child has no operator to define, so it gets "–".
- G6 (per room) and G11 (per bed) are *iterated* goals, instantiated for each element of a collection (`PrioritizedRooms`, `Beds(r)`).
- The extra robots in G23 execute the same G6 subtree for the rooms handed to them, so the subtree is not duplicated.
- Patients with none of the three listed conditions are not specified in the text. I assume a baseline set is defined by the hospital (open point).
- Sensor concurrency depends on robot hardware, which the text does not state. I assume the sensors can operate concurrently.

## 5. Logical relationships

**G1 → G2, G3 [AND][sequential ;]**
- The mission needs the scope and its execution. The rooms and patient needs must be known before the round begins.

**G2 → AT1, AT2 [AND][parallel #]**
- Both the room list and the profiles are needed, and they are independent lookups.

**G3 → G4, G23, G24 [OR][FALLBACK(G4, FALLBACK(G23, G24))]**
- Nominal execution, then extra robots, then escalation, each tried only if the previous fails. Any of them closes the goal (done in time, or manager informed).

**G4 → G5, G6 [AND][sequential ;]**
- Plan, then visit. The plan defines the room order and feasibility.

**G5 → AT3, AT4 [AND][sequential ;]**
- The room order must exist before the duration and energy estimate is computed.

**G6 → AT5, G7, G11, G22 [AND][sequential ;]**
- Navigate to the door, check the entry conditions, check the patients, then leave and decontaminate. This is the order stated in the description.

**G7 → G8, G9 [AND][parallel #]**
- Both conditions must hold and neither depends on the other.

**G8 → AT6, AT7 [OR][FALLBACK(AT6, AT7)]**
- Check first, postpone only when the patient is unavailable. After AT7 the room instance is re-triggered after 5 min.

**G9 → AT8, G10 [OR][FALLBACK(AT8, G10)]**
- Recovery is needed only if the battery check fails.

**G10 → AT9, AT10 [AND][parallel #]**
- Both are mandatory, and reassignment shouldn't wait for charging.

**G11 → G12, G13, G14, G21 [AND][sequential ;]**
- Identify → prepare → measure → close. Measuring the wrong person is unsafe, and instructions must precede measurement.

**G12 → AT11, AT12 [OR][FALLBACK(AT11, AT12)]**
- Either method identifies the patient; scanning is tried first.

**G13 → AT13, AT14, AT15 [AND][sequential ;]**
- Approach, announce, instruct: the stated order.

**G14 → G15, G19, G20 [OR][FALLBACK(G15, FALLBACK(G19, G20))]**
- Measurement first, questions for the failed signs, alert on non-response.

**G15 → G16, G17, G18 [AND][parallel #]**
- All applicable groups are needed, and they are independent. The conditions are: G16 if infectious or post-surgical, G17 if infectious, G18 if diabetic.

**G16 → AT16, AT17 [AND][parallel #]**
- Both signs are needed and they are independent.

**G17 → AT18, AT19 [AND][parallel #]**
- Both signs are needed and they are independent.

**G18 → AT20 [AND]**
- Single measurement, so no operator.

**G19 → AT21, AT22 [AND][sequential ;]**
- Ask, then record. A missing answer fails G19 and escalates to G20.

**G20 → AT23 [AND]**
- Single alert action, so no operator.

**G21 → AT24, AT25 [AND][sequential ;]**
- The robot is clean before the next bed/patient, then the patient is closed as done.

**G22 → AT26 [AND]**
- Single decontamination action, so no operator. Applies only to infectious rooms.

**G23 → AT27, AT28 [AND][sequential ;]**
- Robots must be assigned before rooms can be redistributed to them.

**G24 → AT29 [AND]**
- Single escalation action, so no operator.

## 6. Open points to validate

- **Time conflicts:** The 5-minute postponement (AT7) and sterilization (AT26) can conflict with the 15-minute high-risk window. AT4 should account for them when estimating feasibility.
- **Partial failures:** If a sign fails after other signs succeeded, `FailedSigns` holds only the failed ones, so G19 asks questions only about those.
- **Baseline patients:** Patients with no listed condition need a hospital-defined default sign set.
- **Sensor hardware:** The parallel operators in G15–G17 assume the robot can measure concurrently. If not, change them to sequential.
