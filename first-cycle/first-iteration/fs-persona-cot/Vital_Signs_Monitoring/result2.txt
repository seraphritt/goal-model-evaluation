Below is a structured goal-model decomposition for the multi-robot hospital mission. I treat the mission as a **timed, safety-critical, multi-robot achievement goal**, because the final desired state is not just “robots performed actions,” but that **all occupied-room patients are checked correctly, high-risk patients are checked within 15 minutes, failures are handled, hygiene constraints are satisfied, and infeasibility is escalated**.

## Design rationale

1. **The root mission is an Achieve Goal** because the mission aims to bring about a future state: all required patient checks completed within the required time constraints.

2. **The mission is periodic** because the description says vital signs should be checked **every two hours**.

3. **Occupied rooms are the mission scope** because the assigned robot should visit every occupied room.

4. **Pre-entry checks are mandatory guards** because the robot must verify patient availability and battery sufficiency before entering.

5. **Patient identification is an OR/FALLBACK structure** because the robot may identify the correct patient either by asking or by scanning the barcode.

6. **Vital-sign collection is condition-dependent** because infectious disease, post-surgical condition, and diabetes history activate different required measurements.

7. **Failure handling is a FALLBACK structure** because failed sensor collection triggers questions, and non-response triggers an alert.

8. **Sanitization is conditional but mandatory** because sterilization and actuator disinfection are required after specific contamination/contact conditions.

9. **Multi-robot coordination is a fallback strategy** because additional robots are only assigned when the current team cannot complete the mission on time.

10. **Manager alert is the final fallback** because it is required only when no combination of robots can complete the mission.

# Logical Relationships

## Root mission

* **G1 → G2, G3, G7, G10, G43 [OR] [FALLBACK((G2 ; G3 ; G7 ; G10), G43)]**

  * **Justification**: The mission normally requires triggering the cycle, gathering context, assigning robots, and executing checks. However, if no robot combination can complete the mission, the manager alert is the required fallback.

---

## Mission initialization and context

* **G2 → AT1 [AND] [sequential]**

  * **Justification**: The mission cannot begin unless the two-hour cycle is triggered.

* **G3 → G4, G5, G6 [AND] [parallel]**

  * **Justification**: Occupied rooms, patient profiles, and robot status are all required to plan the mission. These queries can be performed in parallel because they retrieve independent information.

* **G4 → AT2 [AND] [sequential]**

  * **Justification**: The occupied-room list is required to know where robots must go.

* **G5 → AT3 [AND] [sequential]**

  * **Justification**: Patient condition data determines which vital signs are required.

* **G6 → AT4 [AND] [sequential]**

  * **Justification**: Robot battery, location, and availability are needed for feasible assignment.

---

## Robot assignment

* **G7 → G8, G9 [OR] [FALLBACK(G8, G9)]**

  * **Justification**: The initially assigned robot/team is used first. If it cannot satisfy time constraints, additional robots are added.

* **G8 → AT5 [AND] [sequential]**

  * **Justification**: The system must first try to compute a feasible plan with the assigned robot/team.

* **G9 → AT6 [AND] [sequential]**

  * **Justification**: Additional robots are assigned only if the initial plan is infeasible.

---

## Patient-check execution

* **G10 → G11, G12 [AND] [parallel]**

  * **Justification**: The mission requires both global timing compliance for high-risk patients and completion of all occupied-room checks. The high-risk deadline must be monitored while the room-check workflow is executed.

* **G11 → AT7, AT8 [AND] [sequential]**

  * **Justification**: The system must first prioritize high-risk patients, then monitor whether they are checked within 15 minutes.

* **G12 → G13, G18, G20, G21, G25, G39, G40 [AND] [parallel over rooms, sequential inside each room]**

  * **Justification**: Every occupied-room patient must pass through the full workflow. Different rooms may be handled in parallel by different robots, but each individual patient check follows a safe sequence.

---

## Pre-entry checks

* **G13 → G14, G15, G16, G17 [AND] [(FALLBACK(G14, (G15 ; G14)) ; FALLBACK(G16, G17))]**

  * **Justification**: Availability and battery sufficiency are both mandatory before room entry. If the patient is unavailable, the robot retries after 5 minutes. If battery is insufficient, the robot recharges and tasks are reassigned.

* **G14 → AT9 [AND] [sequential]**
