## Goal Table

| Name | Text | Runtime | Goal Type | Target Condition / Enquired Information | Relation | Justification |
|---|---|---|---|---|---|---|
| G1: Resource Request Fulfilled | The required resources are collected from storage and delivered to the requesting agent at the specified location. | [;] `(G2;G8)` | Achieve | `all requiredResources delivered to requestingAgent at specifiedLocation` | AND | This is the main desired future world state of the mission. |
| G2: Mission Plan Prepared | The system prepares the mission by identifying requirements, determining storage order, and assigning robot resources. | [;] `(G3;G4;G5)` | Achieve | `missionPlan available with requiredResources, storageOrder, robotAllocation` | AND | The mission cannot execute correctly unless all planning information and allocation decisions are available. |
| G3: Mission Requirements Identified | The system identifies the required resources, requesting agent, specified delivery location, and relevant storage places. | [;] `AT1` | Query | `requiredResources, requestingAgent, specifiedLocation, storagePlaces` | AND | This goal enquires mission information before execution. |
| G4: Storage Visit Order Determined | The system determines the order of storage visits using waiting-time estimation plus robot path distance. | [;] `AT2` | Query | `orderedStorageList based on waitingTimeEstimate + pathDistance` | AND | This goal retrieves/calculates information needed to decide the collection order. |
| G5: Robot Allocation Established | The system chooses whether the mission will be performed by one robot or by multiple robots in parallel. | FALLBACK `FALLBACK(G7,G6)` | Achieve | `robotAllocation selected for the mission` | OR | Either a single-robot allocation or a parallel multi-robot allocation is sufficient; parallel allocation is preferred when multiple items are required from different storages. |
| G6: Single Robot Assigned | One robot is assigned to perform the collect-deliver mission. | [;] `AT3` | Achieve | `one assignedRobot responsible for the mission` | AND | This establishes the normal single-robot execution mode described in the mission. |
| G7: Parallel Robots Assigned | Multiple robots are assigned to parallel collect-deliver tasks for different storage/resource subsets. | [;] `(AT4;AT5)` | Achieve | `multiple robots assigned to parallel collectDeliverTasks` | AND | This supports the case where multiple items from different storages can be collected and delivered in parallel to reduce completion time. |
| G8: Resource Transfer Completed | The assigned robot or robots execute the collection phase followed by the delivery phase. | [;] `(G9;G14)` | Achieve | `requiredResources collected and delivered according to missionPlan` | AND | The mission requires both successful collection and successful delivery. |
| G9: Collection Phase Completed | The resources are collected from the storage places, or the collection mission is recovered by reassignment if battery becomes low. | FALLBACK `FALLBACK(G10,G13)` | Achieve | `resources retrieved from storage OR collectionTask reassigned after low battery` | OR | Normal collection is preferred; low-battery recovery is an alternative path that preserves mission continuity. |
| G10: Normal Collection Completed | The assigned robot reaches the required storage places and obtains the requested resources. | [;] `(G11;G12)` | Achieve | `assignedRobot has retrieved requiredResources from storagePlaces` | AND | The collection phase requires reaching storage and then requesting/retrieving the resources. |
| G11: Storage Places Reached | The robot goes to the storage places where the required resources can be found. | [;] `AT6` | Achieve | `assignedRobot located at required storagePlaces` | AND | This goal brings about the required physical position for requesting resources. |
| G12: Resources Requested and Retrieved | The robot requests the resources from storage and waits until they are retrieved. | [;] `(AT7;AT8)` | Achieve | `requestedResources retrieved and available to assignedRobot` | AND | The resource request and waiting step are both necessary before delivery can begin. |
| G13: Collection Low-Battery Recovery Completed | If the robot battery reaches 10% during collection, the robot returns to the recharging station and the mission is assigned to another robot. | [;] `(AT9;AT10)` | Achieve | `lowBatteryRobot at rechargingStation AND mission reassigned to anotherRobot` | AND | This handles the specified collection-phase battery contingency. |
| G14: Delivery Phase Completed | The collected resources are delivered to the specified location, or delivery is recovered when the robot battery becomes low. | FALLBACK `FALLBACK(G15,G16)` | Achieve | `resources delivered OR deliveryRecovery completed` | OR | Normal delivery is preferred; low-battery recovery is used when delivery cannot continue safely. |
| G15: Normal Delivery Completed | The robot makes as many runs as necessary to take all resources to the specified location. | [;] `AT11` | Achieve | `all requiredResources placed at specifiedLocation` | AND | This is the intended final delivery state of the mission. |
| G16: Delivery Low-Battery Recovery Completed | If battery reaches 30% during delivery, the robot returns the resource to a checkpoint and transfers the remaining task, or triggers failure handling if checkpoint return fails. | FALLBACK `FALLBACK(G17,G18)` | Achieve | `resource safely checkpointed and task reassigned OR failure alert/report completed` | OR | The mission defines checkpoint handoff as the preferred recovery and alert/reporting as the fallback when checkpoint return fails. |
| G17: Checkpoint Handoff Completed | The robot returns the resource to a checkpoint and assigns the remaining task to another robot that knows the resource position. | [;] `(AT12;AT13)` | Achieve | `resource positioned at checkpoint AND replacementRobot knows resourcePosition` | AND | Both checkpoint placement and transfer of position knowledge are required for the remaining task to continue. |
| G18: Checkpoint Return Failure Handled | If the robot fails to return the resource to a checkpoint, an alert is triggered and a report is sent to the sector manager. | [;] `(AT14;AT15)` | Achieve | `alert triggered AND report sent to sectorManager` | AND | This achieves the required failure-handling state after checkpoint return failure. |

## Task Table

| Name | Text | Relation | Location | Number of Robots |
|---|---|---|---|---|
| AT1: Read Mission Request | Read the mission request to identify the required resources, requesting agent, specified location, and storage places. | AND | `missionControlSystem` | 1 |
| AT2: Compute Storage Order | Compute the storage visit order using estimated waiting time plus the robot path distance. | AND | `missionControlSystem / hospitalLogisticsMap` | 1 |
| AT3: Assign Single Robot | Assign one robot to execute the full collect-deliver mission. | AND | `missionControlSystem` | 1 |
| AT4: Partition Resource Batches | Divide required items from different storages into parallel collect-deliver task bundles. | AND | `missionControlSystem` | 1 |
| AT5: Assign Parallel Robots | Assign multiple robots to execute the parallel collect-deliver task bundles. | AND | `missionControlSystem / storagePlaces` | `[2,n]` |
| AT6: Navigate to Storage Places | Robot navigates to the storage places where the required resources can be found, following the computed order. | AND | `storagePlaces` | `[1,n]` |
| AT7: Send Resource Request Message | Robot sends a message to the storage with the precise specification of the requested resources. | AND | `currentStorage` | `[1,n]` |
| AT8: Wait for Resource Retrieval | Robot waits until the requested resources have been retrieved by the storage. | AND | `currentStorage` | `[1,n]` |
| AT9: Return to Recharging Station | If battery reaches 10% during collection, the assigned robot returns to the recharging station. | AND | `rechargingStation` | 1 |
| AT10: Reassign Collection Mission | Assign the remaining collection mission to another robot. | AND | `missionControlSystem / rechargingStation` | 1 |
| AT11: Perform Delivery Runs | Robot performs as many runs as necessary to take all resources to the specified location. | AND | `specifiedLocation` | `[1,n]` |
| AT12: Return Resource to Checkpoint | If battery reaches 30% during delivery, robot returns the resource to a checkpoint. | AND | `checkpoint` | 1 |
| AT13: Assign Remaining Delivery Task | Assign the remaining delivery task to another robot and provide the known resource position. | AND | `missionControlSystem / checkpoint` | 1 |
| AT14: Trigger Failure Alert | Trigger an alert when the robot fails to return the resource to a checkpoint. | AND | `robotCurrentLocation / missionControlSystem` | 1 |
| AT15: Send Failure Report | Send the failure report to the sector manager. | AND | `sectorManagerInterface` | 1 |
