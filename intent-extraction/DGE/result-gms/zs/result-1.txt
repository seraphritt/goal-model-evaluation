### Goal nodes

| Name | Text | Runtime | Goal Type | Target Condition / Enquired Information | Relation | Goal Type Justification |
|---|---|---:|---|---|---|---|
| G1: Resource Logistics Mission Handled | Handle the mission so that required resources are collected from storage and delivered to the requesting agent at the specified location, with exception handling when needed. | `[;] (G2 ; G6 ; G9)` | Achieve | Required resources are delivered to the requesting agent at `specified_location`; if delivery checkpoint return fails, the failure is escalated through alert and report. | Root | This is an achieve goal because it describes the desired future mission state: the requested logistics mission is completed or formally escalated. |
| G2: Mission Plan Established | Establish the mission plan by identifying required information, defining the storage visit order, and selecting the robot assignment mode. | `[;] (G3 ; G4 ; G5)` | Achieve | A mission plan exists containing required resources, storage locations, visit order, and robot allocation strategy. | AND | This is an achieve goal because the desired state is that a valid plan has been created before execution. |
| G3: Mission Information Obtained | Obtain the information needed to plan the mission. | `-` | Query | Required resources, requesting agent, `specified_location`, storage places, waiting-time estimates, path estimates, number of items, and whether items are in different storages. | AND | This is a query goal because it retrieves information needed for later decisions and does not directly execute the collection or delivery. |
| G4: Storage Visit Order Established | Define the order in which storage places must be visited according to estimated waiting time plus robot path length. | `[;] (AT1 ; AT2)` | Achieve | An ordered list of `storage_places` is available for the robot or robot team. | AND | This is an achieve goal because the intended outcome is a planned storage sequence. |
| G5: Robot Assignment Mode Established | Select whether the mission is executed by one robot or by multiple robots in parallel collect-deliver tasks. | `FALLBACK(AT3, AT4)` | Achieve | A robot assignment strategy is selected: parallel assignment when multiple items from different storages allow it; otherwise single-robot assignment. | AND | This is an achieve goal because the system must reach a decision state about how many robots will execute the mission. |
| G6: Collection Phase Completed | Complete the collection phase so that the requested resources are retrieved from the relevant storage places. | `FALLBACK(G7, G8)` | Achieve | Required resources are retrieved and ready for delivery, either by the initially assigned robot or by a replacement robot after low battery. | AND | This is an achieve goal because the target state is that resources have been collected. |
| G7: Normal Collection Procedure Performed | Execute the normal collection procedure with the assigned robot. | `[;] (AT5 ; AT6 ; AT7 ; AT8)` | Perform | N/A | OR | This is a perform goal because the description specifies concrete activities: go to storage, send a request message, wait, and confirm retrieval. |
| G8: Collection Low-Battery Reassignment Completed | Handle a collection-phase low-battery event by sending the robot to recharge and assigning the mission to another robot. | `[;] (AT9 ; AT10 ; AT11)` | Achieve | When battery reaches 10% during collection, the original robot reaches `recharging_station`, another robot is assigned, and collection continues. | OR | This is an achieve goal because it describes a required recovery state after a low-battery event. |
| G9: Delivery Phase Handled | Deliver the collected resources to the specified location or execute the defined delivery-failure handling procedure. | `FALLBACK(G10, FALLBACK(G11, G13))` | Achieve | Resources are delivered to `specified_location`, or delivery low-battery handling is completed, or checkpoint failure is escalated. | AND | This is an achieve goal because it defines the intended end state of the delivery phase and its exception alternatives. |
| G10: Normal Delivery Runs Performed | Perform as many delivery runs as necessary to move all collected resources to the specified location. | `[;] (AT12)` | Perform | N/A | OR | This is a perform goal because the mission description specifies repeated delivery runs as the required activity. |
| G11: Delivery Low-Battery Handoff Completed | Handle a delivery-phase low-battery event by returning the resource to a checkpoint and assigning the remaining task to another robot. | `[;] (AT13 ; AT14 ; G12)` | Achieve | When battery reaches 30% during delivery, the resource is placed at `checkpoint`, the remaining task is reassigned, and the replacement robot knows the resource position. | OR | This is an achieve goal because the desired state is a successful handoff that allows the mission to continue. |
| G12: Remaining Delivery Completed by Replacement Robot | Complete the remaining delivery after the resource has been positioned at the checkpoint. | `[;] (AT15)` | Achieve | The replacement robot retrieves the resource from `checkpoint` and delivers it to `specified_location`. | AND | This is an achieve goal because the target condition is that the remaining resources reach the specified location. |
| G13: Checkpoint Failure Escalated | Escalate the mission when the robot fails to return the resource to a checkpoint. | `[;] (AT16 ; AT17)` | Perform | N/A | OR | This is a perform goal because the required response is to execute specific actions: trigger an alert and send a report. |

### Task nodes

| Name | Text | Relation | Location | Number of Robots |
|---|---|---|---|---:|
| AT1: Estimate Waiting and Path Cost | Estimate waiting time at each storage and the path to be run by the robot. | AND | `robot_current_location`, `storage_places` | 1 |
| AT2: Define Storage Visit Order | Define the storage visit order using waiting-time estimate plus path length. | AND | `storage_places` | 1 |
| AT3: Assign Multiple Robots to Parallel Tasks | Assign multiple robots to parallel collect-deliver tasks when multiple items are required from different storages. | OR | `storage_places`, `specified_location` | `[2,n]` |
| AT4: Assign Single Robot to Mission | Assign one robot to perform the collection and delivery mission when parallelization is not applicable. | OR | `robot_current_location` | 1 |
| AT5: Navigate to Storage Places | The assigned robot goes to the storage places where the resources can be found. | AND | `storage_places` | `[1,n]` |
| AT6: Send Resource Request Message | The robot sends a message to the storage with the precise specification of the requested resources. | AND | `storage_places` | `[1,n]` |
| AT7: Wait for Resource Retrieval | The robot waits until the requested resources have been retrieved by the storage. | AND | `storage_places` | `[1,n]` |
| AT8: Confirm Resources Retrieved | Confirm that the requested resources have been retrieved and are ready for delivery. | AND | `storage_places` | `[1,n]` |
| AT9: Return to Recharging Station | If battery reaches 10% during collection, the assigned robot returns to the recharging station. | AND | `recharging_station` | 1 |
| AT10: Assign Mission to Another Robot | Assign the remaining collection mission to another robot. | AND | `fleet_management_system` | 1 |
| AT11: Continue Collection by Replacement Robot | The replacement robot continues the remaining collection work. | AND | `storage_places` | 1 |
| AT12: Execute Delivery Runs | The robot makes as many runs as necessary to deliver all resources to the specified location. | AND | `specified_location` | `[1,n]` |
| AT13: Return Resource to Checkpoint | If battery reaches 30% during delivery, the robot returns the resource to a checkpoint. | AND | `checkpoint` | 1 |
| AT14: Assign Remaining Task to Another Robot | Assign the remaining delivery task to another robot and provide the resource position. | AND | `fleet_management_system`, `checkpoint` | 1 |
| AT15: Retrieve from Checkpoint and Complete Delivery | The replacement robot retrieves the resource from the checkpoint and delivers it to the specified location. | AND | `checkpoint`, `specified_location` | 1 |
| AT16: Trigger Alert | Trigger an alert when the robot fails to return the resource to a checkpoint. | AND | `robot_current_location`, `checkpoint` | 1 |
| AT17: Send Report to Sector Manager | Send a failure report to the sector manager. | AND | `sector_manager_interface` | 1 |
