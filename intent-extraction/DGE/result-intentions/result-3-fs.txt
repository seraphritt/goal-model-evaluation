| “collect the required resources in the storage and deliver them to the requesting agent in a specified location” | Goal | This describes the desired end state of the mission: the required resources are obtained and delivered to the requesting agent. It states what must be achieved, not only one internal step. |
| “the required resources” | Resource | This is a physical or informational entity whose availability is central to the mission. The robot must collect and deliver these resources. |
| “storage” | Resource | The storage is an entity/location that must be available because it contains the required resources. |
| “requesting agent” | Resource | The requesting agent is an entity involved in the mission and must be available as the recipient of the delivered resources. |
| “specified location” | Resource | The specified location is an entity/place required for completing the delivery. Its availability and identification matter to the mission. |
| “go to the storage places where the resources can be found” | Task | This specifies a concrete action the robot performs during the collection phase. It is a particular way of achieving resource collection. |

| “estimation of waiting time” | Resource | This is informational data used to decide the order of collection. Its availability is important for route planning. |
| “path to be run by the robot” | Resource | This is route/path information needed by the robot to plan and execute movement between locations. |
| “sends a message to the storage with the precise specification of the requested resources” | Task | This is a specific communication action required to request the resources from storage. |
| “precise specification of the requested resources” | Resource | This is informational content required for the storage to retrieve the correct resources. |
| “waits until the resources have been retrieved” | Task | This defines a concrete behavior of the robot after requesting resources: waiting until retrieval is complete. |
| “the resources have been retrieved” | Goal | This represents a desired state in the collection phase: the resources are available after retrieval. |
| “the delivery phase begins” | Task | This indicates the start of a specific process after collection. It structures the mission execution into phases. |
| “make as many runs as necessary to take all the resources to the specified location” | Task | This specifies a concrete method for delivering all resources, including repeated trips when needed. |
| “all the resources to the specified location” | Goal | This expresses the desired final delivery state: all resources are at the specified location. |
| “battery of the assigned robot” | Resource | The robot battery is a physical resource whose availability determines whether the assigned robot can continue the mission. |
| “goes back to the recharging station” | Task | This specifies a concrete recovery action when the robot battery is low during collection. |
| “recharging station” | Resource | The recharging station is a physical entity required for restoring the robot’s battery. |
| “assigns the mission to another robot” | Task | This is a specific delegation action used when the assigned robot cannot continue the collection phase. |
| “another robot” | Resource | Another robot is an available physical/agent resource that can continue the mission. |
| “return the resource to a checkpoint” | Task | This is a concrete action required when the robot battery is low during the delivery phase. |
| “checkpoint” | Resource | The checkpoint is a location/entity where resources can be placed temporarily, so its availability is important. |

| “report” | Resource | The report is an informational entity that must be generated and made available to the sector manager. |
| “sector manager” | Resource | The sector manager is an entity that receives the report and is involved in failure handling. |
| “multiple robots can be assigned to parallel collect-deliver tasks” | Task | This specifies a particular operational strategy for executing the mission using multiple robots in parallel. |
