### Logical Relationships

```
G1 -> G2, G3, G4, G5, G6 [AND][;]   // sequential execution of main sub‑goals
G2 -> AT10 [AND][-]                 // acquire food
G3 -> AT9  [AND][-]                 // transport food
G4 -> G4.1, G4.4 [AND][;]           // query then choose delivery method
G4.1 -> (query result)              // no task, leaf
G4.4 -> G4.2, G4.3 [OR][FALLBACK(G4.2,G4.3)]
G4.2 -> AT11, AT4, AT3, AT5, AT6 [AND][;]   // deliver to tray + manage retrieval
G4.3 -> AT12 [AND][-]               // deliver to table
G5 -> AT14 [AND][-]                 // retrieve dishes
G6 -> AT13 [AND][-]                 // open door
```

**Notes**

* The `FALLBACK(G4.2,G4.3)` operator captures the decision logic: if delivering to the tray fails (e.g., patient cannot retrieve), the robot falls back to delivering to the table.
* All `AND` relations indicate that the child goals/tasks must all succeed for the parent to succeed.
* The `;` runtime operator enforces sequential execution of the child goals/tasks.
* The `-` runtime operator marks leaf goals/tasks that have no further decomposition.
