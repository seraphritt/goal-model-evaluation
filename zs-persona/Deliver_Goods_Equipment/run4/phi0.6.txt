### Summary of Logical Relationships

- **G1 → G2 ; G3**  
  The overall mission (G1) is achieved by first executing the collection phase (G2) and then the delivery phase (G3) in sequence.

- **G2 → FALLBACK(G2.1, G2.2)**  
  Within resource collection, normal collection (G2.1) is attempted; if the battery falls below 10%, the fallback (G2.2) is activated to recharge and reassign the mission.

- **G3 → FALLBACK(G3.1, G3.2)**  
  In the delivery phase, normal delivery (G3.1) is the default; if the battery falls below 30%, the fallback (G3.2) is used to return the resource to a checkpoint and reassign the task.

- **G3.2 → FALLBACK(G3.2.1, G3.2.2)**  
  Within the battery recovery branch for delivery, the system first attempts to return the resource to the checkpoint (G3.2.1). If that fails, it triggers an alert and sends a report (G3.2.2).

- **G2.1 → AT1 ; AT2 ; AT3**  
  The normal collection branch is executed by sequentially performing the tasks: navigating to storage, requesting the resource, and waiting for retrieval.

- **G2.2 → AT4 ; AT5 ; AT6**  
  The battery recovery collection branch is executed by navigating to the recharging station, recharging, and reassigning the mission.

- **G3.1 → AT7 ; AT8**  
  The normal delivery branch is executed by navigating to the delivery location and delivering the resource.

- **G3.2.1 → AT9 ; AT10 ; AT11**  
  The checkpoint recovery branch is executed by navigating to the checkpoint, returning the resource, and reassigning the remaining delivery task.

- **G3.2.2 → AT12**  
  If checkpoint recovery fails, the alert task is executed.

*Additionally, when multiple items are required from different storages, the execution of G2.1 and G3.1 can be performed in parallel by different robots to optimize mission time.*
