Summary of Logical Relationships
──────────────────────────────
- **G1 -> G2, G3**  
  - Relation: AND  
  - Execution: Sequential (G2 ; G3)

- **G2 -> G2.1, G2.2**  
  - Relation: OR  
  - Execution: Fallback (FALLBACK(G2.1, G2.2))  
  - (Either perform the normal collection task or, if battery is low, execute the battery check routine.)

- **G2.1 -> AT1, AT2, AT3**  
  - Relation: AND  
  - Execution: Sequential (AT1 ; AT2 ; AT3)

- **G2.2 -> AT4, AT5**  
  - Relation: AND  
  - Execution: Sequential (AT4 ; AT5)

- **G3 -> G3.1, G3.2**  
  - Relation: OR  
  - Execution: Fallback (FALLBACK(G3.1, G3.2))  
  - (Either perform the normal delivery task or, if battery is low, execute the battery check routine.)

- **G3.1 -> AT6, AT7**  
  - Relation: AND  
  - Execution: Sequential (AT6 ; AT7)

- **G3.2 -> AT8, AT9, AT10**  
  - Relation: OR  
  - Execution: Fallback (FALLBACK(AT8 ; AT9, AT10))  
  - (Either return the resource to a checkpoint and reassign the task, or if that fails, trigger an alert.)

Additional Note:
──────────────────────────────
When multiple items are required from different storages, the mission execution (G1) could be extended to allow parallel execution of multiple collection–delivery branches. This can be modeled by assigning multiple robots to execute the G2 and G3 branches in parallel (using the parallel operator “#”).
