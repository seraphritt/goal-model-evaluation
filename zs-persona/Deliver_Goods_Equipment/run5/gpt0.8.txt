**Goal Model – Multi‑Robot Resource Delivery**

| **Name**                            | **Text**                                                                                                                        | **Runtime**                                                    | **Goal Type** | **Target Condition / Enquired Info** | **Relation** | **Ground truth I** | **Ground truth C** | **Ground truth E** |

| **G1: Deliver Requested Resources** | Ensure that the requested resources are collected from storage and delivered to the requesting agent at the specified location. | `;` (sequential – first collect, then deliver)                 | Perform       | –                                    | AND          |                    |                    |                    |

### Task Nodes

| **Name** | **Text** | **Relation** | **Location** | **Number of Robots** |
|----------|----------|--------------|--------------|----------------------|
| **AT1: Navigate to Storage** | Robot moves to the storage location that holds the requested resource. | AND | Storage | 1 |
| **AT2: Send Request Message to Storage** | Robot sends a message to the storage specifying the exact resources needed. | AND | Storage | 1 |
| **AT3: Wait for Retrieval** | Robot waits until the storage retrieves and hands over the resources. | AND | Storage | 1 |
| **AT4: Return to Recharge & Reassign Mission** | If battery falls below 10 % during collection, robot returns to the recharge station and assigns the remaining collection task to another robot. | AND | Recharge Station | 1 |
| **AT5: Transport Resource to Requester** | Robot carries the collected resources to the requester’s location. | AND | Requester | 1 |
| **AT6: Return Resource to Checkpoint (Battery ≤ 30 %)** | If battery falls below 30 % during delivery, robot returns the resource to the nearest checkpoint. | AND | Checkpoint | 1 |
| **AT7: Assign Remaining Delivery Task to Another Robot** | After returning to a checkpoint, the robot assigns the remaining delivery task to another robot. | AND | Checkpoint | 1 |
| **AT8: Trigger Alert to Sector Manager** | If the robot fails to return the resource to a checkpoint, an alert is triggered and a report is sent to the sector manager. | AND | Sector Manager | 1 |

### Logical Relationships

- **G1 → G2, G3** [AND][sequential]  
  *First the collection phase (G2) must finish, then the delivery phase (G3).*

- **G2 → AT1, AT2, AT3, AT4** [AND][parallel]  
  *All collection‑related tasks must be satisfied; AT4 is activated only when battery < 10 %.*

- **G3 → AT5, AT6, AT7, AT8** [AND][parallel]  
  *All delivery‑related tasks must be satisfied; AT6, AT7, and AT8 are activated only when battery < 30 % or a checkpoint return fails.*

These tables and relationships provide a complete, depth‑first decomposition of the mission into goals and executable tasks suitable for a multi‑robot system.
