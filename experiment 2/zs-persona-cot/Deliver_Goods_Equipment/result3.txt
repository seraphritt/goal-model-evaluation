Below is a **goal-model decomposition** for the hospital food-delivery and dirty-dish-retrieval mission. I model **intentional objectives as goals** and **directly executable robot operations as tasks**.

## 1. Main modeling rationale

The mission has two major service objectives:

1. **Deliver food from kitchen to inpatient room**, triggered by kitchen delivery requests.
2. **Retrieve dirty dishes from the room**, triggered after meal consumption or by someone in the room calling a robot.

The main uncertainty points are:

* Whether the inpatient can fetch food from the robot tray.
* Whether a companion is present and able to help.
* Whether a nurse is available.
* Whether another robot is available for cooperation.
* Whether the door can be opened by a human or requires robot cooperation.
* Whether the correct meal is retrieved when the robot carries multiple meals.

Because of these alternatives, several parts of the model use **OR decomposition** and **FALLBACK runtime annotations**.

# 5. Logical relationships and justifications

## Main service level

**G1 -> G2, G20 [AND] [sequential: `G2 ; G20`]**

* **Justification**: The complete service includes both delivering the meal and retrieving dirty dishes. Dirty dishes are retrieved after food delivery, so a sequential relation is appropriate.

---

## Food delivery branch

**G2 -> G3, G4, G5, G7 [AND] [sequential: `G3 ; G4 ; G5 ; G7`]**

* **Justification**: A delivery request cannot be fulfilled unless the robot knows the order/context, collects the food, reaches the room, and completes the handover.

**G3 -> AT1, AT2, AT3 [AND] [parallel: `AT1 # AT2 # AT3`]**

* **Justification**: The robot needs kitchen request data, patient data, and companion presence data. These are all required but can be obtained independently.

**G4 -> AT4, AT5 [AND] [sequential: `AT4 ; AT5`]**

* **Justification**: The robot must first go to the kitchen pickup area and then load the requested meals.

**G5 -> AT6, G6 [AND] [sequential: `AT6 ; G6`]**

* **Justification**: The robot must navigate to the room before opening or requesting the opening of the door.

**G6 -> AT7, AT8 [OR] [fallback: `FALLBACK(AT7, AT8)`]**

* **Justification**: The door can be opened by a human or with help from another robot. One successful alternative is enough.

**G7 -> G8, G12 [OR] [fallback: `FALLBACK(G8, G12)`]**

* **Justification**: Food can be delivered directly to the table or fetched from the tray. Table placement is modeled first because it avoids depending on patient, companion, or nurse availability, but it requires manipulation skill.

**G8 -> AT9, AT10, AT11 [AND] [sequential: `AT9 ; AT10 ; AT11`]**

* **Justification**: Direct table delivery requires verifying manipulation capability, placing the meal, and recording the delivery.

**G12 -> G13, G18 [AND] [sequential: `G13 ; G18`]**

* **Justification**: Tray retrieval requires both a retrieval actor and monitoring/recording to ensure the correct meal was retrieved.

**G13 -> G14, G15, G16, G17 [OR] [fallback: `FALLBACK(G14, FALLBACK(G15, FALLBACK(G16, G17)))`]**

* **Justification**: The meal can be fetched by the inpatient, companion, nurse, or another robot. Because human availability and capability are uncertain, fallback is appropriate.

**G14 -> AT12, AT13 [AND] [sequential: `AT12 ; AT13`]**

* **Justification**: The robot must indicate the correct meal before the inpatient retrieves it.

**G15 -> AT14, AT15 [AND] [sequential: `AT14 ; AT15`]**

* **Justification**: The companion must know which meal belongs to the inpatient before retrieving it.

**G16 -> AT16, AT17 [AND] [sequential: `AT16 ; AT17`]**

* **Justification**: A nurse can retrieve the meal, but the robot must first communicate the correct meal identity.

**G17 -> AT18, AT19 [AND] [sequential: `AT18 ; AT19`]**

* **Justification**: Robot-to-robot retrieval requires coordination and then physical transfer.

**G18 -> AT20, AT21, AT22 [AND] [sequential: `AT20 ; AT21 ; AT22`]**

* **Justification**: The robot must monitor which meal was retrieved, record when and where retrieval happened, and alert if a wrong meal was taken.

---

## Dirty-dish retrieval branch

**G20 -> G21, G22, G24, G28 [AND] [sequential: `G21 ; G22 ; G24 ; G28`]**

* **Justification**: Dish retrieval requires knowing the pickup context, reaching the room, collecting dishes, and returning them to the cleaning area.

**G21 -> AT23, AT24 [AND] [parallel: `AT23 # AT24`]**

* **Justification**: The pickup request and door-opening information are both needed. They can be received together from the person calling the robot.

**G22 -> AT25, G23 [AND] [sequential: `AT25 ; G23`]**

* **Justification**: The robot must navigate to the pickup room before the door-opening strategy can be executed.

**G23 -> AT26, AT27 [OR] [fallback: `FALLBACK(AT26, AT27)`]**

* **Justification**: If a human can open the door, that is sufficient. Otherwise, another robot may cooperate.

**G24 -> G25, G26, G27 [OR] [fallback: `FALLBACK(G25, FALLBACK(G26, G27))`]**

* **Justification**: Dirty dishes may be retrieved unassisted, by two robots, or by robot-human cooperation. Any one successful collection mode satisfies the parent goal.

**G25 -> AT28, AT29 [AND] [sequential: `AT28 ; AT29`]**

* **Justification**: The robot must first detect the dishes and then pick them up.

**G26 -> AT30, AT31, AT32 [AND] [`AT30 # AT31 ; AT32`]**

* **Justification**: Two robots can position themselves in parallel, then jointly transfer or collect the dishes.

**G27 -> AT33, AT34 [AND] [sequential: `AT33 ; AT34`]**

* **Justification**: Human-robot cooperation requires requesting human help and then receiving or collecting the dishes.

**G28 -> AT35, AT36 [AND] [sequential: `AT35 ; AT36`]**

* **Justification**: After collection, the robot must transport the dirty dishes and deposit them at the proper cleaning or dish-return location.
