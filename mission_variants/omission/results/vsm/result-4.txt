# Mission Goal Model — Hospital Multi-Robot Vital Signs Check

## 1. Step-by-Step Reasoning

**Step 1 — Identify the mission-level contingency structure.**
The last two sentences ("Additional robots can be assigned... if no combination of robots can complete the mission, the manager must be alerted") describe a *degradation path*: try with the assigned robot(s) → if infeasible, add robots → if still infeasible, escalate to a human. This is a textbook nested **FALLBACK**, and since FALLBACK pairs are always AND-connected, the top goal is AND-decomposed into the normal execution path and the two escalation actions.

**Step 2 — Separate "visit" from "check."** The description layers two concerns: (a) *scheduling* (visit every occupied room, with high-risk patients prioritized in the first 15 minutes) and (b) *the per-room procedure* (identify → check availability/battery → enter → introduce → collect vitals → clean → finish). I modeled (a) as a scheduling task that precedes a reusable "Check Room" goal subtree, and (b) as the deep hierarchy under "Check Room."

**Step 3 — Classify every IF-statement.** The mission has four explicit conditionals: patient unavailable → wait 5 min; insufficient battery → recharge & reassign; vital-sign collection fails → ask assessment questions; mission infeasible → add robots → alert manager. All four are **FALLBACK** by the rubric (explicit primary attempt + explicit failure-triggered alternative). I did **not** use fallback for the infectious/post-surgical/diabetes condition split, because that's not a failure-triggered alternative — it's a context-dependent applicability rule, so I modeled it as **OR** (the applicable branch(es) are sufficient, and more than one can be executed if the patient has multiple conditions).

**Step 4 — Decide parallel vs. sequential.** Wherever the text joins actions with "and" but gives no explicit order (pre-entry checks; the four infectious-disease vitals; recharge + reassign), I used **parallel (#)**. Wherever the text narrates a clear temporal progression (approach → announce → instruct; mark done → proceed; high-risk first → then the rest), I used **sequential (;)**.

**Step 5 — Avoid redundancy.** "Heart rate" and "blood oxygenation" are required both for infectious-disease and post-surgical patients. Rather than creating duplicate task nodes, I defined `AT12 (Check Heart Rate)` and `AT15 (Check Blood Oxygenation)` once and reused them as children under both condition branches.

**Step 6 — Goal typing.** I classified a goal as **Query** whenever its core intent is to obtain information with no mandatory physical action (identify patient, check vitals values), **Perform** whenever its intent is to execute a prescribed action sequence with no interesting target state (announce/instruct, recharge+reassign, mark-done+proceed, infectious protocol incl. sterilization), and **Achieve** whenever there is a clear target condition the robot plans/acts toward, especially ones involving a fallback/retry (ensure availability, ensure battery, ensure vitals collected).

**Step 7 — Locations and robot counts.** The description only names two locations: the **room** and the **hospital** (site). I never invented a "charging station" or similar. Almost every action is performed by a single robot ("the robot" is singular throughout); the only task with a variable count is "Assign Additional Robots," since the mission explicitly allows a variable number of extra robots to be mobilized.

**Step 8 — Pruning.** I did not create a node for "hospital rooms may have one or more beds" (it's a justification/fact, not an action) nor for "patients subject to X disease" classifications alone (they are routing conditions, captured in the OR-split and in justifications, not standalone zero-robot goals).

## 5. Logical Relationships

- **G1 -> G2, AT22, AT23 [AND] FALLBACK(FALLBACK(G2, AT22), AT23)**
  - **Justification**: The normal mission plan (G2) is attempted first; if it cannot complete in time, additional robots are mobilized (AT22); if that still fails, the manager is alerted (AT23) — a nested, two-stage escalation explicitly described in the text.

- **G2 -> AT1, G3 [AND] (sequential)**
  - **Justification**: High-risk rooms must be scheduled/checked within the first 15 minutes before the general room-visiting process continues — explicit temporal priority.

- **G3 -> G4, G10, G18 [AND] (sequential)**
  - **Justification**: "Before entering... once inside... once checked, proceed" gives an explicit three-phase order.

- **G4 -> G5, G8 [AND] (parallel)**
  - **Justification**: Availability and battery checks are joined by "and" with no stated order.

- **G5 -> G6, AT5 [AND] FALLBACK(G6, AT5)**
  - **Justification**: Explicit IF-failure ("If the patient is not available...") triggers the 5-minute retry.

- **G6 -> G7, AT4 [AND] (sequential)**
  - **Justification**: The patient must be identified before their specific availability can be checked (multi-bed rooms).

- **G7 -> AT2, AT3 [OR] (parallel)**
  - **Justification**: "Either by asking or by scanning the barcode" — one method is sufficient, no order given.

- **G8 -> AT6, G9 [AND] FALLBACK(AT6, G9)**
  - **Justification**: Explicit IF-failure ("If there is not enough battery...") triggers recharge/reassignment.

- **G9 -> AT7, AT8 [AND] (parallel)**
  - **Justification**: Recharging and reassignment are both mandated with no stated order; they can proceed concurrently (robot recharges while others take over its tasks).

- **G10 -> G11, G12 [AND] (sequential)**
  - **Justification**: The patient must be introduced to the procedure before vitals are collected — explicit order ("Once inside the room... approach... announce... provide instructions," then vitals).

- **G11 -> AT9, AT10, AT11 [AND] (sequential)**
  - **Justification**: The three actions are explicitly listed left-to-right in the text as a narrative sequence.

- **G12 -> G13, AT19 [AND] (sequential)**
  - **Justification**: Actuator disinfection is explicitly a post-contact action ("afterwards"), occurring after vital-sign collection attempts conclude.

- **G13 -> G14, AT18 [AND] FALLBACK(G14, AT18)**
  - **Justification**: Explicit failure trigger — "The failure of collecting any necessary vital signs should trigger a set of questions."

- **G14 -> G15, G17, AT17 [OR] (parallel)**
  - **Justification**: Which vitals are required depends on the patient's condition(s) (infectious disease, post-surgical, diabetes); these are not strict alternatives for every patient but context-dependent, non-exclusive branches, best captured as OR with no stated order among them.

- **G15 -> G16, AT16 [AND] (sequential)**
  - **Justification**: Sterilization explicitly happens upon exiting the room, after the infectious-disease vitals have been collected.

- **G16 -> AT12, AT13, AT14, AT15 [AND] (parallel)**
  - **Justification**: "Must be checked for heart rate, blood pressure, body temperature, and blood oxygenation" — fully conjunctive, no order stated.

- **G17 -> AT12, AT15 [AND] (parallel)**
  - **Justification**: "Must be checked for heart rate and blood oxygenation" — conjunctive, no order stated; reuses AT12/AT15 to avoid redundant task definitions.

- **G18 -> AT20, AT21 [AND] (sequential)**
  - **Justification**: "Mark it as done **and** proceed to the next room" — explicit completion-then-movement order.

### Key modeling notes / assumptions
- **Shared leaf tasks**: AT12 (Heart Rate) and AT15 (Blood Oxygenation) each have two parents (G16 and G17) to honor the "avoid redundancy" rule rather than duplicating identical task nodes.
- **No invented locations**: only "Room" and "Hospital" are used, since these are the only locations explicitly present in the mission text (recharging, reassignment, alerting, and additional-robot assignment are treated as hospital-wide/system-level rather than tied to an unstated "charging station" or "control room").
- **Variable robot count**: only AT22 (Assign Additional Robots) uses a range `[1, n]`, since it is the only task where the mission text explicitly allows a variable number of robots; every other task is performed by the singular "the robot" referenced throughout the text.
- **Zero-robot pruning**: facts used only as justification (e.g., "hospital rooms may have one or more beds," the disease-category definitions themselves) were not turned into goal/task nodes, since they describe context/reasons rather than robot-performed actions.
