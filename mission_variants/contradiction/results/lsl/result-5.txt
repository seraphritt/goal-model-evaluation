# Goal Model Analysis: Lab Sample Transport Multi-Robot System

## Step 1 — Identifying Agents and Excluding Zero-Robot Actions

Before decomposing, I scanned the description for every actor and flagged which ones are robots vs. humans, since **goals/tasks performed by zero robots must be dropped**:

| Mentioned action | Actor | Robot? | Decision |
|---|---|---|---|
| "A nurse ... can request a delivery" | Nurse | ❌ Human | Excluded (trigger only, not modeled as a node) |
| "Each sample ... is identified with a barcode" (before collection) | Nurse (implicit) | ❌ Human | Excluded |
| "The nurse inserts data ... in a track system" | Nurse | ❌ Human | Excluded |
| "Only laboratory personnel may unload the sample from the transport drawer" | Lab personnel | ❌ Human | Excluded (but its *effect* constrains where the robotic arm may pick up — see AT4 justification) |
| Drawer conveyance | **Transport robot** (named explicitly later: "the transport robot") | ✅ Robot | Modeled (G2) |
| Drawer unlocking "by specific robots in specific locations" | Transport robot, at the laboratory (the only robot + location explicitly tied to the drawer) | ✅ Robot | Modeled (G2/AT3) — see assumption below |
| "The robotic arm picks up, scans, sorts, loads" | **Robotic arm** | ✅ Robot | Modeled (G3) |
| Logging pickup location/time; tracking transit time | Attributed to the transport robot's onboard system (only robot present at both collection and delivery) | ✅ Robot (assumption) | Modeled (G2/G4) |

**Key assumption flagged explicitly:** The description never names which robot/location the phrase *"specific robots in specific locations should be able to open the locked drawers"* refers to. The only robot explicitly tied to the drawer and to a named location is the **transport robot** at the **laboratory**. I therefore interpret this as: the transport robot is permitted to unlock the drawer only upon reaching the laboratory, after which lab personnel (human, excluded) physically unload it — which is also consistent with, and explains, the constraint *"the robotic arm must never receive a sample directly from the transport robot."*

## Step 2 — No Fallback Relations

I looked for explicit conditionals ("if X fails, do Y", exceptions, thresholds triggering an alternative path). **None exist in this description** — there is no stated failure-handling behavior. Therefore **FALLBACK is not used anywhere** in this model; all runtime annotations are Sequential (`;`) or Parallel (`#`).

## Step 3 — High-Level Decomposition Logic

The mission naturally splits into three **jointly necessary** (AND) concerns, each matching one paragraph-cluster of the description:
- **G2 – Transport** (drawer, locking, conveyance)
- **G3 – Lab Processing** (robotic arm: pick/scan/sort/load)
- **G4 – Compliance Monitoring** (logging + time tracking)

G2 must finish before G3 can start (explicit real-world ordering — sample must arrive before being processed) → **sequential**. G4 spans the *entire* journey (collection → delivery) and runs alongside the G2→G3 sequence rather than waiting for it → **parallel**.

## Logical Relationships

- **G1 -> G2, G3, G4 [AND] [(G2;G3)#G4]**
  - **Justification**: All three are jointly required — secure transport, lab processing, and compliance monitoring are complementary, not alternatives, so AND. G2 must complete before G3 (sample must physically arrive before the robotic arm can process it) — explicit temporal order in the text — hence sequential. G4 spans the whole collection-to-delivery window and is not blocked on G3 finishing, so it runs in parallel with the (G2;G3) sequence.

- **G2 -> AT1, AT2, AT3 [AND] (sequential)**
  - **Justification**: All three steps are necessary for "secure transport" to be achieved (AND). Logging the pickup (AT1) happens at the moment of pickup, before conveyance (AT2) begins; the drawer is only unlocked (AT3) once the robot *arrives* at the laboratory — an explicit chronological chain, hence sequential.

- **G3 -> AT4, AT5, AT6, AT7 [AND] (sequential)**
  - **Justification**: The description lists these in a fixed order — "picks up samples, scans the barcode ..., sorts, and loads" — and all four actions are required for the sample to reach the entry-module, so AND + sequential.

- **G4 -> AT8, AT9 [AND] (sequential)**
  - **Justification**: Both steps are required to fulfill the protocol-compliance intent (AND). Timestamps (AT8) must be recorded before an elapsed-time comparison against the protocol threshold (AT9) can be computed, so sequential.
