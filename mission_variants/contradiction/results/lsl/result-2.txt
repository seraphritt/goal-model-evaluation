## Logical Relationships

- **G1 -> G2, G6 [AND] (sequential: G2;G6)**
  - **Justification**: The sample must physically arrive at the laboratory (G2) before the robotic arm can process it (G6); the text's own structure moves from floor-to-lab transport to in-lab handling in that order, and both phases are mandatory (AND) for the sample to reach the analysis machine.

- **G2 -> G3, G4, G5 [AND] ((G3;G4)#G5)**
  - **Justification**: Securing the sample in the drawer (G3) must happen before it is carried (G4) — you cannot transport what isn't yet loaded and locked. Tracking the transit time (G5) is a continuous monitoring activity that runs alongside the whole collection-to-delivery window, so it is modeled in parallel (#) with the G3;G4 sequence rather than sequentially after it.

- **G3 -> AT1, AT2 [AND] (sequential: AT1;AT2)**
  - **Justification**: The drawer must be opened before the sample can be loaded and the drawer re-locked; both actions are required (AND) and occur strictly in this order.

- **G6 -> G7, G9, G10, G11 [AND] (sequential: G7;G9;G10;G11)**
  - **Justification**: The mission description lists the robotic arm's actions explicitly in order — "picks up samples, scans the barcode in each sample, sorts, and loads the samples" — which is a direct textual indication of sequential execution. All four are mandatory (AND), since skipping any one (e.g., not identifying or not sorting) would leave the sample unprocessed.

- **G7 -> AT5, G8 [AND] (sequential: AT5;G8)**
  - **Justification**: A pick-up event must occur before it can be logged ("where and when a given sample was picked" presupposes the pick-up already happened); both the action and the logging are required.

- **G4 -> AT3 [AND] (single child)**
  - **Justification**: Only one concrete action fulfills "carry the sample to the laboratory," performed by one transport robot.

- **G5 -> AT4, G8 -> AT6, G9 -> AT7, G10 -> AT8, G11 -> AT9 [AND] (single-child relations)**
  - **Justification**: Each of these goals maps to exactly one concrete, operational action described in the text (recording timestamps, scanning, sorting, loading), so the single task fully satisfies the goal.

No **OR** decompositions were used anywhere, since the mission description never presents true alternative ways of fulfilling a robot-performed goal — the only "or" in the text ("authorized personnel **or** specific robots") is a choice of *agent*, not an alternative goal path, and the human-performed branch is excluded under the zero-robot rule. No **FALLBACK** relations were used either, since the text never describes a failure, exception, or conditional alternative behavior ("if X fails, do Y") for any robot action — only a fixed, expected order of events, which is why sequential (`;`) was used instead.
