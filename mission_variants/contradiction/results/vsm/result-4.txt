# Goal Model — Hospital Vital‑Signs Checking Mission

Before the tables, a few modeling decisions I made while reading the description — these affect several nodes below, so I'm flagging them once instead of repeating them in every row.

**Modeling notes & assumptions**

- **Consolidated tables, not one table per node.** With 23 goals and 25 tasks, one physical table per node would be unreadable. I built one Goals table and one Tasks table, each row containing every column the spec requires for that node type.
- **Leaf goals get `-` for Runtime *and* Relation.** A goal that maps to a single realizing task isn't actually "decomposed" (decomposition requires ≥2 children), so I treat it the same way the spec treats leaf tasks: `-` / `-`. The link to its one task is still listed in the Logical Relationships section.
- **Locations.** The description only ever names "room" (hospital rooms), the "hospital" setting, and "the site" (for the manager). I did not invent locations like "charging station" or "corridor" — recharge/reassignment/robot‑addition are generalized to **Hospital**, and the manager alert uses **Site** (the exact word used in that sentence).
- **Reused task names.** "Measure Heart Rate" and "Measure Blood Oxygenation" appear once under the infectious‑disease branch and once under the post‑surgical branch. They're the *same physical action*, duplicated as leaves because a tree can't share one node under two parents — this is leaf‑level reuse, not a redundant *goal* (which the instructions actually prohibit).
- **"Leave the responsible nurse/doctor unalerted."** I modeled this exactly as written. It reads unusually (most clinical protocols would want an alert, not the opposite), so if this was meant to say "alerted," tell me and I'll flip G18/AT19 and its fallback logic — everything else in the model is unaffected either way.

## 4. Logical Relationships

- **G1 -> G2, G22, G23 [AND] FALLBACK(FALLBACK(G2,G22),G23)**
  - **Justification**: FALLBACK forces AND between operands; the chain exists because the text explicitly conditions two escalations: "additional robots can be assigned **in case of** impossibility" and the manager "must be alerted **if** no combination... can complete."

- **G2 -> G3, G8, G13, G21 [AND] (sequential)**
  - **Justification**: explicit temporal markers "before entering," "once inside," "once checked... proceed" define a mandatory order.

- **G3 -> G4, G5, G6, G7 [AND] (FALLBACK(G4,G5)) # (FALLBACK(G6,G7))**
  - **Justification**: "check availability **and** battery" → AND; each check's IF‑triggered alternative → FALLBACK; no order between the two checks → parallel.

- **G3 -> AT1 [AND] / G4 -> AT1**
  - **Justification**: sole realizing task of the availability query.

- **G5 -> AT2 [AND]**, **G6 -> AT3 [AND]**
  - **Justification**: each goal maps to exactly one concrete action.

- **G7 -> AT4, AT5 [AND] (parallel)**
  - **Justification**: "recharge **and** reassign" → AND; no sequencing word → parallel.

- **G8 -> G9, G10, G11, G12 [AND] (sequential)**
  - **Justification**: protocol order given in text, each step enables the next.

- **G9 -> AT6, AT7 [OR] (parallel)**
  - **Justification**: explicit "either... or" → OR; no stated order between the two methods.

- **G10 -> AT8 [AND]**, **G11 -> AT9 [AND]**, **G12 -> AT10 [AND]**
  - **Justification**: single realizing action each.

- **G13 -> G14, G17, G18, G19, G20 [AND] (FALLBACK(FALLBACK(G14,G17),G18)) ; (G19 # G20)**
  - **Justification**: failure‑to‑collect "**triggers**" questions, and non‑response triggers the unalerted branch → nested FALLBACK; sterilization/disinfection occur "**afterwards**" → sequential; no order between the two → parallel.

- **G14 -> G15, G16, AT17 [OR] (parallel)**
  - **Justification**: three independent, non‑exclusive patient conditions, each sufficient on its own to require its branch — OR, not AND, since not every patient needs every branch; no order given among conditions.

- **G15 -> AT11, AT12, AT13, AT14 [AND] (parallel)**
  - **Justification**: "heart rate, blood pressure, body temperature, **and** blood oxygenation" — explicit conjunction, no order.

- **G16 -> AT15, AT16 [AND] (parallel)**
  - **Justification**: "heart rate **and** blood oxygenation" — explicit conjunction, no order.

- **G17 -> AT18 [AND]**, **G18 -> AT19 [AND]**, **G19 -> AT20 [AND]**, **G20 -> AT21 [AND]**
  - **Justification**: each is a single, specific triggered/conditional action.

- **G21 -> AT22, AT23 [AND] (sequential)**
  - **Justification**: "mark it as done **and** proceed" — marking is a precondition to leaving the room, presented in that order.

- **G22 -> AT24 [AND]**, **G23 -> AT25 [AND]**
  - **Justification**: each goal is realized by exactly one fleet‑/communication‑level action.
