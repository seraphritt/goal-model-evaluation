# Goal Model – Lab Sample Transport & Processing Mission

## Step‑by‑Step Reasoning

**1. Identify the actors mentioned in the description**
- **Nurse** – human, collects sample, requests delivery, enters data (no robot involved in any of these actions)
- **Technician** – human, positions the transport robot
- **Transport Robot** – robot, carries the sample in a locked drawer, navigates to the lab, opens the drawer
- **Robotic Arm** – robot, picks up, scans, sorts, logs, loads the sample
- **Track system / analysis machines** – passive systems, not robots

**2. Apply the "zero‑robot" exclusion rule**
Several actions in the narrative are performed exclusively by humans and have no robot participant. Per the instructions, these must **not** appear as nodes in the goal model, even though they are necessary business-process context:
- *Nurse requests a delivery* → zero‑robot (excluded; treated as the external trigger event for G1).
- *Sample identified with a barcode before collection* → zero‑robot (excluded; no robot is described performing the labeling).
- *Nurse inserts sample data into the track system* → zero‑robot (excluded).
- *"Authorized personnel" opening the drawer* (the first disjunct of the OR sentence) → zero‑robot branch, excluded. Only the *"specific robots in specific locations"* branch is modeled, so the OR collapses into a single robot-performed task rather than a two-child OR decomposition.

**3. Resolve an interpretive ambiguity (flagged explicitly)**
The sentence "*a technician positions the transport robot beside the robotic arm*" grammatically casts the technician as the agent. However, in a multi-robot-systems context, I interpret this as the **technician triggering/supervising an autonomous navigation action executed by the transport robot itself** (the robot's locomotion system performs the actual positioning). This reading is what allows the step to remain in the model under the zero‑robot rule; if a strictly manual/human-only reading is intended instead, this task (AT2) should be removed from the tree.

**4. Determine sequencing vs. parallelism vs. fallback**
- The narrative lists transport‑phase actions in a fixed physical order (transport → position beside arm → drawer becomes accessible) with no conditional/failure branch described → **sequential (`;`)**, not fallback.
- Likewise, the robotic arm's actions (pick up → scan → sort → load) are narrated in a fixed order with no stated alternative or failure path → **sequential (`;`)**.
- Nowhere does the text say "if X fails, do Y" or explicitly state "first... then..." as an exception/condition — so **FALLBACK is never used** in this model.
- Timestamp logging (collection/delivery) and pick-location logging are monitoring activities that run **alongside** the physical action chain rather than blocking it → modeled as **parallel (`#`)** with the respective task chain.

**5. Classify goal types**
- Root and major phase goals (deliver, transport, process) involve planning/acting toward a state → **Achieve**.
- The time-tracking requirement is explicitly about *obtaining knowledge* (duration) to check compliance, not about causing a physical state change → **Query**.
- No goal in this mission is a bare, unconditioned action with no target state and no information need, so no goal was classified as a pure **Perform** goal at the Goal level (Perform classification is reserved for isolated action-execution goals; here every “action-only” step was concrete enough to be modeled directly as a **Task**, which is the more precise fit).

**6. Build the tree depth-first and number nodes accordingly.**

## Logical Relationships

- **G1 -> G2, G4 [AND] (sequential)**
  - **Justification**: Delivery and processing are both required for the mission to succeed, and processing cannot begin until the sample physically arrives — the narrative presents transport before any lab-side handling.

- **G2 -> AT1, AT2, AT3, G3 [AND] — (AT1;AT2;AT3) # G3**
  - **Justification**: Carrying, positioning, and drawer-access form one physical, strictly ordered chain (you cannot open the drawer before positioning, nor position before arriving). Time tracking (G3) measures the whole transit duration, so it runs in parallel with that chain rather than before/after it. All four are mandatory → AND.

- **G3 -> AT4, AT5 [AND] (sequential)**
  - **Justification**: A collection timestamp and a delivery timestamp are both required to compute "time between collection and delivery," and the collection event necessarily precedes the delivery event.

- **G4 -> AT6, AT7, AT8, AT9, AT10 [AND] — (AT6;AT7;AT8;AT9) # AT10**
  - **Justification**: Pick-up, scan, sort, and load are narrated in a fixed operational order with no alternative path. Secure logging of "where and when" the sample was picked is anchored to the pick event but does not gate the rest of the physical handling chain, so it proceeds in parallel.
