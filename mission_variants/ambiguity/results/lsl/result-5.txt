# Goal Model Analysis — Lab Sample Transport & Processing Mission

## Step 1 — Identifying the Actors

Before decomposing, I mapped every actor mentioned in the description to determine which actions are robot-executable (and thus eligible for the goal model) versus purely human actions (which must be excluded under the "zero-robot" rule):

| Actor | Type | Role in description |
|---|---|---|
| Nurse | Human | Requests delivery, assigns barcode, enters data in track system |
| Technician | Human | Positions the transport robot beside the arm |
| **Transport robot** | **Robot** | Carries locked drawer from patient floor to laboratory |
| **Robotic arm** | **Robot** | Unloads, picks up, scans, sorts, loads samples |
| Track system | Software system | Stores sample data |
| Analysis machine | Equipment | Receives sample at entry-module |

## Step 2 — Excluding Zero-Robot Elements

Per the rule *"Goals and tasks that are not performed by any robot must not be on the goal model,"* I excluded:
- **"Nurse requests delivery"** — purely a human trigger, no robot involved.
- **"Sample identified with a barcode before collection"** — done before any robot is involved (likely by nurse/lab staff).
- **"Nurse inserts data into the track system"** — a human-system interaction, no robot action.

I treated the **technician's act of positioning the robot** as resulting in a *robot-executed* task: the technician initiates/supervises, but the physical act of moving/aligning is necessarily carried out by the transport robot itself. This is an assumption I'm flagging explicitly, since the text doesn't say "the robot moves itself" — but without this reading, the positioning event would have zero robot actor and would have to be dropped entirely, which would break the causal chain needed for the robotic arm to unload the sample.

Similarly, I attributed **logging** ("where/when the sample was picked") and **time-tracking** (collection→delivery duration) to the **robots that generate the underlying event** (robotic arm's pick action; transport robot's trip), since the track system itself is a passive software store — the robots are the actual sources of this telemetry.

## Step 3 — Avoiding Redundancy

The description says the technician positions the robot "so that it can **unload** the sample," and later says the robotic arm "**picks up** samples." These are the same underlying intention (retrieving the sample from the drawer) described twice at different narrative points. I merged them into a single task (**AT5: Pick Up Sample from Drawer**) rather than creating duplicate goals/tasks for "unload" and "pick up."

## Step 4 — Decomposition & Runtime Logic

- **AND, not OR, dominates this model.** The only "or" phrase in the text ("authorized personnel **or** specific robots") describes alternative *authorizers* for drawer access, not alternative *goals*. Since the personnel branch is zero-robot, it's excluded, collapsing what could have been an OR into a single robot-executed path. No other true alternative (substitutable) paths are described, so no OR-decomposition appears anywhere in the model.
- **No FALLBACK anywhere.** FALLBACK requires an explicit normal/alternative behavior pair triggered by a condition, exception or failure (an "if this fails, then..."). The description contains no such conditional language, so FALLBACK was deliberately not used.
- **Sequential (;) is used heavily**, justified both by the narrative's explicit listing order ("picks up samples, scans the barcode..., sorts, and loads") and by physical necessity (you cannot scan a sample before picking it up, cannot sort before scanning is implied complete, etc.).
- **Parallel (#) is used once**, between the physical transport/positioning chain and the continuous time-tracking goal, since monitoring elapsed time runs *alongside* the trip rather than before/after it.

## Logical Relationships

- **G1 -> G2, G4 [AND] (sequential)**
  - **Justification**: Both sub-missions are mandatory — the sample must be transported *and* processed; neither alone satisfies the mission. Sequential ordering is used because the laboratory process (G4) is physically impossible before the sample arrives (G2) — the narrative's own chronological structure (transport described first, lab actions second) reinforces this.

- **G2 -> AT1, AT2, G3 [AND] ((AT1;AT2) # G3)**
  - **Justification**: Carrying the sample (AT1) must precede fine positioning (AT2) — you cannot align beside the arm before arriving at the laboratory. Time-monitoring (G3), however, is not dependent on completion of AT1/AT2; it runs continuously across the whole transport window, so it is modeled in parallel with the sequential pair.

- **G3 -> AT3 [AND]**
  - **Justification**: A single operational task fully realizes this query goal; no alternative or complementary task is described for time-tracking, so the goal maps directly to this one task.

- **G4 -> G5, AT7, AT8, AT9 [AND] (sequential)**
  - **Justification**: All four steps are required to complete lab processing. The order is explicit in the text's own listing ("picks up samples, scans the barcode..., sorts, and loads") and is also logically forced (you cannot scan a sample still inside a locked drawer, cannot load before it is sorted).

- **G5 -> AT4, AT5, AT6 [AND] (sequential)**
  - **Justification**: The drawer must be unlocked before the sample can be removed, and the pickup can only be logged once it has actually occurred. All three are required jointly to satisfy the security/logging constraints stated in the description.

---

### A note on an interpretive choice
Two aspects of this model rest on reasonable-but-not-airtight readings of the text: (1) that the technician's "positioning" of the robot entails the *robot* moving itself (rather than being manually wheeled), and (2) that the logging/time-tracking requirements attach to the robots' own actions rather than being a background IT-system function. Both readings were necessary to keep these mission-critical requirements inside the goal model at all, given the "zero-robot" exclusion rule — happy to revise either assumption if you intended a different division of labor between the humans and the robots.
