* **G1 -> G2, G5 [AND][(sequential)]**
* **Justification**: The mission description states that once resources are retrieved and the collection phase concludes, the delivery phase begins. Thus, collection (`G2`) and delivery (`G5`) must execute sequentially.


* **G2 -> G3, G4 [AND][FALLBACK(G3, G4)]**
* **Justification**: Standard collection (`G3`) represents the primary behavior. If the battery drops to 10%, execution falls back to the exception handling behavior (`G4`) to recharge and reassign.

* **Justification**: To complete standard collection and request, a robot must both navigate to the storage location (`AT1`) and send the request/wait for retrieval (`AT2`).


* **G4 -> AT3 [AND]**
* **Justification**: The collection battery exception is resolved by executing the concrete task of returning to the recharging station and reassigning the mission (`AT3`).

* **Justification**: Standard delivery runs (`G6`) represent normal operation. If a 30% battery threshold or checkpoint failure occurs, it falls back to exception handling (`G7`).

* **Justification**: Delivery runs are executed through the concrete operational task of making multiple trips to the specified location (`AT4`).


* **G7 -> G8, G9 [AND][FALLBACK(G8, G9)]**

* **G9 -> AT6 [AND]**
