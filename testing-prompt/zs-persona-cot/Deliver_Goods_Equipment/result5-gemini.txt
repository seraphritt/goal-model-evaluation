### Step-by-Step Reasoning and Mission Analysis

1. **Mission Scope & Operational Intent:**
* The mission governs the automated transport of resources (such as sterile medical equipment or clean linens) from storage facilities (sterile facilities, laundry) to requesting agents at specified locations (use destinations, storage rooms).
* It involves two primary operational phases: **Collection** and **Delivery**, which must execute sequentially once resources are identified and retrieved.
* **Parallelism:** When multiple items are requested from different storages, multiple robots can be assigned to parallel collect-deliver tasks to minimize completion time.


2. **Collection Phase Breakdown:**
* The robot must first determine the optimal storage order by estimating waiting times and path distances. This constitutes an information-gathering **Query Goal**.
* Upon reaching the storage, the robot sends precise specifications and waits for retrieval, representing an **Achieve Goal** realized through physical navigation and messaging tasks (**AT1**, **AT2**).


3. **Delivery Phase Breakdown:**
* Once retrieved, the robot executes as many runs as necessary to deliver goods to the specified location (**AT3**).


4. **Exception Handling & Fallbacks:**
* The mission explicitly defines threshold conditions and alternative behaviors governed by fallback logic:
* *Low Battery in Collection (10%):* Robot returns to the recharging station and reassigns the mission to another robot (**AT4**).
* *Low Battery in Delivery (30%):* Robot returns the resource to a checkpoint and assigns the remaining task to another robot (**AT5**).
* *Checkpoint Return Failure:* Triggers an alert and sends a report to the sector manager (**AT6**).


* These are modeled using nested `FALLBACK` runtime annotations separating normal execution from failure handling.

* **G1 -> G2, G7 [AND][FALLBACK(G2, G7)]**
* **Justification**: The mission goal (G1) is successfully achieved via normal execution (G2), with fallback exception handling (G7) taking over if conditions or failures occur.


* **G2 -> G3, G6 [AND][(sequential)]**
* **Justification**: Normal execution requires the collection phase (G3) to fully precede the delivery phase (G6).


* **G3 -> G4, G5 [AND][(sequential)]**
* **Justification**: The robot must first query and determine storage priority (G4) before navigating and retrieving items (G5).


* **G7 -> G8, G9, G10 [AND][FALLBACK(FALLBACK(G8, G9), G10)]**
* **Justification**: Exceptions are handled hierarchically: low battery in collection (G8) is attempted first, followed by low battery in delivery (G9), and finally checkpoint return failure reporting (G10) if previous alternatives do not apply.


* **G4 -> AT1 [AND]**
* **Justification**: Querying storage wait times and path metrics is operationalized directly through task AT1 at the storage locations.


* **G5 -> AT2 [AND]**
* **Justification**: Requesting and retrieving resources requires executing navigation and messaging actions at the storage/sterile facilities (AT2).


* **G6 -> AT3 [AND]**
* **Justification**: Delivering resources requires executing physical transport runs to the specified use destinations (AT3).


* **G8 -> AT4 [AND]**
* **Justification**: Handling collection battery depletion requires returning to the recharging station and reassigning the mission (AT4).


* **G9 -> AT5 [AND]**
* **Justification**: Handling delivery battery depletion requires returning goods to a checkpoint and reassigning the remaining task (AT5).


* **G10 -> AT6 [AND]**
* **Justification**: Handling checkpoint return failure is executed by triggering an alert and sending a report to the sector manager (AT6).
