# Hospital Vital-Signs Monitoring Mission — Goal Model

## 1. Reasoning & Key Modeling Decisions

Before building the tables, here is the step-by-step thinking that shaped the tree:

1. **Root goal.** The mission's purpose ("every two hours, all patients' vital signs should be checked") is a recurring state to be reached, not a single action → **Achieve**. I folded the "high-risk patients checked within 15 minutes" requirement into this goal's *target condition* rather than creating a parallel copy of the entire "visit room" subtree, because it is the **same underlying intention** (visit + check a patient) only with a tighter deadline for a subset of rooms — duplicating the whole subtree would violate the "avoid redundancy" rule. The scheduling constraint is captured as text, not as a structural branch.

2. **Top-level resource fallback.** "Additional robots can be assigned... if impossible in time" and "manager alerted if no combination of robots can complete the mission" is an explicit two-step contingency chain (normal → extra robots → escalate to human). Because order is explicit and conditioned on failure/impossibility, this is modeled as a **nested FALLBACK**: `FALLBACK(FALLBACK(Visit-Rooms, Assign-More-Robots), Alert-Manager)`.

3. **Pre-entry checks.** "Before entering... check availability... and battery" — no stated order between the two checks → **parallel (#)**. Each check has its own explicit IF-triggered alternative ("if not available... return in 5 min"; "if not enough battery... recharge and reassign") → two separate **FALLBACK** goals.

4. **Patient identification.** "either by asking or by scanning the barcode" is a textbook **OR**-decomposition (explicit "either...or"); no order is implied, so runtime is parallel.

5. **In-room sequence.** "Once inside... approach, announce, provide instructions" is an explicit ordered list → **sequential (;)**. Identify → Interact → Collect vitals → Hygiene → Close-out is also sequential because the text presents these in that narrative order and each depends on the previous step's completion.

6. **Condition-specific vital signs.** Infectious-disease, post-surgical, and diabetic patients require different (overlapping) sets of measurements. I used **OR**-decomposition because *which* branch(es) are relevant is selected by the patient's actual condition at runtime (fulfilling the applicable branch is what satisfies the parent for that patient), with **parallel** runtime since a patient could qualify for more than one branch with no stated order between them. Note: heart rate and blood oxygenation appear as separate tasks under both the infectious-disease and post-surgical branches — this is a deliberate, minimal duplication (same physical measurement, different triggering context/branch), not a duplicated *goal*.

7. **Failure handling.** "Failure of collecting any vital sign triggers questions... non-response triggers an alert" is two chained, explicitly conditioned alternatives → **FALLBACK(Collect-Vitals, Assess-via-Questions)** and, inside that, **FALLBACK(Ask-Questions, Alert-Nurse/Doctor)**.

8. **Hygiene actions (sterilize / disinfect actuators).** These are two independent, conditionally-triggered actions (triggered by room type vs. by physical contact respectively) with no stated order or exclusivity → grouped under one **Perform** goal with **parallel** runtime, AND-related since both can legitimately be required together.

9. **Goal typing.**
   - **Query**: "Identify the correct patient" — purely about obtaining information (which bed/patient), no state change pursued.
   - **Achieve**: anything with a target state reached through conditional/looping behavior (availability, battery, vital-sign collection, failure assessment, recharge, mission-level completion).
   - **Perform**: straightforward, immediately-executable action sequences with no complex state to reach — patient interaction (approach/announce/instruct), hygiene actions, and closing out the room (mark done/move on) — success is simply "the action happened."

10. **Zero-robot filter.** Every sentence in the description maps to something the robot does (including sending alerts, which I treat as the robot's own communication action) — nothing was excluded on that basis.

## 2. Goal Hierarchy (quick-reference outline)

```
G1 Periodic Patient Monitoring Mission [Achieve] (FALLBACK)
├─ G2 Visit Every Occupied Room [Achieve]
│  ├─ G3 Pre-Entry Checks [Achieve] (#)
│  │  ├─ G4 Ensure Patient Availability [Achieve] (FALLBACK)
│  │  │  ├─ AT1 Check Patient Availability
│  │  │  └─ AT2 Wait & Retry (5 min)
│  │  └─ G5 Ensure Sufficient Battery [Achieve] (FALLBACK)
│  │     ├─ AT3 Check Battery Level
│  │     └─ G6 Recharge & Reassign Tasks [Achieve] (;)
│  │        ├─ AT4 Recharge Robot
│  │        └─ AT5 Reassign Tasks
│  └─ G7 In-Room Patient Check Procedure [Achieve] (;)
│     ├─ G8 Identify Correct Patient [Query] (#)
│     │  ├─ AT6 Ask Patient for ID
│     │  └─ AT7 Scan Patient Barcode
│     ├─ G9 Patient Interaction Procedure [Perform] (;)
│     │  ├─ AT8 Approach Patient
│     │  ├─ AT9 Announce Procedure
│     │  └─ AT10 Provide Instructions
│     ├─ G10 Collect Vital Signs w/ Failure Handling [Achieve] (FALLBACK)
│     │  ├─ G11 Collect Condition-Specific Vital Signs [Achieve] (#)
│     │  │  ├─ G12 Infectious Disease Vital Signs [Achieve] (#)
│     │  │  │  ├─ AT11 Heart Rate, AT12 Blood Pressure, AT13 Body Temp., AT14 Blood Oxygenation
│     │  │  ├─ G13 Post-Surgical Vital Signs [Achieve] (#)
│     │  │  │  ├─ AT15 Heart Rate, AT16 Blood Oxygenation
│     │  │  └─ AT17 Check Glucose Level
│     │  └─ G14 Assess Patient Status on Collection Failure [Achieve] (FALLBACK)
│     │     ├─ AT18 Ask Assessment Questions
│     │     └─ AT19 Alert Nurse/Doctor
│     ├─ G15 Post-Procedure Hygiene [Perform] (#)
│     │  ├─ AT20 Sterilize Robot
│     │  └─ AT21 Disinfect Actuators
│     └─ G16 Close Out Room Visit [Perform] (;)
│        ├─ AT22 Mark Patient as Done
│        └─ AT23 Proceed to Next Room
├─ AT24 Assign Additional Robots
└─ AT25 Alert Site Manager
```

## 6. Logical Relationships

- **G1 → G2, AT24, AT25 [AND] [FALLBACK(FALLBACK(G2, AT24), AT25)]**
  - *Justification*: The mission is attempted with the currently assigned robot(s) (G2); only if that proves impossible in time is help recruited (AT24); only if no combination of robots can finish is the manager alerted (AT25). Explicit, failure-triggered ordering → FALLBACK, and FALLBACK legs are always AND-related.

- **G2 → G3, G7 [AND] (sequential)**
  - *Justification*: "Before entering the room... Once inside the room..." gives an explicit sequence; both phases are mandatory for a room to count as "visited."

- **G3 → G4, G5 [AND] (parallel)**
  - *Justification*: "check if the patient is available... and if there is enough battery" — a conjunction with no stated order.

- **G4 → AT1, AT2 [AND] [FALLBACK(AT1, AT2)]**
  - *Justification*: "If the patient is not available, the robot should come back in 5 minutes" is an explicit IF-condition with a stated alternative.

- **G5 → AT3, G6 [AND] [FALLBACK(AT3, G6)]**
  - *Justification*: "If there is not enough battery, the robot should recharge and the tasks need to be reassigned" is an explicit IF-condition with a stated alternative.

- **G6 → AT4, AT5 [AND] (sequential)**
  - *Justification*: "recharge and the tasks need to be reassigned" — stated in that order.

- **G7 → G8, G9, G10, G15, G16 [AND] (sequential)**
  - *Justification*: Narrative order of the in-room procedure as written: identify, interact, collect vitals (with failure handling), apply hygiene, close out.

- **G8 → AT6, AT7 [OR] (parallel)**
  - *Justification*: "either by asking or by scanning the patient's barcode" — explicit alternative, either suffices.

- **G9 → AT8, AT9, AT10 [AND] (sequential)**
  - *Justification*: "approach the patient, announce the procedure..., and provide instructions" — explicit ordered list, all required.

- **G10 → G11, G14 [AND] [FALLBACK(G11, G14)]**
  - *Justification*: "The failure of collecting any necessary vital signs should trigger a set of questions" — explicit failure-triggered alternative.

- **G11 → G12, G13, AT17 [OR] (parallel)**
  - *Justification*: Which measurements are needed depends on the patient's condition (infectious / post-surgical / diabetic); fulfilling the applicable branch(es) satisfies the goal for that patient. No order is stated between branches that do co-apply.

- **G12 → AT11, AT12, AT13, AT14 [AND] (parallel)**
  - *Justification*: "must be checked for heart rate, blood pressure, body temperature, and blood oxygenation" — explicit conjunction, no order.

- **G13 → AT15, AT16 [AND] (parallel)**
  - *Justification*: "must be checked for heart rate and blood oxygenation" — explicit conjunction, no order.

- **G14 → AT18, AT19 [AND] [FALLBACK(AT18, AT19)]**
  - *Justification*: "In case of non-response, an alert should be sent" — explicit failure-triggered alternative to the questioning attempt.

- **G15 → AT20, AT21 [AND] (parallel)**
  - *Justification*: Sterilization (triggered by infectious-disease room) and actuator disinfection (triggered by patient contact) are independent, co-occurring obligations with no stated order.

- **G16 → AT22, AT23 [AND] (sequential)**
  - *Justification*: "mark it as done and proceed to the next room" — explicit order.
