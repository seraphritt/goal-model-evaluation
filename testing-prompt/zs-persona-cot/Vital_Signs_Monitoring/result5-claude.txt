# Goal Model for the Hospital Vital-Signs Checking Mission

## Step-by-step reasoning (design process)

Before building the tables, here is how I read and decomposed the description:

1. **Root intention** – "Every two hours, all patients' vital signs should be checked" is the mission's overarching intentional objective → **G1** (root, Achieve).
2. **Main operational loop** – "the assigned robot should visit every occupied room" is the concrete, repeated mechanism for satisfying G1 → **G2/G3** (visiting loop over the collection of occupied rooms).
3. **Explicit pre-condition checks** – "Before entering the room... check if the patient is available... and if there is enough battery" are two independent, conjunctive (AND) checks joined by "and" with no stated order → modeled as **parallel** Query goals (G4–G6).
4. **Explicit if-then contingencies** – "If the patient is not available... come back in 5 minutes" and "If there is not enough battery... recharge and reassign" are textbook triggers for **FALLBACK**, since the text gives a normal path (enter and check) and named alternative behaviors triggered by specific failure conditions.
5. **Multi-bed disambiguation** – "identify the correct patient either by asking or by scanning... barcode" is an explicit **OR** (alternative means to the same end).
6. **In-room narrative order** – approach → announce → instructions → collect vitals → mark done is explicitly **sequential** (narrated in that order, each a prerequisite for the next).
7. **Condition-dependent vital sets** – infectious disease / post-surgical / diabetes history each trigger different, non-universal vital-sign requirements → **OR** decomposition (which branch(es) apply depends on the patient's profile; within each branch, the listed vitals are joined by "and" → **AND**, **parallel**, since no order between individual vitals is given).
8. **Failure-escalation chain** – "failure to collect... trigger questions... in case of non-response, alert nurse/doctor" is a **nested FALLBACK** (collect → ask questions → alert).
9. **Post-room hygiene** – sterilization (infectious rooms) and actuator disinfection (patient contact) are both conditionally required, unordered relative to each other, but must finish **before** proceeding to the next room → parallel, then sequential.
10. **High-risk timing constraint** – "must be checked in the first 15 minutes" is an explicit scheduling requirement, modeled as a **sequential** prioritization task before the general visiting loop (to avoid duplicating the entire per-room subtree for a subset of rooms).
11. **Mission-level escalation** – "additional robots... in case of impossibility" then "alert the manager if no combination... can complete" is a clean **nested FALLBACK** at the mission root (normal mission → add robots → alert manager).
12. I excluded the "DEFINITIONS" paragraph entirely — it is meta-instruction about *how* to build the model, not part of the mission itself, and performs no robot action (zero-robot rule).

All 46 nodes below are robot-performed, so none were excluded under the zero-robot rule.

## Logical Relationships

- **G1 -> G2, G18, G19 [AND][FALLBACK(FALLBACK(G2,G18),G19)]**
  - **Justification**: The mission's normal path is visiting and checking all rooms (G2). The text explicitly introduces two contingent alternatives tied to failure conditions: "additional robots can be assigned... in case of impossibility" (G18), and, if that still fails, "the responsible manager... must be alerted" (G19). This is a textbook nested fallback — normal behavior, then two explicit escalation tiers — so AND is mandatory (per the FALLBACK/AND rule).

- **G2 -> AT1, G3 [AND][(sequential) AT1;G3]**
  - **Justification**: "All patients in high risk must be checked in the first 15 minutes" explicitly imposes an order: priority scheduling must occur so high-risk rooms are serviced early, before/at the start of the general visiting process. Not a fallback (no failure/condition trigger), not parallel (explicit priority ordering), hence sequential.

- **G3 -> G4, G7, AT23, G17 [AND][G4;FALLBACK(FALLBACK(G7,AT23),G17)]**
  - **Justification**: "Before entering the room, the robot must check..." establishes G4 strictly precedes everything else (sequential). The two "if" clauses ("If the patient is not available... If there is not enough battery...") are explicit condition-triggered alternatives to the normal entry/check path (G7), hence nested FALLBACK, which forces AND.

- **G4 -> G5, G6 [AND][(parallel) G5#G6]**
  - **Justification**: "check if the patient is available... and if there is enough battery" — joined by "and" with no stated order, so both are required (AND) but may be evaluated in parallel.

- **G7 -> AT4, G8, G9, AT19, G14 [AND][(sequential) AT4;G8;G9;AT19;G14]**
  - **Justification**: The description narrates these in strict order: enter → identify patient → interact/collect vitals → mark done → exit/next-room actions. All are mandatory (AND), explicitly ordered (sequential).

- **G8 -> AT5, AT6 [OR][(parallel) AT5#AT6]**
  - **Justification**: "either by asking or by scanning" is an explicit OR particle — either suffices to identify the patient. No order is specified, so the (optional) parallel annotation applies, though in practice only one is executed.

- **G9 -> AT7, AT8, AT9, G10, AT17, AT18 [AND][(sequential + nested fallback) AT7;AT8;AT9;FALLBACK(FALLBACK(G10,AT17),AT18)]**
  - **Justification**: Approach/announce/instructions are explicitly ordered and jointly required. The vital-collection failure handling is explicitly conditional: "failure... should trigger a set of questions... in case of non-response, an alert." This is a two-tier fallback, forcing AND among all children.

- **G10 -> G11, G12, G13 [OR][(parallel) (G11#G12)#G13]**
  - **Justification**: Each condition-specific vital set only applies if the patient actually has that condition (infectious disease / post-surgical / diabetes history) — this is context-dependent alternative applicability, matching OR semantics, rather than a universal AND requirement for every patient. No order is stated among the categories, so parallel.

- **G11 -> AT10, AT11, AT12, AT13 [AND][(parallel)]**
  - **Justification**: "must be checked for heart rate, blood pressure, body temperature, and blood oxygenation" — explicit conjunctive "and" list, no order given.

- **G12 -> AT14, AT15 [AND][(parallel) AT14#AT15]**
  - **Justification**: "must be checked for heart rate and blood oxygenation" — conjunctive, no order given.

- **G13 -> AT16 [AND]**
  - **Justification**: Single mandatory task ("must be checked for glucose levels"); trivially AND.

- **G14 -> G15, G16, AT22 [AND][(parallel then sequential) (G15#G16);AT22]**
  - **Justification**: Sterilization and actuator disinfection are each independently triggered post-conditions with no stated order between them (parallel), but the room-exit narrative ("...proceed to the next room") places moving on as the final step, after hygiene actions are resolved (sequential).

- **G15 -> AT20 [AND]** / **G16 -> AT21 [AND]** / **G18 -> AT26 [AND]** / **G19 -> AT27 [AND]**
  - **Justification**: Each is a single mandatory action fulfilling its parent goal; trivially AND, leaf goals.

- **G17 -> AT24, AT25 [AND][(parallel) AT24#AT25]**
  - **Justification**: "the robot should recharge and the tasks need to be reassigned" — conjunctive "and," no stated order.
