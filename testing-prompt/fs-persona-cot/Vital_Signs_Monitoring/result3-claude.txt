## Reasoning & Key Modeling Decisions

- **Root structure.** G1 (the periodic mission) splits into G2 (visit/check all occupied rooms) running in parallel with G16 (an ongoing robot-allocation/feasibility process), because "additional robots can be assigned" and the manager-alert rule describe a continuous contingency, not a step that strictly precedes or follows room visits.
- **High-risk priority without duplication.** "All patients in high risk must be checked in the first 15 minutes" is modeled as a scheduling task (AT1: Prioritize Room Visit Order) executed before the generic per-room workflow (G3), rather than as a second copy of that whole workflow for "high-risk rooms." Duplicating the subtree would violate the no-redundancy rule, since the underlying intention — processing a room — is identical regardless of risk level; only the visiting *order* differs.
- **Where patient identification belongs.** G5 (Identify Correct Patient) sits inside the pre-entry checks (G4), not the in-room workflow, because the description introduces it ("rooms may have one or more beds, so the robot has to identify the correct patient...") between the availability/battery sentence and the "once inside the room" sentence. The robot must know *which* patient it is dealing with before it can evaluate that patient's availability.
- **FALLBACK used only for explicit conditions.** Every "if X, then Y" clause — patient unavailable → wait 5 minutes; battery insufficient → recharge & reassign; vital-sign collection fails → ask questions; no response → alert nurse/doctor; no robot combination works → alert manager — is modeled as FALLBACK, per the rule that an explicit condition, failure or exception triggering an alternative behavior requires FALLBACK rather than sequence or OR.
- **Parallel vs. sequential.** Conjunctions with no stated order (heart rate/blood pressure/temperature/oxygenation for infectious patients; recharge *and* reassign; sterilize/disinfect) use the parallel operator (#). Narratively ordered actions with no condition attached (approach → announce → instruct; pre-entry checks → in-room checking → post-room actions) use sequential (;), since FALLBACK applies only to condition-triggered alternatives, not plain narrative order.
- **OR for condition-dependent vitals.** The three vital-sign requirements (infectious disease, post-surgical, diabetes) form an OR decomposition under G11, because they are non-exclusive alternatives that depend on the specific patient's medical profile — a patient may trigger one, several, or none of them, matching OR's "at least one branch applies" semantics (not AND, since not every patient has every condition).
- **Zero-robot exclusion.** Every leaf task is a concrete action explicitly named in the description and executed by a robot (ask, scan, measure, approach, announce, recharge, sterilize, disinfect, alert). Nothing was included that lacks an explicit robot actor.
- **Locations.** Restricted to terms the description actually uses: *Room* (the specific occupied room being visited), *OccupiedRooms* (the collection of rooms to visit), and *Hospital/Site* (for manager alerts and fleet-wide robot allocation, matching "the responsible manager for the site").
- **Goal typing.** Identify Correct Patient is a **Query** goal (its purpose is retrieving identity information). Prepare Patient for Procedure is a **Perform** goal (a fixed action sequence with no deeper target state, like the "Enter the Car" example). Every other composite goal is **Achieve**, since each has a clear target condition reached through planning, waiting, or conditional action.

## Logical Relationships

- **G1 -> G2, G16 \[AND\] (parallel)**
  - *Justification*: visiting/checking rooms and ensuring robot-allocation feasibility are both required for the mission, and run concurrently rather than in a fixed order.
- **G2 -> AT1, G3 \[AND\] (sequential)**
  - *Justification*: rooms must be prioritized (high-risk first) before the per-room process is carried out.
- **G3 -> G4, G8, G15 \[AND\] (sequential)**
  - *Justification*: the description gives an explicit narrative order — pre-entry checks, then in-room checking, then post-checking actions.
- **G4 -> G5, G6, G7 \[AND\] \[(G5;G6) # G7\]**
  - *Justification*: patient identity must be resolved before that patient's availability can be checked (sequential), while the battery check is independent of patient identity and can proceed in parallel.
- **G5 -> AT2, AT3 \[OR\] (parallel)**
  - *Justification*: asking and scanning are explicitly offered as alternative, equally sufficient identification methods.
- **G6 -> AT4, AT5 \[AND\] FALLBACK(AT4, AT5)**
  - *Justification*: availability is checked first; the 5-minute wait-and-retry is only pursued if that check fails (patient unavailable).
- **G7 -> AT6, AT7, AT8 \[AND\] FALLBACK(AT6, (AT7 # AT8))**
  - *Justification*: battery is checked first; recharging and task reassignment are only pursued if the battery is insufficient, and run in parallel with each other since no order is stated between them.
- **G8 -> G9, G10 \[AND\] (sequential)**
  - *Justification*: the text lists preparing the patient, then collecting vital signs, as sequential steps once inside the room.
- **G9 -> AT9, AT10, AT11 \[AND\] (sequential)**
  - *Justification*: "approach the patient, announce the procedure..., and provide instructions" is an explicit left-to-right order.
- **G10 -> G11, G14 \[AND\] FALLBACK(G11, G14)**
  - *Justification*: condition-specific vital signs are measured first; failure-handling (questions/alert) is only triggered if that collection fails.
- **G11 -> G12, G13, AT18 \[OR\] (parallel)**
  - *Justification*: the infectious-disease, post-surgical, and diabetes vital-sign requirements are non-exclusive alternatives depending on the patient's actual condition(s); any applicable combination can occur, with no order between them.
- **G12 -> AT12, AT13, AT14, AT15 \[AND\] (parallel)**
  - *Justification*: all four measurements are explicitly required together for infectious-disease patients, with no stated order.
- **G13 -> AT16, AT17 \[AND\] (parallel)**
  - *Justification*: both measurements are explicitly required together for post-surgical patients, with no stated order.
- **G14 -> AT19, AT20 \[AND\] FALLBACK(AT19, AT20)**
  - *Justification*: assessment questions are asked first; the nurse/doctor alert is only sent if there is no response.
- **G15 -> AT21, AT22, AT23, AT24 \[AND\] \[AT21 ; (AT22 # AT23) ; AT24\]**
  - *Justification*: marking the patient done precedes leaving the room; decontamination (sterilization/actuator disinfection, run in parallel with each other) must happen before the robot proceeds to avoid cross-contamination, and proceeding to the next room is explicitly the final step ("mark it as done and proceed to the next room").
- **G16 -> AT25, AT26 \[AND\] FALLBACK(AT25, AT26)**
  - *Justification*: additional robots are assigned first as the primary recourse; the manager is alerted only "if no combination of robots can complete the mission."
