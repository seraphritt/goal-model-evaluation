# Mission Analysis: Lab Sample Transport & Processing

## Step‑by‑Step Reasoning

**1. Identify all actors/agents mentioned in the description.**
- *Nurse* — human, collects sample, requests delivery, enters data in track system.
- *Transport mechanism (locked drawers)* — implied to be carried by a mobile robot, since this is a multi‑robot system mission and "transported... to the laboratory" is the core mission statement.
- *Robotic arm* — explicitly robotic, performs pick/scan/sort/load in the laboratory.
- *Laboratory personnel* — human alternative to the robotic arm for picking samples.
- *Authorized personnel* — human alternative for opening locked drawers.

**2. Apply the zero-robot exclusion rule.**
The instructions state goals/tasks performed by **zero robots must not appear** in the model. Applying this:
- "Nurse requests delivery," "barcode identification before collection," and "nurse inserts data in track system" are purely human (nurse) actions → **excluded**.
- "picked by... laboratory personnel" is the human branch of an OR → **excluded**, leaving only "picked by a robotic arm" as the modeled path (I note this explicitly rather than silently dropping information).
- "opened by... authorized personnel" is the human branch of an OR → **excluded**, leaving only "specific robots in specific locations" as the modeled path.

This means the two explicit ORs in the text collapse into single (robot-only) branches once the human alternative is removed — this is why the resulting model is **entirely AND-structured**: no OR node has two robot-relevant alternatives left to compare. I want to flag this explicitly rather than force an artificial OR.

**3. Identify sequencing cues (sequential, parallel, fallback).**
- "Transported from patient floors to the laboratory... **In the laboratory**, the sample can be picked" → explicit order: transport completes before lab processing → **sequential**.
- "picks up samples, scans the barcode..., sorts, and loads..." → explicit enumerated order → **sequential** chain.
- Opening the drawer must physically precede picking the sample out of it → **sequential** (logical/physical precondition, even though not stated with an explicit "then").
- "Information about where and when... should be logged" has no stated ordering relative to scan/sort/load — logging only needs the pick event to have occurred, after which it can proceed independently → **parallel** with the scan-sort-load chain.
- Tracking elapsed time spans the entire transport interval — it is not before/after the transport task, it co‑occurs with it → **parallel**.
- The two timestamps needed to compute an elapsed duration are themselves ordered (collection happens before delivery) → **sequential**.
- **No fallback** relations: nothing in the text describes a failure, exception, interruption, or conditional alternative triggered by a condition (e.g., "if the robotic arm fails, then..."). The robotic-arm/personnel and robot/personnel ORs are plain alternatives, not fallback-with-failure language, and the human side is excluded anyway. So FALLBACK is correctly never used here.

**4. Classify goal types.**
- Goals describing a state to be reached via a sequence of physical actions (sample relocated, sample retrieved, sample processed) → **Achieve**.
- The one goal whose purpose is purely to obtain information (elapsed time) → **Query**.
- No goal here is a bare "do this one action regardless of outcome" with no target state in a way that's distinguishable from Achieve, so no **Perform** goal was needed — each action-goal in this mission has a clear resulting state it must reach (drawer open, sample out, etc.), which is why I modeled them as Achieve rather than Perform.

**5. Build the tree, depth-first, trying to maximize meaningful relationships** without inventing singleton decompositions (every AND/OR has ≥2 children).

## Logical Relationships

- **G1 -> G2, G4 [AND] (sequential)**
  - **Justification**: The description's order ("transported from patient floors to the laboratory... In the laboratory, the sample can be picked...") shows lab processing presupposes the sample has already arrived. Both steps are mandatory (AND), and transport must finish before processing begins (sequential), so `G2;G4`.

- **G2 -> AT1, G3 [AND] (parallel)**
  - **Justification**: The physical transport (AT1) and the duration tracking (G3) are both explicitly required ("samples are transported..."; "the time...should be tracked"). Tracking spans the whole transport interval rather than preceding or following it, so it runs concurrently: `AT1#G3`.

- **G3 -> AT2, AT3 [AND] (sequential)**
  - **Justification**: Both timestamps are needed to compute "the time between sample collection and laboratory delivery" (AND). The collection timestamp is chronologically earlier than the delivery timestamp, so `AT2;AT3`.

- **G4 -> G5, G6, AT9 [AND] (G5 sequential, then G6 parallel with AT9)**
  - **Justification**: Retrieval, preparation, and logging are each explicitly required. The sample must be retrieved before it can be prepared or have its pick event meaningfully logged, but once retrieved, preparation and logging are not stated to depend on one another, so: `G5;(G6#AT9)`.

- **G5 -> AT4, AT5 [AND] (sequential)**
  - **Justification**: A locked drawer cannot be picked from while closed — opening is a physical precondition to picking — so `AT4;AT5`.

- **G6 -> AT6, AT7, AT8 [AND] (sequential)**
  - **Justification**: The mission text gives an explicit order — "scans the barcode..., sorts, and loads..." — so `AT6;AT7;AT8`.

### Modeling notes / exclusions
Per the zero-robot rule, the following mission elements were deliberately **left out** of the model because no robot performs them: the nurse's delivery request, barcode identification prior to collection, the nurse's data entry into the track system, the "laboratory personnel" alternative for picking samples, and the "authorized personnel" alternative for opening drawers. This is also why the model contains **no OR decomposition**: both explicit ORs in the text ("robotic arm or laboratory personnel," "authorized personnel or specific robots") had one branch removed by this rule, leaving a single robot-relevant path rather than a genuine alternative to weigh.
