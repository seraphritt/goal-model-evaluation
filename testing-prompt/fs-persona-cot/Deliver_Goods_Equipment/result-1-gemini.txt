## Step-by-Step Thinking & Reasoning Process

1. **Mission Objective & Scope Analysis**:
* The primary objective of the mission is to collect required resources (e.g., sterile medical equipment, clean linens) from storage facilities and deliver them to requesting agents at specified locations (e.g., use destinations, storage rooms).
* The mission is structured into two main sequential operational phases: **Collection Phase** and **Delivery Phase**.
* When multiple items are required from different storages, multiple robots can execute collect-deliver tasks in **parallel** to reduce completion time.


2. **Collection Phase Breakdown**:
* **Navigation & Request**: Robots must travel to storage locations (ordered by waiting time + path cost), transmit precise specifications via messaging, and wait for retrieval.
* **Exception Handling (10% Battery Threshold)**: If the assigned robot's battery drops to 10% during collection, it must trigger a fallback behavior: return to the **recharging station** and reassign the mission to another robot.


3. **Delivery Phase Breakdown**:
* **Multi-Run Delivery**: The robot performs as many runs as necessary to transport all retrieved resources to the specified location.
* **Exception Handling (30% Battery Threshold)**: If the battery drops to 30% during delivery, a fallback behavior is triggered: return the resource to a **checkpoint** and assign the remaining task to another robot.
* **Failure Handling**: If returning the resource to a checkpoint fails, an alert must be triggered and a report sent to the **sector manager**.


4. **Goal Model Hierarchy & Decompositions**:
* **G1 (Root Goal)**: Execute Resource Logistics Mission (`G2;G3` sequential execution of collection and delivery).
* **G2 (Collection Phase)**: Governed by `FALLBACK(G2.1, G2.2)` where normal collection (`G2.1`) is attempted first, and low-battery handling (`G2.2`) serves as the exception fallback.
* **G3 (Delivery Phase)**: Governed by `FALLBACK(G3.1, G3.2)` where normal delivery (`G3.1`) is attempted first, and battery/checkpoint exception handling (`G3.2`) serves as the fallback.
* **Tasks (`AT1` through `AT6`)**: Leaf actionable operations tied to specific locations and robot assignments (`[1, n]` for parallel multi-robot tasks or `1` for single-agent exception/reassignment tasks).

* **Justification**: The mission mandates that resource collection must occur before delivery can take place, establishing a sequential dependency between the collection phase (G2) and delivery phase (G3), both of which are required (AND) for mission completion.


* **G2 -> G2.1, G2.2 [AND][FALLBACK(G2.1, G2.2)]**
* **Justification**: Normal collection execution (G2.1) is pursued as the primary behavior. If the 10% battery threshold is breached, the robot falls back to recharging and task reassignment (G2.2). As per specification, fallback relationships are connected via an AND-decomposition.


* **G2.1 -> AT1, AT2 [AND][(sequential)]**
