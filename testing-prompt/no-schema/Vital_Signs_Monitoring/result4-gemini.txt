## Mission Analysis and Reasoning (Step-by-Step Thinking)

As a mission designer specialized in Multi-Robot Systems (MRS), decomposing a natural language mission description into a formal goal model requires identifying structural hierarchy, temporal constraints, conditional branching (fallbacks), resource allocations, and safety protocols.

### Step 1: Mission Scope & Temporal Requirements

* **Periodicity**: The mission must run every two hours (`G1`).
* **High-Risk Prioritization**: All high-risk patients must be checked within the first 15 minutes (`G2`). This introduces a temporal constraint that requires prioritizing high-risk rooms right at mission startup.

### Step 2: Room Inspection & Task Execution Workflow (`G3`)

Each room visit follows a strict sequence:

1. **Pre-entry Checks (`G3.1`)**: Before entering, the robot must verify patient availability and sufficient battery.
* *Fallback logic*: If the patient is unavailable, retry in 5 minutes. If battery is low, recharge and trigger task reassignment (`AT2`).


2. **Identification & Briefing (`G3.2`)**: Multi-bed rooms require patient identification via barcode scanning or asking (`AT3`), followed by approach, procedure announcement, and instructions (`AT4`).
3. **Data Collection (`G3.3`)**: Vitals collection is conditioned on patient medical history:
* *Infectious*: Heart rate, blood pressure, body temperature, blood oxygenation.
* *Post-surgical*: Heart rate, blood oxygenation.
* *Diabetes*: Blood glucose levels.


4. **Failure Recovery & Escalation (`G3.4`)**: If vital sign collection fails, a questionnaire assessment is triggered (`AT6`). If the patient is non-responsive, an alert is sent to a nurse/doctor (`AT7`). This represents a `FALLBACK` relationship.
5. **Hygiene & Progression (`G3.5`)**: Actuators must be disinfected after touching patients. If an infectious room is exited, full robot sterilization is required (`AT8`). Finally, the room is marked done, and the robot proceeds (`AT9`).

### Step 3: Fleet Management & Escalation (`G4`)

* **Dynamic Scaling**: If the mission cannot be completed within the required time, additional robots can be assigned (`AT10`).
* **Critical Failure Escalation**: If no combination of robots can complete the mission, the site manager must be alerted (`AT11`).

## 4. Logical Relationships

* **G1 -> G2, G3, G4 [AND][(sequential)]**
* **Justification**: The overarching mission (G1) first prioritizes high-risk patients within the initial time window (G2), executes routine room-by-room vital checks (G3), and manages multi-robot fleet scaling and escalation (G4) across the mission lifecycle.


* **G3 -> G3.1, G3.2, G3.3, G3.4, G3.5 [AND][(sequential)]**
* **Justification**: Room checking requires strict sequential stages: pre-entry assessment (G3.1), patient identification and briefing (G3.2), condition-specific vital signs acquisition (G3.3), failure handling/escalation (G3.4), and post-check hygiene and progression (G3.5).


* **G3.1 -> AT1, AT2 [FALLBACK(AT2)]**
* **Justification**: The robot performs pre-entry checks (AT1). If battery is insufficient, the system falls back to recharging and task reassignment (AT2).


* **G3.4 -> AT6, AT7 [FALLBACK(AT7)]**
* **Justification**: If vital signs collection fails, the robot initiates the questionnaire assessment (AT6). If the patient is non-responsive, it falls back to alerting medical staff (AT7).


* **G4 -> AT10, AT11 [FALLBACK(AT11)]**
* **Justification**: If time constraints cannot be met by the current fleet, additional robots are assigned (AT10). If no combination of robots can complete the mission, the system falls back to alerting the site manager (AT11).
