> **Justification of Goal Types**  
> *Perform* goals are used whenever the objective is to *do something* – i.e., execute actions (e.g., plan, request, deliver).  
> *Query* goals are used when the system only needs to *obtain information* (battery level) and not necessarily act on it; the retrieved value triggers other actions.  
> No *Achieve* goals are required because the mission does not define an abstract future state that the agents must bring about; the objectives are concrete operational tasks.

```
G3.1 -> AT7 [AND]
G3.2 -> AT8 [AND]
```

*Notes on Runtime Annotations*  
- **Sequential (`;`)**: the parent goal must finish one child before starting the next (e.g., planning → request → wait).  
- **Parallel (`#`)**: children can be executed concurrently (e.g., querying battery while delivering).  
- **Fallback (`FALLBACK(e1,e2)`)**: not used in this model because all sub‑tasks have deterministic success criteria.  

This goal–task tree fully captures the mission description, separates operational actions from information‑gathering, and explicitly models battery‑management contingencies and parallelism for multi‑robot execution.
