> **Note on Runtime Operators**  
> * `;` – ensures that children are executed one after another.  
> * `#` – allows children to run concurrently (useful when several robots operate on different storages).  
> * `FALLBACK(a,b)` – expresses a binary alternative; if the first child fails, the second is executed.

## 4. Logical Relationships

- **G1 → G2, G3** [**AND**]  
  *Justification:* Collection and delivery phases are both required for mission completion.

- **G2 → G2.1, G2.2, G2.3** [**OR**] (runtime: `FALLBACK(G2.2,G2.3)`)  
  *Justification:* Normal collection or battery‑low handling are alternative plans; the fallback operator models the switch.

- **G2.1 →** (leaf)  
  *Justification:* No further decomposition; it simply queries the order.

- **G2.2 → AT1, AT2, AT3** [**AND**] (runtime: `#`)  
  *Justification:* All three actions must be performed, and they may run in parallel when multiple storages are handled concurrently.

- **G2.3 → AT4, AT5, AT6** [**AND**] (runtime: `;`)  
  *Justification:* Must check battery, recharge, and hand‑off in sequence.

- **G3 → G3.1, G3.2** [**OR**] (runtime: `FALLBACK(G3.1,G3.2)`)  
  *Justification:* Normal delivery or battery‑low handling are mutually exclusive alternatives.

- **G3.1 → AT9, AT10** [**AND**] (runtime: `;`)  
  *Justification:* Movement to destination precedes transportation of the resource.

- **G3.2 → G3.2.1, G3.2.2** [**OR**] (runtime: `FALLBACK(G3.2.1,G3.2.2)`)  
  *Justification:* Successful return → assign task; failure → alert.

- **G3.2.1 → AT7, AT8, AT11** [**AND**] (runtime: `;`)  
  *Justification:* Battery check, return to checkpoint, then hand‑off must occur in order.

- **G3.2.2 → AT12** (leaf)  
  *Justification:* Only triggered on failure to return the resource.

### Remarks

- **Parallelism** (`#`) is used where the mission can exploit multiple robots (e.g., collecting from several storages or delivering multiple items).  
- **Sequential** (`;`) is used where an order is mandated by the mission (e.g., moving before transporting).  
- **Fallback** models the decision between normal execution and contingency plans (battery‑low handling).  
- **Query** goal (`G2.1`) captures information acquisition required to decide the visitation order.  
- **Perform** goals represent concrete actions that must be executed by the robots.  

This goal model decomposes the mission into a clear, hierarchical structure, specifying execution semantics, relationships, and concrete tasks that can be directly mapped to robot behaviors in a multi‑robot system.
