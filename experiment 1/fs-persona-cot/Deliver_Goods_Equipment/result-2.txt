| **G1: Deliver Requested Resources** | Deliver all requested resources to the specified agent location. | `;` | Achieve | *all requested resources are delivered to the destination* | AND | The overall mission consists of **collection** followed by **delivery** – the two sub‑goals must both succeed before G1 can succeed. |
| **G2: Collect Resources** | Collect the required resources from storage. | `FALLBACK(G2.1, G4)` | Perform |  | OR | Two mutually exclusive execution paths: normal collection (`G2.1`) and a low‑battery fallback (`G4`). The fallback is triggered only when the battery is below 10 % during the collection phase. |
| **G2.1: Normal Collection** | Perform the normal collection routine from a single storage. | `;` | Perform |  | AND | All constituent tasks (navigation, request, wait, load) must be completed sequentially for the collection to be considered done. |
| **G4: Handle Low‑Battery in Collection** | Handle a low‑battery situation (≤ 10 %) that occurs while collecting. | `;` | Perform |  | AND | After the battery drops, the robot must recharge and hand the mission over to another robot. Both steps must succeed. |
| **G3: Deliver to Destination** | Deliver the collected resources to the destination. | `FALLBACK(G3.1, G3.2)` | Perform |  | OR | Normal delivery (`G3.1`) or a low‑battery fallback (`G3.2`). The fallback is activated when the battery drops below 30 % during delivery. |
| **G3.1: Normal Delivery** | Deliver resources without battery interruption. | `;` | Perform |  | AND | Navigation to destination followed by unloading. The robot must finish both actions. |
| **G3.2: Handle Low‑Battery in Delivery** | Handle a low‑battery situation (≤ 30 %) that occurs while delivering. | `;` | Perform |  | AND | Return to checkpoint, hand the task over to another robot, and, if the return fails, trigger an alert. All three actions must be completed. |

### Task – Operational nodes

| Name | Text | Relation (to parent goal) | Location | Number of Robots | Justification |
|------|------|---------------------------|----------|------------------|--------------|
| **AT1: Navigate to Storage** | Robot moves from its current location to the target storage. | AND | *Storage* | 1 | Physical movement is required to reach the storage before any further action. |
| **AT2: Send Request to Storage** | Robot sends a message containing the exact specification of the requested resources. | AND | *Storage* | 1 | This communication is necessary before the storage can retrieve the items. |
| **AT3: Wait for Retrieval** | Robot remains idle at the storage until the storage confirms that the requested resources have been removed. | AND | *Storage* | 1 | Waiting ensures the robot does not proceed until the resources are actually available for pickup. |
| **AT4: Load Resources** | Robot physically picks up the retrieved resources and secures them for transport. | AND | *Storage* | 1 | The robot must load the items before moving to the destination. |
| **AT5: Navigate to Destination** | Robot moves from the storage to the destination location where the agent will receive the resources. | AND | *Destination* | 1 | Movement is required to deliver the items. |
| **AT6: Unload Resources** | Robot places the loaded resources at the destination location. | AND | *Destination* | 1 | Delivery is completed only after the resources are unloaded. |
| **AT7: Navigate to Recharging Station** | Robot moves from its current location to the nearest recharging station. | AND | *Recharging Station* | 1 | Needed when the battery falls below 10 % during collection. |
| **AT8: Return Resource to Checkpoint** | Robot returns the partially delivered resources to a pre‑defined checkpoint. | AND | *Checkpoint* | 1 | Required when the battery falls below 30 % during delivery to preserve the load for another robot. |
| **AT9: Assign Mission to Another Robot** | Robot informs the central controller to hand the remaining task to another robot and updates the task state. | AND | *Control Base* | 1 | The new robot needs to know the current location of the resources (storage or checkpoint). |
| **AT10: Send Alert to Sector Manager** | Robot notifies the sector manager that it failed to return the resources to the checkpoint. | AND | *Control Base* | 1 | An alert is required only when the return fails, to trigger human intervention. |

### Logical Relationships

| Relationship | Justification |
|--------------|---------------|
| **G1 → G2, G3** | **AND** – The mission cannot succeed unless all resources are collected and then delivered. The sequential runtime (`;`) indicates that the delivery phase starts only after collection finishes. |
| **G2 → G2.1, G4** | **OR** – The collection phase may either run normally (`G2.1`) or be interrupted by a low‑battery condition (`G4`). The `FALLBACK` runtime explicitly captures this alternative behavior. |
| **G4 → AT7, AT9** | **AND** – When the battery drops, the robot must first recharge (`AT7`) and then hand the mission over (`AT9`). Both steps must be done for the fallback to be considered satisfied. |
| **G3 → G3.1, G3.2** | **OR** – Normal delivery (`G3.1`) or low‑battery handling (`G3.2`). The `FALLBACK` runtime denotes the fallback path. |
| **G3.2 → AT8, AT9, AT10** | **AND** – Returning the resources to a checkpoint (`AT8`), assigning the rest of the task (`AT9`), and sending an alert (`AT10`) must all succeed for the low‑battery handling to complete. |
| **G2.1 → AT1, AT2, AT3, AT4** | **AND** – Navigation, request, wait, and load are sequentially necessary to collect the resources. |
| **G3.1 → AT5, AT6** | **AND** – The robot must travel to the destination and unload; both steps are required. |

All relations are justified directly from the mission description: the sequential flow of phases, the need for parallelism when multiple robots are involved (parallel execution indicated by `#` only for the top‑level goals if required), and the explicit fallback paths triggered by battery thresholds. The model respects the AND/OR decomposition rules and provides a clear operational mapping from high‑level goals to concrete robot actions.
